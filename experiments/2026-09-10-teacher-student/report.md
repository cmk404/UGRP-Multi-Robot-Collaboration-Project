# 좌표 교사에서 RGB 학생으로: 첫 국소 파지 학습

## 요청과 경계

사용자 요청: 좌표 등 특권 정보를 받으면 성공하는 기존 제어를 교사로 사용하고, 그 성공 데이터를 바탕으로 영상 학생의 학습을 진행한다. 교사에서는 좌표/IK/접촉 검증을 허용한다. 학생의 보정 함수에는 자기 RGB, 고정된 공용 상단 RGB와 고정된 학습 모델만 전달하며, 실행기는 자기 발행 명령에 보정량을 더한다. 카메라 설치 위치/FOV, 단일 직육면체 물체와 기존 손가락 접촉 형상을 유지했다.

첫 단계 범위는 **교사 명령으로 초기화한 파지 직전 자세에서, 학습에 쓰지 않은 작은 팔 명령 오차를 RGB로 복구하는 것**이다. 교사의 접근과 닫기/들기는 시연 명령을 재생한다. 독립 출발점에서 접근하거나, 닫기/들기까지 영상으로 학습한 정책, LLM 협업, 새로운 배치 일반화가 아니다.

## 방법과 교사 자료

- 교사는 기존 좌표/IK 성공 경로를 수행하고, 파지 직전 각 로봇의 손목/팔꿈치/어깨에 -50, -25, +25, +50 pulse 탐색을 한 뒤 복구한다. 500..2500 범위에서 실제 적용량을 기록한다. 어깨의 양수 탐색은 +15로 제한되어 반복된다.
- 성공 시연의 자기/상단 영상을 목표로 삼고, 각 탐색 전후 영상 차이와 발행 pulse 변화의 선형 회귀로 영상 Jacobian을 학습한다. 작은 grayscale/Sobel 영상 특징을 사용한 NumPy/OpenCV 회귀이며, 신경망 또는 LLM을 학습한 것이 아니다.
- 학생은 현재 두 영상과 목표 영상의 오차를 최소화하는 pulse 보정량을 계산한다. 한 번에 최대 25 pulse, 16회 고정 예산이다. 목표 좌표·목표 관절 pulse를 학생 보정 모델에 저장하지 않는다. 초기화 및 닫기/들기 재생 명령은 별도 skill 항목에 명시한다.
- 교사 v1: 물리 파지는 성공했지만, 범위 제한으로 같은 적용량이 생길 때 파일 이름이 충돌했다. 중복 sample ID 8개 및 이미지 hash 불일치 12개를 발견해 학습에서 제외했다. 실패 자료도 보존한다.
- 교사 v2: source `70f2502c640c8d91cbee6ce145dd6f0947c66f42`. 요청량과 실제 적용량을 파일 이름에 함께 넣고 덮어쓰기를 금지했다. 106개 sample ID가 모두 유일하고 모든 참조 이미지의 SHA-256이 일치한다. 물체를 0.071571 m 들어 2초 동안 두 로봇 양쪽 손가락 접촉을 유지했고 weld는 꺼져 있었다.
- 로봇별 12개 paired probe로 학습, rank 3, condition number 약 7.0/6.9, 학습 wall time 0.71초. 학습 데이터의 적합도는 실제 성공률로 취급하지 않는다.

## 비교 설계

[protocol.json](protocol.json)에 코호트 실행 전 조건과 판정 기준을 저장했다. 동일 seed 11/물체/로봇 위치/카메라에서 손목 ±37, 팔꿈치 ±37, 어깨 -37/+7 pulse를 양쪽 로봇에 적용한다. 영상 보정과 보정 없는 시연 재생의 각 6회, 총 12회다. 각 쌍의 최초 RGB hash 일치를 확인한다. 손목 +37은 사전 pilot에서 이미 본 반복 진단 조건이며, 나머지 5개가 아직 보지 않은 검증 조건이었다.

두 조건은 16×0.45초의 동일 복구 예산과 동일 닫기/들기/2.2초 유지 절차를 갖는다. 실제 파지 판정은 output-only 물리 표본으로 높이 3cm 이상, 두 로봇 양쪽 접촉, weld 없음이 2초 연속 유지되는지 확인한다. 이동 중 콜백 빈도 때문에 표본 수는 다를 수 있으나, 최종 유지 구간은 동일 10Hz이고 시뮬레이션 시작/종료 시간도 비교한다.

사전 pilot에서는 손목 +37에 영상 보정과 재생 모두 성공했다. 영상 특징 오차는 영상 보정으로 r1 50.5%, r3 91.8% 감소했다. 이것만으로 파지 성공의 학습 효과를 입증하지 않는다.

## 결과

**첫 학습 및 실제 비교는 완료했다. 작은 오차는 양쪽 6/6, 큰 복합 오차는 영상 학생 6/8, 단순 재생 5/8이다.** 작은 오차 5/6 사전 gate는 통과했으나 baseline도 6/6이므로 그 자체로 학습 우위를 뜻하지 않는다. 모델/제어를 수정하지 않고 [stress-protocol.json](stress-protocol.json)의 8개 factorial 조건을 선언해 추가 실행했다.

| 큰 오차 (손목, 팔꿈치, 어깨 pulse) | 영상 학생 | 시연 재생 |
|---|---:|---:|
| [-90, -90, -90] | 성공 | 실패 |
| [-90, -90, 7] | 성공 | 성공 |
| [-90, 90, -90] | 성공 | 성공 |
| [-90, 90, 7] | 성공 | 성공 |
| [90, -90, -90] | 실패 | 실패 |
| [90, -90, 7] | 실패 | 실패 |
| [90, 90, -90] | 성공 | 성공 |
| [90, 90, 7] | 성공 | 성공 |

- 유일하게 결과가 갈린 `[-90,-90,-90]`에서는 학생이 최대 7.82cm 들어 2.2초 유지했고, 재생은 물체를 들지 못했다. 학생의 영상 보정이 해당 조건의 파지 성공에 기여했다는 직접 비교다.
- `[90,-90,-90]`, `[90,-90,7]`에서 학생은 모두 실패했다. 뒤 조건의 재생은 잠깐 들었어도 연속 유지가 1초라 실패다. 실패를 성공으로 제외하거나 판정을 완화하지 않았다.
- 영상 오차가 단조롭게 줄지는 않는다. corner-1의 r3는 15.19→15.86으로 증가했는데도 파지에는 성공했고, corner-5의 r1은 8.09→12.57로 악화했다. 전체 영상 선형 회귀의 오차가 접촉 성공을 충분히 나타내지는 않는다. 1개 추가 성공을 통계적 우위나 넓은 일반화로 해석하지 않는다.
- 두 비교 모두 같은 고정 배치/seed 11, 같은 모델을 사용했다. 14가지 자세는 작은 국소 복구+큰 오차 탐색이며, 새로운 배치/물체/조명/카메라나 독립 접근 검증이 아니다. 닫기/들기 정책 학습도 아직 남아 있다.

코호트 source는 작은 조건 `c1b429a2b1dfa237800e4f765ba6dc706415f0cf`, 큰 조건 `691812147aeafd6202f955941ef6727c5a7fb06f`이며 runtime/model은 두 사이에 바꾸지 않았다(프로토콜 문서만 추가). 각 14쌍의 최초 own/top RGB SHA-256, 초기 명령, 실제 perturb, skill/source SHA, 시뮬레이션 시간 5.382..16.472초가 일치한다.

사전 pilot 2회 + 작은 비교 12회 + 큰 비교 16회 = 총 30회, 960개 로봇 판단을 exact RGB replay로 검사했다. 저장된 모델/skill/이미지 해시, 예측 dict, 발행 명령 이력, 실행할 arm action 모두 일치했다. 좌표나 접촉을 읽어 행동을 재계산하지 않았다. 결과 evaluator도 원본 evaluation-only.jsonl에서 다시 계산해 result.json과 일치했다. 독립 코드 검토에서도 actor 입력 경계나 성공 판정에 심각한 문제는 발견되지 않았다. 이 검사는 로그/제어 입력 재계산이며 실제 로봇 하드웨어 검증은 아니다.

작은 오차 비용: visual 평균 5.83초/실행, 보정 arm action 총 561개, playback 평균 5.72초/실행, 보정 arm action 총 0개. 각 실행은 보정 16회, 총 32 predictions(로봇별 16), 고정 7.2 SIM초의 복구 예산이다. 재생 조건도 비교를 위해 같은 영상 예측을 계산하고 적용만 하지 않았다. API 호출/토큰 비용은 0이다. wall time은 초기화·렌더링·저장 포함 로컬 관측값이고 microbenchmark가 아니다.

큰 오차 비용: visual 평균 5.64초/실행, 보정 arm action 총 758개, playback 평균 5.28초/실행, 보정 arm action 총 0개. 각 실행은 보정 16회, 총 32 predictions(로봇별 16), 고정 7.2 SIM초의 복구 예산이다. 재생 조건도 비교를 위해 같은 영상 예측을 계산하고 적용만 하지 않았다. API 호출/토큰 비용은 0이다. wall time은 초기화·렌더링·저장 포함 로컬 관측값이고 microbenchmark가 아니다.

검증: 최종 로컬 403 tests + 140 subtests 통과(7.25초). GitHub offline에서 교사 데이터 테스트가 import 시 MuJoCo를 요구하는 문제를 발견했다. 시뮬레이션 import를 collect 실행 시점으로 옮겨 dataset/command helper를 최소 테스트 환경에서 쓸 수 있게 했으며, MuJoCo import를 차단한 상태의 직접 import도 통과했다. 시뮬레이션 동작 변경은 없다. 최종 CI 상태는 아래 별도 기록한다.

시각 검토: 교사·사전 pilot의 첫/중간/마지막 프레임, 큰 오차 corner-1 양 조건의 같은 구간을 직접 비교했다. 학생에서 물체가 올라가고 재생에서는 바닥에 남는 장면을 확인했다. 모든 영상 프레임을 전수 수동 검토한 것은 아니다. [대표 비교 프레임](stress-corner-1-video-review.jpg). raw motion.mp4는 각 local run 폴더에 있다. 최종 실패 두 조건의 RGB/영상 대표 프레임도 별도 QA 파일에 포함한다.

다음 학습에서 해결할 구체적 문제는 큰 오차 두 실패 구간의 비선형 영상 변화다. 좌표 교사로 해당 영역의 복구 시연을 추가 수집하고, 단일 목표 주변 선형 모델을 여러 시연/국소 모델 또는 비선형 행동 모형으로 확장한 뒤, 새로운 holdout 배치에서 다시 비교해야 한다. 현재 결과로 접근·파지·들기 전체 문제가 해결됐다고 보고하지 않는다.



## 보관과 재현

각 `*-raw-manifest.json`은 원본 파일 위치/크기/SHA-256을 기록한다. `*-evidence.zip`은 결과와 모델/교사 데이터를 보관한다. 유효한 교사 v2 RGB 전체와 학생 모델은 Git에서 복원할 수 있다. 원본 동영상과 학생 회차별 RGB 대부분은 로컬 outputs에 보관하며 원격 백업이 아니다. 대표 stress corner-1 양 조건의 RGB 전체는 해당 evidence.zip에도 포함해 저장된 모델로 exact replay를 재현할 수 있다. 프로젝트 지침에 따라 Google Drive는 사용하지 않는다.

코드: `scripts/collect_camera_grasp_teacher.py`, `scripts/train_camera_grasp_student.py`, `harness/camera_teacher_student.py`, `scripts/run_camera_grasp_student.py`. 실행 환경은 각 result.json에 Python/platform/MuJoCo 버전으로 기록한다.
