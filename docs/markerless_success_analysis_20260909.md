## 확정된 병목

### 1. 마지막 진입을 위한 정보가 모델에 충분히 전달되지 않는다

`harness/visual_placement.py`는 자체 카메라에서 구역 사각형을 복원하고 자체 PWM 기반의 내려놓기 위치와 블록 크기·50mm 여유를 비교한다. 그러나 `harness/transport_context.py`는 위치 판단을 status/reason/stage 및 identity 확인 여부로 압축하고, 거리·방향·개선량을 버린다. 모델은 멀리 벗어난 경우와 몇 cm 남은 경우를 모두 outside로 받는다.

44번에서 최소 signed margin은 호출18 -0.828m, 22 -0.191m, 23 -0.105m, 25 -0.0675m로 달랐지만 압축된 피드백은 동일했다. 모델은 손목 화면 전체에서 경계가 없어지는 것을 목표로 쓰기도 했다. 실제 판정은 화면 전체 색상이 아니라 내려놓을 블록의 여유 포함 영역이다. 이 불일치가 불필요한 미세 이동을 유발한다는 것은 유력한 원인 가설이며, 정량 개선 효과는 비교 실험이 필요하다.

**해결 후보:** 자체 RGB에서 얻은 최근 구역 경계와 예상 내려놓기 영역을 모델 입력 영상에 표시하거나, 출처·시각·불확실성을 붙인 로봇 기준 진입 방향/경계 부족량/최근 변화량을 간결하게 전달한다. 세계 좌표·정답 경로·seed를 넣지 않는다. LLM이 이동을 선택하고 기존 새 RGB 안전 검사를 유지한다. known-size 추정의 오차보다 정밀한 수치를 확정값처럼 주지 않는다. 같은 outside가 반복되면 현재 화면의 부족한 방향을 다시 보고 heading/duration을 바꾸게 한다.

**검증:** 저장된44/45 근접 영상에서 새 피드백의 방향과 여유 표시가 원본 판정에 일치하는지 확인한 뒤, 정책만 바꾼 동일조건 실제 실행에서 마지막 진입 호출 수·안전 여유·전체 성공을 비교한다. 목표는 44/45에서 최소 3~4호출의 여유를 확보하는 것이다. 이는 제안 목표이지 검증된 개선량이 아니다.

### 2. 버려지는 모델 호출과 실제로 보호되지 않는 종료 예산

44번은 요청3 stale(5,285), 요청8 state_changed(5,441), 요청24 stale(4,276), 합15,002토큰을 사용했지만 해당 동작은 실행되지 않았다. 현재8 SIM초 frame-age 제한은 실제 세계가 추론 중에도 움직이는 점을 반영한 안전 장치다. 이를 단순 해제해서는 안 된다. `terminal_input_reserve=12000`은 모델에게 전달되는 계획용 수치이며, `InferenceInputBudget.can_reserve`는 다음 요청 하나의 예상치만 검사한다. 종료 두 호출을 별도 보호하는 구현은 없다. 보호 장치만 추가하면 더 일찍 멈출 수도 있으므로 navigation/그립 비용 감소와 함께 설계해야 한다.

44번 마지막 저장 자체 RGB/PWM(step223)을 기존 판정기에 그대로 재생하면 inside, 최소 여유 +9.78mm였다. 이 여유는 이미50mm안전영역을 포함한 발자국 기준이다. 당시 실행기는 예산 검사를 먼저 해 종료했으므로 release/finish 요청을 보내지 못했다. 이는 내려놓기 후보 위치 도달을 뜻하며 실제 방출 성공을 증명하지 않는다.

**해결 후보:** 그립 감시가 변경할 상태를 먼저 확정한 후 모델 요청을 보내 상태변경 폐기를 줄인다. 지연 응답은 현재 RGB·상태와의 재검증 및 필요시 간결한 재계획 경로를 설계하되, 오래된 화면의 동작을 무조건 실행하지 않는다. 모델에 실질적으로 가능한 잔여 요청 수를 명확히 전달하고, navigation/회복 비용과 release/finish 예산을 분리해 계획한다. 입력 내용의 반복·불필요한 비교 이미지 비용도 현재 정책 기준으로 계측한다.

**검증:** 추론 지연 및 그립 상태변경을 주입해 오래된 동작 거부가 유지되는지, 중복 요청/사용량 누락이 없는지 확인한다. 실제44번에서 폐기 비용과 완수 호출 수를 비교한다. 보수적인 예산 추정치를 무근거로 낮추거나 공급자 토큰 한도를 초과하지 않는다.

### 3. 구역에 가까워질수록 경계 관측이 부족해진다

45번 마지막 저장 자체RGB/PWM(step247)의 새 판정은 DESTINATION_SQUARE_UNDERCONSTRAINED였다. 모델이 직전에 받았던 outside는 이전 carrying 시점의 기록이다. 목표의 일부가 보인다는 것과 배치 영역이 안전하게 내부라는 증거는 다르다.

**해결 후보:** 경계가 보이는 시점에 진입 방향을 계획하고, 판정이 불확실해지면 작은 관측용 방향 변경으로 실제 모서리를 다시 확보한다. 과거 경계를 사용할 경우 자체 관측 기반 움직임 추정과 불확실성·유효기간을 포함해야 하며, 과거 inside를 현재 inside로 재사용하면 안 된다. 구역 추정 유효성/관측 시각을 모델 피드백에 분명히 전달한다.

**검증:** 저장된45번 마지막 화면을 inside로 오인하지 않고 관측 확보 행동을 선택하는지 확인한다. 실제 실행에서는 새 경계 관측 후 기존 여유 기준과 방출 검사를 통과해야 한다.

## 그립 실패의 구체적 증거와 수정 후보

46번 최초 집기 확인은 강하게 통과했다(원위치 중심 차이1.47px, IoU0.9908). 첫 운반 명령은 fwd0.13/turn0.04/2.5초였으나0.618초 실행 후 중단됐고, 연속 영상의 블록 중심이27.22px 변했다. 이후 원위치 복귀 차이34.93px, IoU0.856으로 재확인도 실패했다. 이는20.5px 좌우 기준 하나의 문제가 아니다. 평가 전용 최종 높이는84.53mm여서 바닥 낙하는 아니지만, 안정된 양쪽 파지인지 집게에 걸쳐 있거나 미끄러지는지는 아직 확정할 수 없다.

45번은 모든 재확인이 통과했으나 곡선 주행 뒤8px 기준을 넘는 영상 변화가 반복됐다. 우선 가감속·회전으로 인한 물리 흔들림과 카메라 검사 자체의 민감도를 분리한다. 기준을 느슨하게 하는 대신, 같은 집기 직후 상태에서 정지 유지/직진/제자리 회전/기존 복합 주행을 각각 독립 비교한다. 자체RGB와PWM로 판정하고 물체-집게 상대운동 및 접촉은 평가용으로만 기록한다. 실제 미끄러짐이면 집기 중심·접촉 여유와 주행 변화율을 개선하고, 상대물체가 안정적인데 관측만 실패하면 정지 기준 영상과 좌우·원위치 복귀 검사 설계를 수정한다. 분리 주행이나 긴 대기가 무조건 좋다고 가정하지 않는다.

## 권장 진행 순서

1. LLM 없이 짧은 집기→주행→그립 재확인 시험으로46번 실패를 분리하고, 물리적 흔들림과 관측 변화의 기여를 확인한다. 관련 상세는 grip-analysis.md를 참고한다.
2. 44/45 마지막 구역 접근 피드백 및 요청 시점/예산 계획을 한 변수씩 비교한다. 동작을 LLM이 선택하는 실험 성격을 유지한다.
3. 개선 코드 전체를 고정하고 기존42~46을 같은30호출/120,000입력토큰/300SIM초에서 다시 평가한다. 한 조건만 재시도해 결과를 합산하지 않는다.
4. 5/5 이후 같은 묶음을 적어도3회 반복하고, 미사용 초기 배치·방향도 추가한다. 각 실행은 집기, 운반 중 파지, 장애물 통과, 바닥 방출, fresh finish 및 영상 검토가 모두 필요하다. 반복 성공도 임의 현실 환경의100%보장을 뜻하지 않는다.

현 단계에서 토큰 한도만 올리는 것은 병목 분리용 실험으로는 가능하지만46번 그립 실패를 해결하지 못한다. 표식 복구, 정답 좌표 주입, 그립 임계값 완화, 임의 물리 접착은 해결로 보지 않는다.
