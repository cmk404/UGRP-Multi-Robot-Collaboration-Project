## 현재 상태 요약

- **마지막 갱신**: 2026-08-20
- **연구 단계**: 범위 고정 및 실행 환경 준비 전후
- **현재 연구 질문**: 중앙 계획자 없이 동등한 에이전트가 자연어로 협상할 때 다중로봇의 역할 분담·협력 이송·예외 복구가 개선되는지 검증한다.
- **현재 실행 목표**: 연구 방향을 임의로 확정하지 않고, 저장소 문서의 순서에 따라 환경·프로토콜·기록을 재현 가능하게 준비한다.
- **연구 사양 승인 상태**: 공식 제출계획(로봇팔 3대)과 Isaac Lab 수정안(휴머노이드 2–3대)이 함께 존재한다. 수정안의 공식 승인 여부는 이 로그에서 확인되지 않았으므로 미확정이다.
- **과거 확인 상태**: 2026-08-14에 아이폰 핫스팟 경로로 `ugrp1`의 SSH와 noVNC 연결을 실제 확인했다. 당시 DHCP 주소는 현재 주소로 간주하지 않는다.
- **현재 작업 상태**: 2026-08-20 라이브 점검에서 Mac은 `postech` Wi‑Fi에 연결되어 있지만 `ugrp1.local`, Pi MAC, USB 직결 IP가 발견되지 않았다. 현재 Pi 연결은 확인되지 않았다.
- **가장 먼저 할 일**: 하나의 선택된 AP에서 Pi 전원·Wi‑Fi 연합·DHCP·SSH를 계층별로 재검증하고, 연결 경로를 운영 런북으로 고정한다.

## 문제·시도·해결 기록

### I-001 — 플래싱 CLI의 실시간 진행률이 대화 화면에 보이지 않음

- **발견일**: 2026-08-14
- **문제**: Raspberry Pi Imager CLI를 백그라운드로 실행했을 때 대화 화면에는 진행률이 직접 표시되지 않았다.
- **실제로 확인한 증거**:
  - Imager 프로세스가 `/dev/rdisk6`를 열고 이미지 파일을 읽고 있었다.
  - 별도 출력 로그에서 `Writing: 100%`까지 확인했다.
  - 이어서 `Verifying` 단계가 시작되었고, 확인 시점에는 35%까지 기록되어 있었다.
- **시도한 방법**: 프로세스 상태, 열린 파일, 디스크 입출력, Imager 출력 로그를 별도로 확인했다.
- **결과**: 쓰기와 검증이 진행 중이라는 사실은 확인할 수 있었지만, 당시 검증 완료는 확인하지 못했다.
- **상태**: 후속 확인 필요
- **다음 행동**: Imager 종료 상태와 SD 카드 재인식 여부를 확인한다. 완료 전에는 카드를 분리하지 않는다.
- **보안 메모**: 네트워크 인증정보와 계정 비밀번호는 기록하지 않았다.

### I-002 — 이전 플래싱 종료 후 SD 카드 재인식 미확인

- **확인일**: 2026-08-14
- **관찰**: 이전 작업의 `rpi-imager` 프로세스가 확인되지 않았고, 당시 `diskutil list`에서 `/dev/disk6`도 보이지 않았다.
- **해석하지 않은 것**: 프로세스 종료와 장치 미인식만으로 이미지 검증 성공·실패, SD 카드 손상, 부팅 가능 여부를 단정하지 않는다.
- **상태**: 새 Bullseye 이미지 재플래싱으로 후속 조치 중
- **다음 행동**: 새 플래싱의 검증 완료와 최종 종료 결과를 확인한다.

### I-003 — Bullseye 이미지 재플래싱 진행

- **확인일**: 2026-08-14
- **관찰**: Raspberry Pi Imager가 `/tmp/raspios-bullseye-arm64.img.xz`를 `/dev/disk6`에 기록 중이었다.
- **실제 진행률**: Imager 로그에서 `Writing: 38%`를 확인했고, SD 카드 쓰기 활동도 약 16 MB/s로 관찰했다.
- **상태**: 쓰기 완료 후 검증 단계로 진행됨
- **다음 행동**: 검증 100%와 종료 결과를 확인한다.

### I-004 — Bullseye 이미지 쓰기 완료 및 검증 진행

- **확인일**: 2026-08-14
- **관찰**: Imager 출력 로그에서 `Writing: 100%` 뒤 `Verifying` 단계 진입을 확인했다.
- **실제 진행률**: 해당 시점의 로그에서 `Verifying: 2%`까지 기록됐다.
- **단계**: 이미지 검증 중. 아직 최종 성공은 확인하지 않았다.
- **상태**: 후속 확인으로 진행 중
- **다음 행동**: 검증 100%와 Imager 종료 코드·최종 로그를 확인한다.

### I-005 — Bullseye 이미지 검증 49% 진행

- **확인일**: 2026-08-14

- **실제 진행률**: 최신 출력 로그에서 `Verifying: 49%`를 확인했다.
- **상태**: 진행 중
- **다음 행동**: 검증 100%와 Imager 종료 코드·최종 로그를 확인한다.

### I-006 — Raspberry Pi Imager GUI 기반 맞춤설정 주입 전환

- **확인일**: 2026-08-14
- **관찰**: CLI raw 이미지 플래싱 후 수동 파일 복사 시 `userconf` 미생성(계정 누락) 및 Wi-Fi 포맷 오류 위험이 존재함을 확인했다.
- **조치**: Raspberry Pi Imager GUI를 실행하고 OS 맞춤설정(호스트네임 `ugrp1`, 사용자 계정 `ugrp1`, 무선 LAN 국가 `KR`, SSH 비밀번호 인증 활성화)을 적용하여 플래싱하도록 전환했다. (인증정보 비밀값은 저장소에 미기록)
- **상태**: Imager GUI 맞춤설정 입력 및 플래싱 대기
- **다음 행동**: 플래싱 완료 후 SD 카드를 Pi에 장착해 부팅하고 SSH 접속(`ugrp1.local` 또는 IP)을 검증한다.

### I-007 — Mac을 고정형 무선 공유기(AP)로 구성하는 방안 채택

- **확인일**: 2026-08-14
- **관찰**: 아이폰 핫스팟의 불안정성(AP 격리, 절전 모드 전환, mDNS 차단)으로 인해 라즈베리파이 무선 접속 및 다중 로봇 통신 신뢰도가 낮아짐.
- **해결책**: Mac의 **인터넷 공유 (Internet Sharing)** 기능을 활성화하여 Mac 자체를 독립 Wi-Fi AP 및 DHCP 게이트웨이로 전환.
- **상태**: Mac AP 설정 및 라즈베리파이 Wi-Fi 연동 준비 중
- **다음 행동**: Mac의 Wi-Fi AP 이름과 암호를 정하고, 라즈베리파이 맞춤설정에 주입 후 부팅 검증.

### I-008 — 연결 경로 혼선과 관찰 불가능성

- **발견일**: 2026-08-20
- **문제**: 아이폰 핫스팟, Mac 인터넷 공유, 교내 Wi‑Fi가 번갈아 사용되었고, 기존 `find_pi.sh`는 mDNS·ARP만 확인하면서 무한 대기했다. 어느 망에 있는지와 실패 계층이 드러나지 않았다.
- **실제로 확인한 증거**:
  - Mac의 현재 Wi‑Fi는 `postech`이고 IPv4는 `172.29.4.126`이다.
  - `ugrp1.local`이 해석되지 않았고 Pi MAC 후보가 ARP에 없었다.
  - Raspberry Pi USB 직결 서비스에 IP가 없고 SD 카드도 현재 마운트되지 않았다.
- **조치**: 비밀정보를 출력하지 않는 bounded 진단기 `scripts/masterpi_connection_status.sh`를 추가하고, 기존 `scripts/find_pi.sh`를 호환 진입점으로 전환했다. 네트워크 선택·상태 모델·SSH/GUI 검증 순서를 `docs/masterpi_network_runbook.md`에 기록했다.
- **결과**: 현재 라이브 점검은 `MAC_WIFI_HAS_IPV4`와 `PI_NOT_VISIBLE`을 분리해 반환하며, 이름 조회나 포트 확인이 무기한 대기하지 않는다.
- **아직 확인하지 못한 사항**: 현재 Pi가 부팅되었는지, 어떤 SSID를 기억하는지, 실제 Wi‑Fi 연합 단계에서 실패하는지는 확인하지 못했다.
- **다음 행동**: 하나의 AP만 켜고 Pi 전원을 인가한 뒤, 런북의 `Mac Wi‑Fi → Pi 발견 → SSH → GUI/API` 순서로 재검증한다.

### I-009 — SD 카드가 Mac에 노출되지 않음

- **발견일**: 2026-08-20
- **문제**: 사용자는 SD 카드가 연결되었다고 알렸지만, 현재 Mac에서 부팅 파티션을 읽을 수 없다.
- **실제로 확인한 증거**:
  - `diskutil list`에는 내부 `disk0`와 APFS `disk3`만 있고 외장 디스크가 없다.
  - `/Volumes`에는 `Macintosh HD`와 `Recovery`만 있으며 `bootfs`가 없다.
  - USB 장치 목록에도 외장 카드 리더·SD 저장장치가 나타나지 않는다.
- **조치**: 카드를 포맷하거나 마운트 해제하지 않고 읽기 전용 인식 상태만 확인했다.
- **결과**: 현재는 SD 카드 파일을 백업하거나 Wi‑Fi 설정을 수정할 수 없다.
- **아직 확인하지 못한 사항**: 카드 리더 연결, 카드 삽입 상태, 카드 자체의 인식·파일시스템 상태.
- **다음 행동**: SD 카드 또는 카드 리더를 Mac에 다시 연결한 뒤 외장 디스크가 나타나는지 확인한다. 인식되면 기존 파일을 먼저 백업하고, 선택한 네트워크 설정만 수정한다.
