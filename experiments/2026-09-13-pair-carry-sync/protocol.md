# 공동 운반 동기화 M1: 사전 계획

요청: #39의 작업 중 의미 있게 검증할 수 있는 범위까지 자율 진행한다. 첫 범위는 이미 함께 잡은 짐의 20cm 직선 운반에서 준비·출발·정지·정렬·재개를 연결하는 것이다.

## 가설과 기존 증거

- 기존 #34의 0.6/1.0초 한쪽 출발 보류는 고정 조건에서 실패했다. 같은 기록의 top RGB에서 짐의 아래/위 끝 X 차이가 증가한 뒤 모델 지원 범위를 벗어났다.
- 명령 접수와 영상에서 확인한 진행을 구별하고, 영상상 기울어짐이 작을 때 멈춘 뒤 뒤처진 쪽을 제한적으로 움직이면 이탈을 줄일 수 있다는 가설이다.
- 이 비교는 새 동기화와 국소 보정의 묶음 효과를 측정한다. READY 메시지 자체의 순수 인과 효과나 독립 LLM 협업 효과로 해석하지 않는다. 코드는 로컬 실행 조정자이며 네트워크 분산 합의 프로토콜이 아니다.

## 경계

PR #34의 고정 파지 시작·로봇·카메라/FOV·물리·weld OFF·파지 모델·운반 모델·시연 내려놓기 순서를 유지한다. 학생 입력은 자기 RGB·공용 RGB·초기 운반 RGB·자기 발행 명령 이력이다. 제어기에 평가 정답, 실행기의 실제 적용 명령, 결함 주입 시각을 넣지 않는다. coordinator는 영상 판단에서 만든 준비 보고와 로컬 단조 시계를 받는다.

교사 재학습, 다양한 파지 자세, 지도·공동 회전, 새 내려놓기 인식, 외부 LLM, 실물 시험은 이 M1 비교에 포함하지 않는다. 일반 자원 소유권은 계약/단위 시험 범위이며 물리 운반·메시지 버스 통합과 구분한다.

## 후보와 기준선

- baseline: 기존 `choose_carry_actions`의 RGB 운반과 두 차례 정지 후 확인. 원래 0.20초 운반/0.25초 정지 명령과 모델을 유지한다.
- sync: 최신 양쪽 준비, 관측 기준 0.6초 보고 TTL, 정지 시 epoch 갱신 후 재합의. 초기 짐 기울기 대비 3px를 넘으면 0.4초 정지, 12px 이내에 한해 뒤처진 로봇에 최대 0.04 전진을 발행한다. 1px 이내로 회복하면 0.4초 정지 후 두 보고로 재개한다. 기울기는 실제 공용 JPEG의 짐 끝점으로 계산한다. 이 값은 고정 영상의 픽셀 차이이고 물리 좌표가 아니다.
- 유효 RGB를 잃으면 양쪽 정지·최대 5회 재관측 뒤 중단한다. 최대 8회 정렬 시작, 최대 150판단으로 한정한다. 임계값만 완화해 기존 실패를 성공으로 바꾸지 않는다.
- 명령 접수 지연이 아닌 **실제 한쪽 구동 보류**는 최초 양의 운반 명령 시각을 기준으로 주입한다. 정지·메시지 대기 때문에 결함이 출발 전에 소진되지 않게 한다. 보고 단절은 운반 관측 시작 기준으로 실제 전달을 생략한다. 모든 주입은 setup/executor/relay에만 있다.

## 개발과 최종 비교

개발에는 기존 고정 시작, r1/r3의 1초 출발 보류를 사용한다. 원인을 좁힐 새 증거가 없으면 같은 후보 반복 실행을 멈춘다. 최대 세 차례 후보 수정 뒤에도 핵심 실패가 남으면 통과한 계층과 미해결 물리 문제를 구분해 기록한다.

후보를 고정하고 다음 전체 비교를 새로 실행한다. 모든 시도·실패와 source SHA를 기록한다.

1. 고정 시작 정상 10회 × baseline/sync. 결정적인 시뮬레이션의 반복 재현성으로만 해석한다. 기존 완료율 9/10 이상 유지가 1차 기준이다.
2. r1/r3 × 0.2/0.4/0.6/1.0초 출발 보류 × 두 조건. 기존에 본 조건의 회귀 비교이며 새 일반화 증거가 아니다.
3. 개발에 사용하지 않는 r1/r3 × 이동 시작 0.8초 후 0.35/0.75초 구동 보류 × 두 조건. 제한된 새 시점·기간 전이 시험이다.
4. r1/r3 × 처음 1초 또는 이동 관측 시작 1.2초부터 1초 보고 단절 × 두 조건. 주로 준비/보고 만료·재개 경계 검증이며 통신 성공률 우위의 본실험이 아니다.

M1 완료는 1을 유지하고 2의 모든 sync 조건에서 낙하 없이 운반·시연 내려놓기 완료, 영상상 정지/정렬/재개와 입력 감사가 확인되는 경우다. 3/4의 미통과는 숨기지 않고 제한 또는 다음 작업으로 기록한다. 중단한 실행을 운반 성공에 넣지 않는다.

## 평가와 저장

기존 `evaluate_transport_samples`를 그대로 사용한다: 2초 이상 파지 유지, 운반 중 3cm 들림과 양쪽 양측 접촉, 20±3cm 도착·횡방향 3cm 이내, 내려놓은 뒤 접촉 분리와 1초 위치 안정성. 10Hz 표본 범위의 검증이며 모든 물리 단계의 접촉 증명은 아니다.

완료율, 실패 이유, SIM/실제 시간, 판단/명령 수, HOLD/재개 횟수·이유, 시각 보고 나이, 기울기, 비용을 기록한다. 외부 모델 호출은 없고 로컬 계산 비용은 측정하지 않는다. 단계별 준비 대기/보고 대기/실행 시간은 관측 가능한 범위로만 분석한다.

각 실행의 영상·RGB·명령·메시지·평가 로그를 로컬 outputs에 보존한다. 저장한 RGB에서 판단/행동/동기화 사건을 재계산하고 파지 감사·독립 평가를 확인한다. Git에는 최종 코드·설정·모든 결과·대표 영상/실제 입력·원본 위치/해시·검토 범위를 남긴다. 전체 원본을 원격 보관하지 않았으면 명시한다. PR을 만들되 main 병합은 별도 사용자 확인을 기다린다.
