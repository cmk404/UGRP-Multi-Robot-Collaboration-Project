# 주행 중 RGB 재관측 후보

기존 단독 상자 접근은 짧은 주행·정지·영상 처리·카메라 팔 보정을 반복한다. 완성 원본 세 실행에서 접근 구간의 발행 주행 시간 비율은17~22%였고, 근접 구간은13~17%였다. 이 비율은 명령 유효 시간이며 실제 변위 측정이 아니다.

`bash scripts/open_simulation.command dispatch --realtime-control --rolling-visual-servo`는 기존 dispatch 옵션과 함께 쓰는 명시적 실험 후보이다. 자기 RGB에서 직접 검출된 상자, 같은 시점 TOP, 새 프레임, 기존 계획/자원 권한이 지원하는 접근 명령만 짧게 발행하고 다음 영상을 주행 중 요청한다. 원 명령 horizon을 연장하지 않으며 개별0.25초·원 관측+0.6초를 지킨다. 명령 만료·관측 불확실·권한/계획 변경 시 정지한다. 물체 가까이에서는 멈추고0.2초 뒤 새 관측으로 기존 정밀 접근에 넘긴다. 팔 움직임·파지·운반·방출·카메라·물리를 바꾸지 않는다.

발행 명령에는 입력 own/TOP 해시, frame/time, 만료와 원 horizon을 기록한다. 실제 hold 시각으로 유효 명령 구간을 잘라 촬영 당시 명령이 활성 상태였는지 사후 감사한다. 명령 적분은 측정 이동거리나 보장된 최대 이동거리가 아니며 근접 재관측을 보수적으로 요청하는 데만 쓴다.

자동 검사와 물리 성공은 별개이다. [사전 비교 계획](rolling-protocol.json)에 따라 원래 배치 진단2회와 다른3개 배치의 RGB/rolling6회 전체 결과를 저장한다. 기준은v28 소스931d910이며 새v29 source/bundle은 실행 전 별도 고정한다. 현재 이 문서는 실행 전 구현 설명이고 완주·속도 개선을 주장하지 않는다.
