# 2026-09-25 계산 후 재생(post-run replay) 확인

PR #140(bundle v42, 소스 `4014935`)의 표준 `dispatch` 계산 후 재생 기능이 제어를 바꾸지 않는지, 기록이 실제로 재생되는지 확인했다.

## 실행

같은 커밋과 저장 계획(`experiments/2026-09-22-parallel-transport/independent-plan.json`, open, seed 11)으로 동기 headless 실행을 두 번 했다. 재생 기록만 켜고 끈 차이다. 원본은 기본 체크아웃의 `outputs/post-run-replay-20260924/`에 로컬로만 있다. 파일 해시는 `results.json`에 있다.

| 실행 | 재생 기록 | 물리 성공 | 프로토콜 완료 | 제어 종료 SIM초 | 명령 수 | wall초(참고) |
|---|---|---|---|---:|---:|---:|
| A-record | 켬 | 성공 | 완료 | 132.26 | 861 | 235.6 |
| B-no-record | 끔 | 성공 | 완료 | 132.26 | 861 | 243.8 |

- 발행 명령, box 결정, 평가 파일은 바이트 단위로 같다. pair 결정 파일은 wall 시계 필드(`pair_bind_wall_s`)만 다르다.
- 재생 기록은 3,949프레임(SIM 30Hz), 6.3MB다.
- Mac의 `mjpython`으로 MuJoCo 창을 열어 16배속으로 재생했고, 10초 안에 마지막 프레임(3948)까지 갔다. 처음·중간·끝 프레임을 별도로 렌더링해 로봇·빔·상자 위치도 눈으로 확인했다.

## 범위

- 이 저장 계획과 seed 하나에서 기록이 제어에 영향을 주지 않음을 확인했다. 새로운 임무 성공이나 속도 개선을 주장하지 않는다.
- 제어 종료 132.26초가 2026-09-24 기준(126.26초)과 다른 이유는 그 사이 main이 바뀌었기 때문이다(`2854fa4`→`4014935`). 재생 기록 때문이 아니다(A/B 동일).
- 재생 창에는 동료 대화 표시가 없다. 대화는 `team/conversation.jsonl`과 `--live-view`에 남는다.
- 메뉴 기본 경로(창 사용 → 계산 후 자동 재생)는 단위 테스트로 연결만 확인했다. 사용자가 메뉴에서 직접 여는 경로의 수동 확인은 아직 하지 않았다.
