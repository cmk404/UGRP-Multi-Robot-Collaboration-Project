# 공동 파지 부분 완료 수정과 E2E 재검증

**GRASP 부분 완료의 명령 차단을 수정했고, 과거 잘못된 영상 보고는 새 검사에서 보류됐다.
실제 공동 운반 E2E 성공은 아직 없다.** 새 실행들은 파지 준비 자세에 도달하지 못했다.

실행 소스: `e706f155b011e9dc9c6c95d318e9a3ab9b2000bc`.
[사전 계획](protocol.md), [전체 결과·환경·원본 해시](results.json),
[PR #57](https://github.com/kcm0127-dotcom/ugrp/pull/57).
기본 main은 `60622bb27ed2280cf8adaf41446d6fa25eaf9063`이며 이번 변경을 병합하지 않았다.

## 무엇을 고쳤는가

이전 실행은 GRASP에서 r1 DONE / r3 READY이면 동기화 코어가 GO를 줘도
실행기의 `all READY` 조건이 남은 파지를 막았다. 조건만 지우면 완료한 로봇에
다시 명령을 보내는 문제도 있어, 코어가 현재 명령 대상 참여자를 명시하도록 했다.
GRASP에서만 완료한 로봇은 설정을 유지하고 아직 READY인 상대가 계속할 수 있다.
양쪽 최신 보고·허가·만료·epoch 검사는 유지한다. 다른 공동 단계의 편측 명령은
실행 어댑터에서 허용하지 않는다. 완료한 로봇의 마지막 명령 ID도 덮어쓰지 않는다.

영상 오판에는 PREPARE READY / GRASP DONE을 별도 모델 요청으로 다시 검토하는
실험용 장치를 넣었다. 행동 모델의 답을 보여주지 않고 자기 RGB·공용 TOP의 현재/이전
영상만 제공한다. TOP의 중앙 절반을 2배 확대해 함께 보여주며 원본도 유지한다.
두 손가락과 그 사이 물체, 열린/닫힌 상태·자기 식별·정지 근거가 부족하면
UNCERTAIN/wait로 보류한다. GRASP에서 확인 실패 시 모두 정지하고 새 준비를 요청한다.
행동 모델에는 자기 영상 검토 이력만 전달한다. 원래 답과 적용된 답을 둘 다 보존한다.

같은 Gemini 모델의 별도 추론이므로 오류가 독립적이라고 가정하지 않는다.
영상 해석의 동의는 실제 접촉·하중 유지 판정을 대신하지 않는다.
카메라 위치/FOV·외관·weld OFF·출력 전용 평가 경계는 유지했다.

## 확인 결과

- 자동 회귀 **713개 + 하위 검사 154개 통과**. 수정 구간만의 검사 118개 포함.
  두 로봇 각각 선완료, 나머지 명령 발행 후 단계 진행, 완료 포트 유지,
  만료·철회·과거 허가·완료 포트 재발행·다른 공동 단계 차단을 확인했다.
  이 계약 시험의 시각 판정은 합성 입력이며 실제 파지 성공이 아니다.
- 보관 영상 분류 **6/6 예상 일치**: 근거 없는 자세/파지 음성 장면 4개 거부,
  파지가 가능했던 준비 자세 2개 인정. 실제 과거 READY 2개와 DONE 1개를 새 gate에
  다시 넣어 모두 UNCERTAIN/wait로 바뀌는 것도 확인했다.
  r3의 GRASP 음성 장면은 분류 대조용이며 과거 r3 DONE 보고가 있었다는 뜻은 아니다.
- 양성 장면은 교사 초기화 뒤 실제 파지가 성공한 실행의 **닫기 전 영상**이다.
  학생 독립 실행 성공이나 닫힌 파지 양성 판별 검증으로 해석하지 않는다.
- GitHub의 실행 소스 CI는 offline-regressions, ubuntu-simulation,
  individual-proxy-bootstrap 모두 통과했다(실제 모델 E2E 성공과 별도).

## 실제 E2E

동일 소스로 두 로봇·한 장면을 실행했다. 모델은 Gemini 3.8 Flash,
행동 48턴·협상 6턴 상한, 입력 600,000토큰·900초 soft cap이다.
첫 none이 프록시 오류로 끝나 실제 영상 요청 1회로 응답 복구를 확인한 후
동일 설정으로 한 번 재실행했다. 실패와 재실행을 모두 남겼다.

| 조건 | 완료한 행동 턴 | 요청 | 명령 r1/r3 | 경과 시간 | 보고 입력 토큰 | 종료 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| natural | 40 | 86 | 54 / 49 | 311.50초 | 613,404 | 입력 예산 |
| none 최초 | 8 | 33 | 17 / 17 | 332.38초 | 141,825 | timeout/HTTP 500 재시도 소진 |
| none 재실행 | 39 | 85 | 57 / 56 | 266.69초 | 602,413 | 형식 오류 재시도 전 예산 소진 |

세 실행 모두 최종 **PREPARE**, READY/DONE 보고 0회, 손가락 접촉 0,
실제 파지·들기·도착·E2E 성공 없음. 명령 수에는 wait도 포함한다.
natural은 팔을 조정하다 자기 영상에 특징 없는 어두운 면만 보이며 조정을 반복했다.
none 재실행도 접근/회전과 팔 조정 끝에 집게가 물체를 둘러싼 자세를 만들지 못했다.

라이브 READY/DONE이 없었으므로 **실행 중 witness 호출은 0회**다.
따라서 이 코호트가 witness 통과 후 GRASP 진입, GRASP 실패 후 재준비,
DONE/READY 혼합 상태의 실제 파지 성공까지 검증했다고 주장하지 않는다.
부분 완료 수정은 계약/포트 회귀시험, 오판 차단은 보관 영상과 실제 옛 답 재생으로 검증했다.

E2E **204개 실제 요청 / 804개 이미지 참조 / 148개 로컬 RGB 판단** 재계산 감사 통과.
입력·전송 본문·자기 이력·재시도·평가 분리 및 카메라/형상 불변·weld OFF를 확인했다.
none 최초의 실패 요청 11개는 usage가 없어 비용을 알 수 없다. 공급자가 청구액을 주지 않아
금액을 추정하지 않았다. 진단 영상 요청 7개는 E2E 요청 수와 별도로 기록했다.
SIM은 모델 추론 중 멈춘다. 이 결과로 통신 효과나 일반화된 성공률을 결론내리지 않는다.

## 남은 연결 작업

현재 병목은 원시 바퀴·관절 값을 직접 제안하는 임시 actor의 **영상 기반 접근·파지 자세 제어**다.
창민의 동기화 계층에서 준비를 강제로 참으로 만들거나 정답 좌표로 보정해 해결하지 않는다.
로봇별 실행 담당의 제어기를 아래 경계에 연결해 재검증하는 것이 다음 작업이다.

1. 자기 RGB·TOP RGB·자기 발행 명령으로 관측 가능한 자세를 유지하며 접근/집게 정렬을 한다.
   자기 시야가 가려지면 그 상태를 검출하고 새 영상에 근거한 복구를 보고한다.
2. `TaskStageExecution.capture()`의 request에 실제 영상 근거의 READY/UNCERTAIN/DONE을 반환한다.
   DONE은 자기 마지막 명령 뒤 새 영상이어야 하며 발행만으로 완료를 보고하지 않는다.
3. 이 생산자로 PREPARE → GRASP → LIFT를 먼저 통과시킨 뒤 CARRY/LOWER/RELEASE까지 같은
   평가 기준으로 확장한다. 현재 준비 단계 실패를 숨긴 채 동기화·통신 효과를 측정하지 않는다.

사용자 역할 범위를 로봇별 모든 인식·파지 알고리즘 구현으로 확장하지 않는
[작업 목록 #39](https://github.com/kcm0127-dotcom/ugrp/issues/39)의 경계를 유지한다.
