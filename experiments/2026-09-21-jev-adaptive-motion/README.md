# RGB 피드백 동작과 Jev 하네스 비교 — 진행 중

사용자 요청: 호출·상태·동작·불확실성·완료 처리의 문제를 수정하고 더 어려운 새 조건에서 Jev/Gemini/규칙을 비교한다. 기존 원본·기준 실행기는 유지한다. 이 파일의 계획은 성공 결과가 아니다.

## 구현/검증 순서

1. RGB 바퀴 기하의 방향 제한과 순간 각도 흔들림을 개선한다. 같은 영상 관측기로 모델별 비교, 기존 관측기는 기준으로 보존.
2. 현재 영상의 목표 거리/방위, 최근 영상 변화, 추정 품질을 사용한다. 진전 없는 명령 반복을 따로 센다.
3. 짧은 coarse/fine 동작과 RGB 중단 조건, 상태 변화/유효기간 재호출, 정지와 완료 구분, 불확실성 재관측을 구현한다.
4. 개발 조건에서 로컬 제어·제공자 스키마·입력 경계를 검증하고 실행 소스를 커밋한다.
5. 새 평가 자세/표적 위치/장애물/가림 조건을 고정하여 전체 비교와 구성요소 제거 비교를 수행한다. 실패도 분모에 포함한다.
6. 전체 결과·행동/요청·이미지 해시·영상·비용 확인 범위를 보존하고 PR #80에 반영한다. main 병합은 별도 승인 대상.

## 공통 제약

자기 RGB·공용 TOP RGB·자기 발행 명령 이력, 사전 정적 지도/카메라 보정만 제어에 허용한다. 미래 환경 이벤트·실시간 정답·물리 접촉·측정 관절은 제어/완료에 넣지 않는다. 카메라/FOV/로봇 외관을 유지하고 weld OFF. 출력 평가는 제어와 분리한다.

새 동작의 관측 주기와 전체 SIM 시간 상한은 공통이다. 동작 길이가 달라지므로 API/동작 횟수만 같은 것으로 공정성을 주장하지 않는다. 성공·무접촉·완료 확인·SIM 시간·벽시계·호출·토큰·개입 비율을 함께 기록한다. 실제 비용은 확인 전 미상이다.

여러 구성요소의 결합 성능과 단일 구성요소 효과를 구분한다. 코드가 선택한 경로·복구를 Jev 단독 지능으로 보고하지 않는다. API 재시도는 하지 않으며 코드 수정 후에는 최종 후보 전체를 다시 평가한다. raw 출력은 로컬 보관, Git에는 출처·설정·압축 결과와 감사 기록을 저장한다.
