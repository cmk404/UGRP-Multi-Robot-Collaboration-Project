# 빔 미세 정렬 이득 스케줄 — 2026-09-24

사용자 요청: 현재 시뮬레이션이 느린 이유를 물리 연산과 로봇 알고리즘 두 측면으로 분석하고 해결책을 찾는다.

## 원인 분석 (기존 기록, 새 물리 실행 없음)

최신 main(`f67d4ef`)의 realtime 실행은 물리 시계가 약 1.0배속이므로 걸린 시간 ≈ 작업에 필요한 SIM 시간이다. `2026-09-24-faster-dispatch/baseline-time-breakdown.json`의 v19 두 완주(196.1/200.9초)를 다시 보면 임계 경로는 빔 접근·미세 정렬(파지 시작 87초) → 상자 파지(빔 파지 시작 뒤 허가) → 상자 운반 76초 → 하역이다. 상자 접근은 빔 파지를 8.7초 기다리는 동안 가려져 있다. v26에서 상자 운반을 22초 줄였는데 전체가 5%만 준 이유다.

빔 미세 정렬 51–54 SIM초 중 전진 단계가 22–26초(약 90–98회 판단), 측면 단계가 10–14초다. 저장된 pose 모델은 영상 추정 오차에 비례 명령(전진 이득 .2, 측면 .35, 최소 .01)을 낸다. 연속 이동 판단 사이의 영상 추정 오차 변화로 보면, 명령 1당 0.2초 구간에서 전진 오차가 약 .14–.18 줄어든다. 그래서 한 판단에 오차의 약 3%만 보정되고 전진 17cm에 약 25초가 걸렸다. 오차 5cm 이하에서는 최소 명령 .01로 12초 이상 이동했다. 기존 명령 상한(전진 .15)은 쓰이지 않았다.

## 변경 (`b44b3cc`, 번들 `rgb-standard-dispatch-v30`)

`--fine-gain-schedule`(기본 OFF)은 pose 영상 모델의 미세 yaw/측면/전진 단계에서 오차가 기존 허용오차의 3배를 넘을 때만 모델 명령을 올린다. 목표는 같은 영상 추정 오차의 35%를 한 명령 구간에 줄이는 것이다. 모델 명령을 낮추거나 뒤집지 않는다. 기록된 상위 사분위 응답에서도 바깥 허용오차를 넘지 않도록 제한하고 기존 명령 상한을 유지한다. 준비 판정·허용오차·정지 확인 2회·최종 정렬 재확인·dock·lease·예산·카메라·물리는 같다. 판단마다 `model_command`와 `gain_schedule`을 기록한다. 응답 상수는 영상 추정 오차에서 얻은 제어기 보정값이며 referee·시뮬레이터 상태를 쓰지 않았다.

번들 번호: main은 v27, draft PR #129·#131이 v28·v29를 쓰고 있어 충돌을 피해 v30(부모 v27)과 workflow 1.28.0으로 등록했다. 병합 순서에 따라 번호 정리가 필요하다.

## 예상과 위험 (추정, 미검증)

- 단순 선형 응답 가정에서 전진 단계는 약 20회 판단(약 5초), 미세 정렬 전체는 54초에서 약 25–30초로 줄 수 있다. 측면의 목표 근처는 .01 데드밴드 때문에 여전히 느리다.
- 한 판단 지연을 포함한 이산 비례 제어에서 보정 비율 .35는 안정 범위(극점 크기 약 .59, 상위 사분위 응답에서 약 .75)지만 영상 흔들림으로 약한 진동이 생길 수 있다.
- 빔 파지가 빨라지면 상자 접근(현재 78.6 SIM초에 준비)이 새 병목이 될 수 있다. 상자 카메라 기울기 8 pulse 제한은 draft #129의 `fast_near_field_servo`, 정지-재관측은 #131이 다룬다.

## 물리 검증 계획

`protocol.json`에 사전 고정했다: 같은 소스·번들에서 플래그만 다른 A/B를 ABBA 순서로 최대 4회 실행한다. 조건은 open/seed11 저장 계획, local_contact_fine, weld OFF, native realtime 1×, 효율 촬영, 자동 경로 겹침, overlap-start grasp이다. 다른 시뮬레이션·학습과 동시에 실행하지 않는다. 결과·실패·원본 해시와 TensorBoard 스냅샷은 실행 후 이 문서에 추가한다. **현재 물리 실행 결과는 없다.**
