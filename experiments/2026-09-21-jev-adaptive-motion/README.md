# Jev/Gemini RGB short-skill comparison

## 사전 고정 설계

목적은 기존 70회 고정 모터 선택 실험에서 섞여 있던 관측 오류, 행동 해상도, 반복 요청, 질문 구성, confidence 사용, 추론 중 시간 정지를 분리해 비교하는 것이다. 범위는 로봇 한 대의 RGB 접근·우회·일시 가림 복구이며, 파지·운반·다중 로봇 협력 성공을 뜻하지 않는다.

- 입력: 자기/공용 TOP RGB, 자기 발행 명령, 정적 지도와 고정 카메라 보정. RGB 좌표 추정과 경로 후보 생성은 공통 코드가 수행한다. 모델에는 명시적 allowlist의 의미 상태와 후보 효과를 제공한다.
- 모델: Jev 1.13.0, Gemini 3.8 Flash. 같은 상태·질문·후보를 제공하되 Jev는 native Choice API, Gemini는 JSON 응답을 사용한다. Gemini의 confidence를 임의 생성하지 않는다.
- 공통 실행: 모델은 짧은 스킬을 선택하고 RGB 로컬 피드백이 선택한 스킬만 실행한다. 지도/RGB로 후보를 제한하며, 가림·충돌 경로·목표 안정화에 대한 공통 정지는 별도 기록한다. rule baseline도 같은 관측·후보·실행기를 사용한다.
- 목표: 제어는 RGB 거리 0.27–0.28 m, 각도 ±3°, 안정 관측 3회. 별도 물리 평가는 기존 거리 0.26–0.30 m, 각도 ±6°, 0.35 SIM초 유지, 접촉 0, weld 0, 카메라 불변을 요구한다. 평가 좌표/접촉/환경 이벤트 시간표는 제어에 전달하지 않는다.
- 시간: 0.25 SIM초 관측, 최대 6 tick 스킬 유지, 의미 변화/후보 변화/정체/종료 시 재질의. Jev action confidence <0.45는 유지 길이만 2 tick으로 줄인다. 이 문턱은 개발용 고정값이며 확률 보정이나 안전 보증이 아니다.
- 한도: trial당 90 SIM초, 1,200 벽시계초, 400 모델 요청, 1,000,000 입력 토큰. 모든 조건 동일한 물리 시간과 충분한 요청 한도를 사용하고 한도 종료도 실패로 보존한다.

## 코호트

`run_jev_skill_motion.py`의 기본 DEVELOPMENT 6개와 진단에서 승격한 2개만 수정·진단에 사용한다. HOLDOUT 12개는 본 시험 전에 고정하며, 본 결과를 본 뒤 후보를 수정해 같은 조건의 결과를 최종 독립 시험이라고 부르지 않는다. `run_jev_skill_cohort.py`는 seed 210922로 열거한 trial을 섞어 4 worker에 배정한다.

| 구분 | 조건 | 횟수 |
|---|---|---:|
| 새 조건 | open, yaw, known barrier, unknown barrier, physical target cover, temporary barrier 각각 2배치 × 3 API 반복 × rule/Jev/Gemini | 108 |
| 회귀 | 앞선 비교의 시작 자세 12개 × rule/Jev/Gemini | 36 |
| 고정 모터 행동 | open03/04, yaw03/04 × 2 반복 × Jev/Gemini | 16 |

연속 시간 조건은 API 대기 중 physics/RGB를 계속 갱신하되 만료된 스킬을 제동한다. 4 SIM초보다 오래됐거나 의미 상태/후보가 바뀐 응답은 버린다. 계속 움직이는 비동기 제어를 검증했다는 뜻은 아니다. 공유 Mac의 동시 실행 때문에 벽시계는 독립 장비 지연 측정이 아니며 API 자체 지연도 함께 보고한다.

고정 모터 행동과 스킬 행동은 동일한 매 관측 질의 조건(open03/04, yaw03/04)에서 직접 비교한다. 호출 빈도의 효과는 full과 always의 같은 배치·반복을 맞춰 비교한다. 초기 216회 안에서 두 효과가 섞이는 것을 방지하려고 본 시험 전 always 12회를 추가했다.

- raw는 `/Users/changmin/projects/ugrp/outputs/`의 로컬 자료이며 원격 백업이 아니다. 키를 결과·명령 인수·환경 파일·Git에 기록하지 않는다.

## 첫 평가의 진단 전환과 독립 평가 재고정

`7dce220`의 첫 평가(`jev-skills-holdout-v1`)는 108개 중 32개 완료(30성공, 2실패) 후 공통 하네스 결함을 찾아 중지했다. 완료/중단 원본과 계획은 덮어쓰지 않는다. `diagnostic-interruption.json`이 중지 시점과 모든 완료 결과를 열거한다. 이 결과를 최종 독립 평가 성공률에 섞지 않는다.

- temporary02/Gemini/r1: 세 바퀴의 최종 RMS는 기존 허용값 3.5px 이내(2.420px)인데, 더 앞선 대응 후보 게이트에서 거절되어 24회 재관측 후 종료됐다. 정답 좌표 없이 저장 RGB만으로 재현했다.
- known02/Gemini/r2: 최종 RGB 거리 0.2788m, 방위 -3.35°에서 90 SIM초에 도달했다. 기존 미세 전진은 방향을 함께 보정하지 않아 경계에서 정렬/접근을 반복했다. 목표 기준을 넓히지 않고 미세 이동에 RGB 방향 피드백을 추가한다.

수정 전에 seed 210923으로 새 12조건을 뽑아 [replacement-holdout-predeclared.json](replacement-holdout-predeclared.json)에 고정했다. 이전 01/02 조건은 진단 자료이며 본 평가/구성요소 비교의 대응 조건은 같은 계열의 03/04다. 원래 명시한 228회 구성과 예산을 유지한다. 별도 미지 경기장 토폴로지 평가라는 뜻은 아니다.

후속 수정은 후보 검색 반경을 넓히고 최종 RMS 3.5px·최대 중심 이동·방향 연속성 검사는 유지한다. 허용 목표 거리/각도도 유지한다. 미세 이동은 전진/후진과 함께 목표를 향한 제한된 RGB 방향 보정을 수행한다. 연속 시간의 즉시 응답은 physics가 아직 진행되지 않았으면 현재 관측을 유지하며, 이후 RGB가 상실된 경우 그 이전 관측으로 되돌아가지 않는다. 세 항목 모두 별도 회귀검사로 검증한다.

`40f735c`의 개발 8조건 × 3정책은 24/24 성공하고 RGB·명령 재생 감사도 24/24 통과했다. 전체 오프라인 검사는 2,262 passed, 4 skipped, 229 subtests passed다. 개발 실행과 자동 테스트를 동시에 수행했으므로 이 개발 자료의 벽시계 시간은 성능 비교에 사용하지 않는다.

최종 실행 전 연속 시간의 공통 경계 처리를 보완했다. 다음 0.25초가 예산 안에 들어오는지 확인하여 부동소수점 오차로 추가 이동하지 않는다. 대기 중 RGB 완료가 확인되면 물리 진행을 종료하고 늦게 도착한 응답은 성공/오류 여부와 사용량을 보존하되 실행하지 않는다. 이 완료는 오래된 모델 선택이 아니라 공통 RGB 완료 판정으로 따로 감사한다. 완료 없이 예산이 끝난 응답도 실행하지 않는다. 즉시 응답, RGB 상실, 시간 반올림, 완료와 오류 응답의 경합 및 미사용 응답 재생을 회귀검사에 포함했다.
