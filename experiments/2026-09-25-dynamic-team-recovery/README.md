# 2026-09-25 동적 협업 실패 결정 확인 (E1–E4 v51, V1–V4 v56, W1–W3 v58)

PR #147(v51)은 `--coordination dynamic`에서 실패가 나면 로봇들이 스스로 정하게 했다. 빔 쌍은 접근 실패 때 retry/abort, 파지 실패 때 regrasp/abort를 고른다. 상자 로봇은 retry/abort를 고른다. 한 작업을 포기하면 세 로봇이 continue_others/stop_all을 고른다. 이 기록은 실제 LLM으로 그 결정과 뒤따르는 물리 복구를 확인한 결과다.

## 실행

- 공통: open 지도, 작업 문장 "서로 역할과 순서를 합의해서 beam과 box를 dock_b로 옮겨", 동기 SIM, `--headless --record-replay --coordination dynamic`, 모델 `gemini-3.8-flash`, weld OFF.
- 각 실행은 진단 실패를 한 번 넣는다. 로봇에게는 실제 제어기 정지 이유만 보이고, 주입했다는 사실은 출력에만 남는다.
- 조건마다 1회다. 원본은 기본 체크아웃 `outputs/dynamic-team-recovery-20260925/`에 로컬로만 있다. 해시·부하 평균·결정별 응답은 `results.json`에 있다.
- W1–W3는 같은 잠금 안에서 구역 Z2 실행 뒤에 차례로 돌았다(병렬 실행 없음). v58의 E4/V4 조건(빔 포기)은 v56에서 이미 확인해 다시 돌리지 않았다.
- V1–V4가 도는 동안 같은 Claude 잠금 안에서 구역 벤치마크 개발 실행(#152)을 함께 돌렸다. 동기 SIM이라 SIM 결과는 영향을 받지 않고, wall 시간은 참고용이다.

## 결정 층

- 8회 모두 결정 대화가 제시된 선택지 안에서 끝났다. 결정은 참가 로봇에게만 물었다(쌍 실패는 r1·r3, 상자 실패는 r2, 작업 포기는 셋 모두).
- E3의 작업 포기 첫 라운드는 r3만 continue_others라 갈렸다. 둘째 라운드에서 r3가 동료를 따라 stop_all로 만장일치가 됐다. 빔은 이미 도착한 상태여서 두 선택의 물리 결과는 같다. 로봇들은 "임무는 두 화물 모두"라는 이유로 stop_all을 골랐다.
- V2·V3·V4에서는 세 로봇 모두 continue_others를 골랐다. V4에서는 빔 포기 뒤 상자가 실제로 도착했다.

## 범위

- 조건마다 1회라 성공률은 말할 수 없다. 확인된 것은 네 종류의 실패 대화가 실LLM에서 끝까지 돌고, 결정대로 물리 복구·작업 포기·나머지 작업 계속이 실행된다는 점이다.
- 전체 성공(두 화물 모두)은 접근 실패 주입(E1·V1·W1)과 v58의 상자 실패 주입(W3)에서 나왔다. 파지 실패 뒤 빔 복구는 아직 성공한 적이 없다(학습된 미세 정렬 지원 범위, 위 표).
- v58의 W 결과는 v58 수정이 겨냥한 두 문제(쌍 재접근 방향, 상자 재탐색)가 한 번씩 풀렸다는 사례다. v56과의 우열은 1회씩이라 일반화하지 않는다.
- 제어 종료 SIM 시간은 TensorBoard 변환기가 내보내지 않는다. 이 표와 `results.json`을 본다.
