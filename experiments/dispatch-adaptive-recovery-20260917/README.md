# 목적지·장애물 변화에 대응하는 3대 운반 복구

실행 소스 `e099a4a38c8da094c8c1946ffca2e7ab02f16a83`를 고정해 여섯 조건에서 새로운 LLM 합의부터 실제 집기·운반·방출까지 검증했다. 결과는 아래 표와 `results.json`, 전체 판정은 `final-full-reports.json.gz`에 있다. 이전 후보의 모든 결과는 최종 비교와 분리했다.

## 문제와 수정

기존 [여섯 조건 비교](../dispatch-variation-e2e-20260917/README.md)는 기본 A만 완주했다. B에서는 물체와 바닥 색을 혼동했고, 장애물 조건에서는 회전 운반이 실제 실행에 연결되지 않았다. 복구 과정에서 배치 공간 부족, 오래 이어진 영상 추적의 오차, 지원하지 않는 집기 역할 배치도 확인했다.

- **물체 인식:** 봉은 여러 채도 구간에서 같은 가느다란 형상이 유지되는지 검사한다. 직선 운반의 기울기도 중앙 단면 중심선이 네 구간 이상에서 일치할 때만 채택한다. 정확한 수직선에서 픽셀 행을 중복 집계하던 계산도 수정했다. 강한 바닥 색 한 구간이 보정 명령을 결정하지 않는다.
- **상자 추적:** 처음 찾은 뒤에도 강한 색 근거를 먼저 사용한다. 이미 식별한 상자에 한해 작은·어두운 색 조각을 이어 찾되, 이전 RGB 움직임의 예측에서 8픽셀 안에 있어야 한다. 첫 운반 영상과 같은 자리에 남아 있는 바닥 픽셀을 제외한다. 색 근거가 없을 때의 영상 이동 추정과 자기 카메라 파지 검사는 유지한다. 밝은 자기 영상의 잘린 cyan 채도도 별도로 처리하며, 떨어진 물체를 파지로 인정하던 변경은 도입하지 않았다.
- **공동 운반:** 두 차체와 화물 전체의 회전 경로를 검사하고, 공통 이동·회전 명령을 각 로봇 기준으로 변환한다. 영상으로 본 대형 간격의 지속 오차는 제한된 누적 보정으로 줄인다. 영상으로 본 각 차체의 방향 차이도 제한된 회전 보정으로 줄이며, 큰 차이는 경로 진행을 멈춘다. 현재 바퀴 배치가 충분히 보일 때만 누적 관측 오차를 보정한다. 전체 점유 공간의 방향은 영상 속 두 차체의 배치로 정하며, 시험 주행의 이동 방향은 모터 명령 변환에만 쓴다.
- **계획과 자원:** 통로·현재 장애물·대기 로봇·집기 접근 경로가 기존 스킬로 실행 가능한지 검사한다. 거부된 배치는 런타임이 임의 교체하지 않으며 세 LLM이 새로운 정확한 계획에 다시 동의해야 한다. 상자를 먼저 옮긴 경우에는 방출 뒤 로봇이 영상으로 빈 대기 위치까지 이동해야 봉 운반을 시작한다. 자원 대기는 실행한 스킬의 행동 횟수에서 제외하되 전체 시간 제한은 유지한다. 방출한 상자 위치는 차체를 찾는 대략적인 단서로만 사용하고, 주변 RGB에서 현재 바퀴 네 모서리가 일치할 때 양보 이동을 시작한다.
- **파지 유지와 평가:** 운반 기준 속도를 4cm/s에서 7.5cm/s, 회전 속도를 0.055rad/s에서 0.10rad/s로 바꿔 들고 있는 시간을 줄였다. 기존 모터 상한·영상 지연·방향·간격 중단 조건은 유지한다. 모터 상한에 닿으면 각 축을 따로 자르지 않고 두 로봇의 명령을 같은 비율로 줄여 공통 운반 동작을 유지한다. 속도 조정만으로 긴 우회의 낙하가 해결되지 않아 접촉 계산 간격과 접선 감쇠를 추가로 개선했다. 유한한 연접촉 모델의 미끄러짐이 줄었지만 무한정 파지를 보장하는 변경은 아니다. 평가에서는 운반 도중의 바닥 접촉과 0.11초를 넘는 표본 공백을 실패로 처리한다. 의도한 내려놓기 구간은 운반 구간과 구분한다.
- **관절 명령:** 작은 계산 간격에서 매번 정수로 반올림해 관절 명령이 실제 구동기에 전달되지 않던 문제를 수정했다. 누적 값의 소수 부분을 보존하고 내보내는 명령만 정수로 바꾼다. 세 계산 간격·양방향 명령의 시간당 전달량을 검사했다. 발행 명령을 관절 측정값으로 취급하는 변경은 아니다.
- **마지막 배치:** 봉은 허용 슬롯 안에서 옆 상자 로봇의 공간을 남긴다. 직선 경로에도 같은 여유와 고정 카메라의 명목 높이 보정을 적용한다. 상자는 영상 윤곽에 여유를 더한 범위가 목적 구역에 들어왔는지로 도착을 판단하며, 정확한 중심점까지 밀어붙이지 않는다. 방출 후 자기 영상에서도 상자와 바닥을 분리하는 같은 채도 기준을 사용하며, 기존 바닥 형상·다중 시점 정지 검증은 유지한다.

학습된 접근·파지 가중치, 실제 카메라 배치/FOV, 외관과 weld OFF는 유지했다. 기존 모델의 가중치가 모두 0인 고정 TOP 배경 영역만 제외하는 입력 어댑터는 출처와 해시로 기록했다. 카메라 기반 학생 실행에 측정 좌표·관절·접촉·성공 판정을 넣지 않았다. 사후 진단의 평가 좌표와 학생 입력은 구분해 보관했다.

seed 11, 같은 모델과 `local_contact_fine`을 사용했다. 조건마다 실제 LLM 요청을 새로 보냈으며 계획 재생이나 미리 든 상태를 사용하지 않았다.

물리 성공은 두 화물 모두 실제 운반 구간의 연속된 평가 표본에서 바닥 접촉이 없고, 들림, 전체 형상의 슬롯 포함, 바닥 지지, 로봇 접촉 해제, 약 1초간 5mm 이내 안정, weld 0을 별도 평가 출력으로 확인한 경우다. 실행기 완료 선언과 구분한다. 평가는 제어와 단계 전환에 전달하지 않는다.

동시에 최대 두 물리 워커를 실행했다. 실제 시간에는 모델 요청과 렌더링이 포함되므로 직렬 실행 대비 속도 향상으로 해석하지 않는다. 조건당 한 번의 탐색 검증이며 일반적인 성공 확률이나 임의 시작 자세·역할 교환의 검증이 아니다. 이 시작 배치에서는 다른 로봇이 막은 접근로를 우회·재배치하는 스킬이 없어 해당 역할 배치를 보수적으로 거부한다. 로봇 이름을 고정한 허용 목록은 아니다.

## 검증과 보관

자동 회귀 검사 884개와 하위 검사 160개가 통과했다. [동일 실행 소스의 GitHub CI](https://github.com/kcm0127-dotcom/ugrp/actions/runs/35245028101) 판정은 success다. 최종 사례 입력 감사 6/6, 실제 계획 요청 재구성 6/6. 상세한 호출·명령 수, 토큰, 경로 길이, 평가와 영상 검토는 `results.json`에 연결했다.

실제 모델에 보낸 요청과 RGB, 자기 발행 명령 이력으로 입력을 재구성하고 저장된 스킬 판단을 다시 계산했다. 입력 감사는 물리 성공의 대체가 아니다. 영상 전체 디코딩과 선택 프레임의 직접 검토도 구분한다. 정확한 검토 범위는 `manual-review.json`과 각 사례의 `video_qa`에 기록했다.

수치 접촉 설정은 `local_contact_fine`으로 바꿨다. 물리 계산 간격은 0.5ms에서 0.25ms로, 손가락–화물의 접선 감쇠는 3000에서 6000으로 변경했다. 마찰계수·힘 상한·접촉의 법선 설정·형상·질량은 같다. 교사 전용 정지 비교에서 기존 설정은 88.2초에 바닥에 닿았고 새 설정은 150초 동안 바닥 접촉 없이 유지한 뒤 집게를 열었을 때 방출됐다. 31초 이동 비교의 화물 이동 거리는 두 설정 모두 약 1.106m였다. 이는 학생 E2E와 별도인 제한된 수치 진단이다(`contact-resolution-diagnostic.json`). 이 설정은 이 시뮬레이터의 실행 프로필이며 실물에 보정된 물리 모델이라는 뜻은 아니다. 세 LLM은 역할·경로·선행 작업에 합의하고, 이후 연속 동작은 RGB 기반 제어기와 기존 학습 스킬이 수행한다. 모든 모터 동작을 LLM이 새로 추론한 결과로 표현하지 않는다.

원본 영상·RGB·요청/응답은 로컬 `outputs/dispatch-adaptive-*`에 있다. Git에는 요약, 전체 판정 보고서, 선택한 검토 이미지와 원본 해시를 저장한다. 원본의 원격 백업은 아니며 Drive는 사용하지 않는다. 확인되지 않은 USD 비용은 null로 두고 공급자가 보고한 토큰을 기록했다. 명령·스킬 판단·모델 호출은 서로 다른 단위이므로 임의로 하나의 행동 수로 합치지 않는다.

## 이전 후보와 남은 범위

최종 비교 이전 48회를 `diagnostics.json`과 `diagnostic-full-reports.json.gz`에 모두 보존했다. 기록 계획 진단과 실제 LLM 실행, 과거 최종 배치 판정과 강화된 연속 운반 판정을 각각 구분한다. 중간 후보 성공을 최종 비교의 분모에 섞지 않았다.

R3의 B 성공은 기록 계획을 투표한 물리 진단으로 실제 LLM 요청이 0회다. 중간 후보 4의 중앙 장애물·북쪽 차단 성공과 후보 10의 B 성공도 최종 후보의 분모에 섞지 않았다. 바닥 오인 추적으로 실제 장애물 접촉이 발생한 후보 6 F5도 실패로 보존했다. 후보 8의 상자는 구역에 들어왔어도 놓지 못했으므로 실패다. 후보 10 F5는 집기 역할 배치의 접근 경로 문제로 시작 단계에서 멈췄다. 후보 11 F4는 바닥 추적 전환, 후보 12 F4는 상자 배치 후 차체 인식 실패로 중단됐다. 후보 12 F5는 물리적으로 배치했지만 방출 확인을 못 했으므로 E2E 실패다. 후보 13 F4는 양보 후 대형 방향을 잘못 넣은 경로 계산으로 멈췄다. 후보 14·15에서는 한쪽 파지가 실제로 풀렸다. 큰 방향 차이는 낙하 뒤에 나타났으므로 방향 오차만을 원인으로 확정하지 않았다. 후보 11 F5/F6는 과거 최종 배치 판정을 통과했지만 강화된 중간 접촉 검사에서는 실패다. 후보 16 F5는 강화된 기준까지 통과했으나 F4는 목적 구역 접근 중 바닥에 닿았다. 이때 묶음 종료가 F4와 진행 중인 F2를 함께 중단했으며, 정상 완료 판정이 없는 두 경우를 중단으로 따로 기록했다. 중단된 두 사례는 최종 판정·명령 로그가 없고 원본 MP4가 열리지 않아 완료 입력 감사·영상 검증 대상으로 세지 않는다. 저장된 RGB와 평가 표본·시작 설정은 보존했다. 이후 예약 중단과 실행 중 시험 종료를 분리했다. 후보 17은 B와 좁은 통로를 통과했지만 긴 북쪽 차단 우회에서는 다시 파지가 풀렸다. 이 때문에 속도 조정 대신 별도 정지·이동 접촉 비교로 원인을 좁혔다. 후보 18의 작은 계산 간격에서는 기존 관절 명령 누적기의 정수 반올림 버그가 드러나 상자 접근이 중단됐다(`servo-subpulse-diagnostic.json`). 해당 실패와 수정 후의 전체 재실행은 분리했다.

`body-perception-replay.json`, `box-region-replay.json`, `box-identity-diagnostic.json`, `photometric-diagnostic.json`은 기존 영상의 사후 진단이다. 시연 재생·영상 관측 개선을 새 물리 성공으로 세지 않는다. 과거 긴 운반에서는 실제 차체 간격이 거의 일정해도 물체가 100초 동안 약 2.4cm 내려왔다(`retention-diagnostic.json`). 이번 작업 길이의 검증을 임의로 오래 들고 있기의 해결로 일반화하지 않는다.

지도에 없는 장애물은 시작부터 존재했다. 운반 중 장애물 추가, 운반 중 온라인 재합의, 요철 직접 통과, 다양한 무작위 시작·질량·마찰·조명, 실물 이식은 별도 검증이 필요하다. 이번 요철 조건은 안전한 통로로 우회한다.
