# 손목 카메라만으로 두 로봇 long_beam 공동 운반: 타당성 연구 (2026-09-26)

## 요청과 범위
- 코디네이터 요청(2026-09-26): 로봇 2대가 각자 자기 `robot_cam`(손목 fisheye)만으로 long_beam(0.60 m, 0.30 kg)을 옮길 수 있는지 본다.
  1. 손잡이·스테이션 정렬
  2. 공유 카메라 없는 파지 동기화: 자기 발행 명령 타이밍과 승인된 message/wait 프로토콜(`PairCarrySync`)만 쓴다.
  3. 들보가 시야를 가리는 상태에서 대형 유지 운반
  4. 동기화된 내려놓기
- 기존 공동 운반은 모두 TOP 카메라를 썼다(robust 5/5, dispatch). 이번에는 TOP·nav_cam·GT를 제어에 쓰지 않는다.
- 조건
  - 열린 바닥(`zone_wide`, 경계벽뿐)에서 한다.
  - `cargo_noslip_v1`이 주 조건이며 **사용자 결정 대기** 표시다. weld OFF.
  - Kiro B2의 팀 화물 부분 가시 인식 브랜치(`kiro/zone-own-perception(-v2)`)는 작성 시점에 원격에 없었다. 그래서 인식은 stub(`harness/owncam_pair_beam.py`: 라임 색상 + 발행 PWM 카메라 FK + 들보 윗면 평면)으로 대신했다.
- **M1이 아니고 성공 주장이 아니다.** 타당성 판단용 소규모 코호트다.

## 입력 경계
- 각 로봇이 쓰는 것
  - 자기 `robot_cam` JPEG와 자기 발행 PWM
  - 작업 시트(역할 end_neg/end_pos, 경로 다리 axial 0.60 m → lateral 0.30 m, 속도 0.06 m/s)
  - `PairCarrySync` 장벽. 보고에는 자기 프레임 id, 준비 여부, 이유를 담고, TTL은 1 s다.
- 쓰지 않는 것: 상대 영상, TOP, GT pose, 접촉. GT는 `evaluation-only.jsonl`에만 쓴다.
- `stub_approach` 조건
  - 스테이션 0.30 m 뒤 pre-station까지만 **GT P 제어**로 접근하고, 이 구간을 표시한다.
  - 시작은 0.8 m 더 뒤에서, ±0.6 rad 돌린 상태로 한다. 그 뒤는 `own_only`와 같다.
- 정적 보정 1개: 적재 운반 주행 척도(axial 0.772, lateral 0.697)
  - dev 601 GT 이동량에서 한 번 구한 정적 상수다(카메라 보정과 같은 지위). 실행 중 GT는 쓰지 않는다.
  - 결과 파일에 출처를 기록한다(`carry_odometry_calibration`).

**601 원인 분석** (GT 평가 전용)
- 대형은 강체처럼 유지됐다. r1–들보 간격은 운반 내내 0.452–0.453 m였고, 손가락 힘도 일정했다.
- 오차는 시간 기반 개루프 다리의 **이동 부족**에서 나왔다.
  - axial은 0.60 m 중 0.463 m(77 %)만 갔다.
  - lateral은 0.30 m 중 0.209 m(70 %)만 갔다. 교사의 무부하 이득을 그대로 쓴 탓이다.
- r1의 held-strip IoU는 0.87 → 0.46으로 떨어졌지만 GT 미끄러짐은 없었다.
  - 운반 자세 손목 시야는 들보 아래 가장자리의 얇은 띠와 어두운 바닥뿐이다. 띠의 명암이 바뀌면 IoU가 흔들린다.
  - 같은 프레임에서 띠 존재 비율(현재/anchor 픽셀 비율)은 ≥ 0.99였다. 실제 낙하면 이 비율은 0에 가까워진다.
  - 그래서 운반·장벽 유지 판정을 비율 ≥ 0.5로 바꿨다. 들어 올림 확인은 동시 움직임 IoU ≥ 0.45를 그대로 쓴다.
- 파지 시야 signature는 r1 0.029, r2 0.060이었다. 문턱을 0.02로 낮췄다. 실제 파지 증거는 들어 올림 동시 움직임 IoU(r1 0.735, r2 0.835)다.

## 사전 등록 (시험 고정 커밋 전 작성)
- 시드 **611–614**. 들보 yaw는 −0.5…+0.6 rad, 시작은 스테이션 뒤 0.26–0.35 m, 횡 ±0.04 m, yaw ±0.15 rad다. 표는 `SCENARIOS`에 있다.
- 조건
  - **O** = `own_only`: 4개 시드 모두.
  - **S** = `stub_approach`: 611, 612. 먼 거리 접근만 GT이고, 표시된다.
- 한도: SIM 240 s, 상태별 장벽 대기 한도는 코드 `STATE_LIMIT_S`에 있다.
- 판정 기준(타당성)
  - F1 정렬: O에서 두 로봇이 자기 시야로 `aligned`에 도달하고 GT 양손 파지(`both_gripped_gt`)가 된 경우 ≥ 3/4.
  - F2 동기화: 네 장벽(lift/carry/lower/open)이 모두 두 로봇의 보고로만 GO한다. 두 로봇 GO 시각 차이 ≤ 0.2 s.
  - F3 운반: 들어 올림 ✓, 들어 올린 동안 최대 기울기 ≤ 5°, GT 파지가 유지되는데 `LOAD_CHANGED_IN_CARRY`로 끝난 경우(거짓 낙하 경보) 0.
  - F4 내려놓기: 바닥 위 해제 ✓, 최종 들보 위치 오차 ≤ 0.10 m가 O에서 ≥ 3/4.
  - F5 weld 0, O의 `pose_source = none`, S의 GT 구간 표시.
- 중단 규칙
  - 시험 커밋 고정, 깨끗한 트리, 동시 SIM 2개, 스레드 1, 시드별 부하 평균을 기록한다.
  - 첫 제어 단계 전 인프라 예외만 1회 재실행한다. 코호트 뒤 조정은 새 버전으로만 한다.
