# 두 로봇의 RGB 통로 예약·양보·재출발

실행 소스 **`ca1ed29fcb4c75f82d18099d170952ef3a95cd72`**. 기반은 main `1b3b576`이며, 미병합 공동 파지 PR44–53과 독립된 변경이다. [#49](https://github.com/kcm0127-dotcom/ugrp/issues/49)의 첫 무부하 2대 단계로 구현했다. 코드를 저장한 뒤 고정 소스로 최종 8조건을 실행했다.

통과 가능 예약 조건 **6/6 도착**, 차단 조건 **1건 안전 대기**, 독립 주행 대조 **1건 미완료**를 구분한다. 각 조건은 한 번씩 실행한 기능 검증이며 일반 성공률이나 통계적 우위를 뜻하지 않는다. 대조도 충돌은 없었으므로 “충돌하던 시스템의 충돌을 없앴다”고 해석하지 않는다. 이번 대조의 차이는 근접·추적 상실로 인한 중단을 피하고 작업을 끝낸 것이다.

모든 최종 조건에서 로봇 간/지도 접촉 0, weld OFF, 카메라·로봇 형상 불변을 확인했다. 통과 조건의 최소 표본 원형 차체 여유는 **21.19cm**였다. 이는 반경 .18m 두 원 사이의 값이며 실제 표면 사이 최단 거리 측정은 아니다. 위치와 경계는 .1초 표본 및 영상 촬영 시점, 접촉과 weld는 모든 물리 step에서 별도 평가했다.

영상 촬영과 같은 시각의 위치 오차는 최대 **2.86cm**로 선언한 .035m 불확실성 범위 안이었다. 보고 누락의 첫 라운드부터 두 발행 명령이 0이었고, r1의 이후 관측된 최대 정지 변위는 **9.66mm**로 .08m 여유 안이었다. 보고가 돌아온 29라운드에 새로운 허가로 재개했다. 이 값은 해당 속도/주기/고정 조건의 측정이며 실물 제동 거리 보증이 아니다.

실제 실행 시간은 조건별 8.2–65.9초, 총 약 203초였다. 일부 입력 감사와 동시에 실행했으므로 속도 비교 기준으로 쓰지 않는다. 판단 라운드마다 두 독립 주행기가 제안한다. 모델 호출 0회·모델 비용 $0이며 중앙 조정 방식과 고전 RGB 주행 결과다. LLM 협상이나 독립 LLM 협업으로 보고하지 않는다.

## 실제 변경

- 기존 `HeadingMapNavigator`의 영상 위치/방향 추정과 A* 경로를 두 로봇에 각각 연결했다. 로봇마다 다른 정적 시작·목표 구역과 자기 발행 명령 이력을 유지한다. 자기 JPEG는 필수 입력으로 저장·디코딩하지만 현재 위치·제어 판단은 공용 top RGB에서 나온다.
- coordinator는 전체 경로를 연속 원형 swept capsule로 검사하고 FIFO/ID 순서로 원자적으로 예약한다. 점과 점 사이의 교차·반대 방향 엇갈림·추종도 검사한다. 대기 중이거나 이미 도착한 몸체도 경로를 막을 수 있다. 전체 경로 예약은 보수적이어서 좁은 통로에서는 43초의 대기가 발생했다.
- `REQUEST → GRANT → RGB ENTER → RGB CLEAR → RELEASE`와 매 라운드 허가를 기록한다. GO 유효시간은 최대 .6초지만 점유는 만료시간으로 지우지 않는다. 영상 도착 뒤 두 신선한 정지 프레임과 다른 요청 경로 밖임을 확인해야 해제한다. 막힌 출구는 임의 후진하거나 점유를 강제로 넘기지 않는다.
- 정상적인 경로 재계산은 새 route version으로 제안한다. 다른 예약/현재 몸체와 겹치지 않을 때만 옛 경로 점유를 유지하면서 새 경로를 추가하고 허가 세대를 바꾼다. 다른 task/plan으로의 변경은 점유를 보존한 채 정지·상위 재계획 필요 상태로 둔다.
- 로봇 측 gate는 참여자·계획/경로 버전·세대·epoch·프레임·유효시간을 검사한다. 거부된 주행 제안은 보정 단계나 회전 단계에 반영하지 않고 실제 0명령을 별도로 기록한다. 기존 포트의 명령 만료 정지를 유지한다.
- 상태 스냅샷은 명령 전송 전에 파일로 교체한다. 저장 상태로 조정기를 복원할 때 점유를 보존하고 epoch를 올린다. 마지막 재시작 이전 기록을 포함한 전체 원장은 `actor-decisions.jsonl`이다. `traffic-events.json`은 마지막 조정기 인스턴스의 사건 목록이다.

## 검증과 실패 기록

저장 RGB·정적 지도·발행 명령 시계·보고만 재생한 감사 **8/8**이 원래 결정, 예약 상태, 실제 발행 명령과 정확히 일치했다. 평가는 감사 입력에 사용하지 않는다. 충돌 예약 이중 허가와 보고 누락 중 이동이 없음을 추가 확인했다.

로컬 전체 검사 **605 tests + 161 subtests** 통과. 연속 구간 충돌, 누락/중복/역순 보고, 잘못된 출처/숫자, 만료/과거 GO, 계획 변경, 경로 확장, 점유 중 복원, 주차된 출구, 실제 RGB에서 거부된 보정 명령을 실행한 것처럼 취급하지 않는 회귀 검사를 포함한다. Ubuntu CI에는 실제 crossing 주행·도착 판정·RGB 재생·세션 정리를 추가했다. 원격 CI 결과는 PR에서 별도 확인한다.

물리 파일럿은 3회이며 모두 보존했다. 첫 교차로는 성공했다. 최초 head_on은 주행기의 정상 경로 수정이 예약에 반영되지 않아 55라운드부터 대기하고 300라운드 제한에 도달했다. 무충돌이었지만 실패로 기록했다. 기존 점유를 유지하는 경로 확장을 연결한 두 번째 head_on은 양쪽 도착했다. OpenCV 패키지 이름을 찾지 못해 물리 실행 전 종료한 준비 오류도 별도 기록했다. 기존 설치된 headless OpenCV의 실제 import 버전을 기록하도록 수정했으며 새 환경을 설치하지 않았다.

최종 8조건의 top RGB에서 조건당 4개 대표 프레임을 눈으로 검토했다. 좁은 통로 양쪽 own RGB와 보고 누락 시 own RGB도 확인했다. 모든 동영상 프레임을 수동 검토한 것은 아니다. 영상 자막은 검토용으로만 붙였고 모델 입력에는 없다. 비교 영상의 왼쪽은 대조 종료 프레임을 유지하며 오른쪽의 완료까지 보여준다.

## 현재 프로젝트 상태와 다음 순서

작업 시작 시 primary main은 원격 main과 같은 `1b3b576`이며 깨끗했다. 공동 파지 개선은 PR44→45→46→47→48→52→53에 누적되어 있고, PR53의 5분 유지/6지형 및 CI를 확인했다. 이 결과가 main에 병합됐다는 뜻은 아니다. 이번 무부하 예약 PR은 그 스택과 독립되어 main 기준으로 검토할 수 있다.

남은 연구는 **공동 하중 전체 footprint를 가진 운반 팀 + 다른 로봇의 조정**, 그 위에 **LLM 작업 분해·역할/목표 배정·상황별 재계획(#50)**, 마지막으로 고정 planner/LLM·통신 조건을 분리한 비교(#51) 순서가 적절하다. #49 전체를 완료 처리하지 않았다.

새 시작 위치/하중/재질 일반화, 임의 장소 재파지, 다수 자원의 복잡한 교착 해소, 점유 중 새 작업 계획을 실제로 복구하는 정책, 실제 네트워크와 벽시계 비동기 실행, 실물 로봇은 이번 검증 밖이다. 모델 대기 동안 물리가 계속 진행되는 LLM 통합 실험도 아니다. main 병합은 해당 PR에 대한 명시적인 사용자 승인 뒤 수행한다.
