# ACT 맵·프로토콜 준비 v1

[개선 계획](act_map_generalization_plan.md)의 작업 묶음 A를 위한 맵 생성·분할·정적 검토 경로다.
학습과 교사 시연, 실제 운반 평가는 후속 B–D의 작업이다.

## 공통 지도와 실행기 경계

정적 표현은 기존 `ugrp.pair_navigation_map.v1`을 사용한다. 경계, 고정 TOP 카메라,
장애물, 작성 시작 구역, 목표 위치·방향, 전체 하중 footprint를 함께 검증한다.
기존 예시 여섯 지도는 원본 그대로 읽고 회귀 집합으로만 등록한다.

`sim/act_map_suite.py`의 `scene_config`는 같은 지도를 dispatch 장면 빌더가 읽는
`ugrp.dispatch_map_preview.v1`로 변환한다. 지도 경계 바깥에 물리 벽을 추가해
계획에서의 자유 공간과 실제 충돌 경계를 맞춘다. 로봇 세 대·봉·상자와 자기 카메라는
기존 production 모델을 유지하고 weld를 끈다. 목표 바닥 표시는 0/90도 방향에 맞춘다.
미리보기는 접힌 팔과 바닥에 놓인 물체의 초기 장면이다. 명목 운반 시작 자세는
기하 검사만 위한 값이며, 초기 장면이 파지·들기를 마친 상태라는 뜻은 아니다.

학생에게 제공할 `student-task.json`에는 엄격히 검증된 작성 지도만 들어간다.
정확한 초기 배치, seed, 분할, 사건 스케줄, 예상 결과, 기하 탐색 경로는 별도 파일에 둔다.
`load_prepared_map`은 저장된 지도·학생 과제를 manifest의 해시와 대조한 후 반환한다.
이 함수는 정적 과제 로더이며 학생의 관측·행동 API가 아니다.

현재 dispatch는 두 물체/목적지 A·B, `north/south` 경로와 전용 자원 이름을 요구하며,
기존 ACT는 이를 8차원 문맥에 인코딩한다. 이 PR에서는 새 지형을 그 경로 이름에
억지로 대응시키지 않는다. 새 지도는 **생성·로딩·물리 미리보기만 지원**한다.
실제 운반 연결 시 다음을 하나의 변경으로 구현·검증해야 한다.

1. 작성된 경로 구간·자원·최종 방향을 포함한 버전 있는 임무/계획 계약.
2. 같은 경로·방향을 로봇별 제안·합의 hash와 단계별 실행 권한에 연결.
3. RGB 추정에 따른 구간 전환, 전체 하중 clearance와 공동 정지/복구.
4. 동일한 지역 경로·방향을 ACT 텐서와 데이터 출처에 연결하고 새 모델 버전을 사용.

기존 체크포인트의 의미를 바꾸거나 지원하지 않는 이름을 조용히 `north/south`로
치환하지 않는다. 신규 경로에 기존 ACT/dispatch 계약을 사용하면 오류가 난다.

## 맵 분할

| 집합 | 새 맵 수 | 내용 |
| --- | ---: | --- |
| 학습 | 6 | 개방 공간·문·L자 코너 각 2개 |
| 개발 | 3 | 같은 계열의 독립 배치 각 1개 |
| 시험 A | 3 | 같은 계열의 미사용 기하·목표 조합 각 1개 |
| 시험 B | 2 | 두 문과 어긋난 중간 공간의 새 연결 순서 |
| 불가능 대조 | 2 | 40cm 문, 완전 차단 |
| 회귀 | 0 (기존 6) | 기존 narrow-door/L/S/staggered/branch/blocked |

총 22개 물리 배치를 확인한다. 작은 준비용 suite이며 일반화 성능의 통계적
입증에 충분하다는 주장이 아니다. 특히 개방 공간은 경계 폭을 소폭 달리한 약한 변화다.
더 복잡한 갈림길·우회 구조, 비직각 코너, 마찰·경사는 후속 suite에서 확장한다.
시험 B는 이번 학습 집합에서 보류한 구체적인 연결 순서이며, 모든 미지 그래프에
일반화한다는 평가가 아니다. 과거에 검토한 지형은 새 시험 성적에 포함하지 않는다.

map generation seed는 각 인스턴스별로 다르다. physics seed `[11, 29]`는 별도
네임스페이스이며 이번 정적 미리보기는 11만 사용한다. 모델 학습 seed는 파일럿 후
고정한다. 같은 맵에서 시작점/사건/학습 seed를 반복해도 맵 수를 늘리지 않는다.
생성기는 seed 중복, 물리 배치 중복(이름·목표만 바꿔도 검출), 분할 누락,
시험 B 구조의 학습/개발 유입을 거부한다. 인접 프레임 분할은 사용하지 않는다.

## 검사와 증거

기하 검사는 기존 SE(2) 격자 탐색과 전체 하중의 연속 구간 샘플 검사를 사용한다.
footprint는 앞뒤 0.40m × 좌우 1.02m에 각 방향 0.025m 여유를 더한다.
이것은 보수적인 작성 모델이며 현재 파지 폭을 실시간 정답으로 얻지 않는다.
경로가 있으면 `geometric_candidate`, 격자 탐색만 실패하면
`no_lattice_path_unresolved`다. 40cm 문/완전 차단은 여유 포함 최소 하중 폭
45cm보다 좁고 벽이 경계를 가로막는 별도 기하 근거를 남긴다.
어느 결과도 실제 교사 통과 또는 학생 운반 성공으로 세지 않는다.

렌더 시 각 지도·경계의 컴파일된 MuJoCo 위치·크기·충돌 활성, 목표 paint,
TOP 배치/FOV, weld OFF, 초기 충돌을 검사한다. 고정 카메라의 frustum 내에
장애물 윗면 전체가 들어오는지도 계산한다. 카메라 이미지 자체의 가림이나 품질은
갤러리와 원본을 따로 검토한다. r1/r2/r3 자기 영상과 TOP 영상을 모두 보관한다.
맵 해시 → dispatch 변환 해시 → 실제 scene XML 해시를 연결한다.

## 재현

소스/설정을 먼저 커밋하고 작업 트리가 깨끗한 상태에서 실행한다. 출력 폴더가
있으면 덮어쓰지 않는다. 시뮬레이션/모델 서비스는 필요하지 않고 외부 API 호출도 없다.

```sh
.venv-sim-worker-mac/bin/python -m pytest -q tests/test_act_map_suite.py
.venv-sim-worker-mac/bin/python scripts/ugrp_session.py run act-map-preview-NEW -- \
  .venv-sim-worker-mac/bin/mjpython scripts/prepare_act_map_suite.py \
  --render --output outputs/act-map-preview-NEW
```

`--render`를 생략하면 맵·분할·기하 검사·도면만 만든다. 이미지 생성에는 기존
시뮬레이션 환경의 Pillow와 한글 글꼴이 필요하다. 원본 결과의 `manifest.json`,
`summary.json`, `environment.json`, `artifact-hashes.json`과 축소 갤러리를
새 `experiments/` 기록에 보존한다. raw 장면 XML/카메라 영상은 로컬 `outputs/`에
보관하며 백업으로 표현하지 않는다. 작업에서 시작한 세션은 종료를 확인한다.

## 후속 평가 프로토콜

[protocol_v1.json](../maps/act_generalization/protocol_v1.json)은 현재 `pilot_design`이다.
최종 성공 기준/허용 감소폭/시간·행동·비용/충돌·낙하 표본 주기는 비어 있으며,
`require_frozen_protocol`은 이 상태의 최종 평가를 거부한다. 학습·개발 집합의
교사 파일럿으로 비용/분산과 실패 범위를 확인한 후 모든 값을 고정한다.

교사 시연은 특권 상태 사용 여부와 모든 시도/실패/제외 사유를 기록한다.
운반 진입률, 진입 후 엄격 성공률, 전체 임무 성공률은 따로 보고한다.
기존 RGB/현재 ACT/개선 ACT는 같은 조건으로 비교하고 정답 교사는 별도 진단한다.
완료 오판·낙하·충돌·한쪽 완료 대기·교착·timeout을 시간·행동·비용과 함께 남긴다.
맵별 묶음을 유지한 대응 차이/신뢰구간을 사용하며 빨리 실패한 시간을 이득으로 세지 않는다.
시험 A/B의 정적 검토만 이번에 수행하며 교사/학생 rollout이나 튜닝은 수행하지 않는다.
정책 성적을 본 뒤 튜닝하면 새 holdout을 만든다.

사건 축은 baseline `none`만 구현했다. 점유·메시지 지연·미관측 장애물은
프로토콜에 독립 축으로 예약했으며 스케줄러와 입력 감사를 붙이기 전에는 실행을 거부한다.
관측되지 않은 사건을 정적 지도나 학생 과제에 사전 노출하지 않는다.
