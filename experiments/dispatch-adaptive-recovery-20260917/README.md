# 목적지·장애물 변화 대응 복구

후보 `4ffae7bfb4bd367bd5c29c5c69a25aa6f6b4a643`에서 정확한 수직 영상의 샘플 구간이 중복되는 계산 오류를 확인했다. 이를 수정한 다음 후보의 전체 비교를 준비 중이다. `results.json`에는 이 후보의 완료된 시험만 모으고, 이전 23회 진단·중간 후보 결과는 `diagnostics.json`에 별도로 보존한다.

## 문제와 수정

기존 [여섯 조건 비교](../dispatch-variation-e2e-20260917/README.md)는 기본 A만 완주했다. B에서는 빔과 노란 바닥 표시가 합쳐졌고, 장애물 네 조건에서는 회전 운반이 연결되지 않아 통로 폭 검사에서 멈췄다.

- 밝게 비친 상자의 색 추출은 좁은 cyan 색상·높은 밝기 조건으로 보완한다. 어두운 바닥을 함께 추출하지 않으며, 양쪽 회전·복귀 영상의 파지 확인 기준과 모든 정지 기준을 유지한다.
- 직선 운반의 기울기는 포화된 물체 중앙 단면의 중심선으로 측정한다. 불확실한 프레임은 기존 정책에 따라 정지·재관측하며, 보정 횟수나 기울기 제한을 늘리지 않는다.
- 원본 TOP 영상의 여러 색상 임계값과 이전 빔 윤곽이 함께 지지하는 가느다란 부분을 추적한다. 손가락·바닥이 붙어 보이는 픽셀을 물체 전체로 취급하지 않는다.
- 정적 지도와 현재 RGB 장애물 관측으로 두 로봇·화물을 포함한 회전 대형의 경로를 검사한다. 실행할 수 없는 합의는 폐기하고 이유를 세 모델에 전달해 새 계획에 다시 전원 동의를 받는다.
- 로봇의 몸체 이동은 영상으로 추적하고, 현재 네 바퀴의 배치가 충분히 보일 때 누적 오차를 보정한다. 두 로봇에 공통 회전을 지시하며 실제 영상 간격의 지속 오차를 제한된 누적 보정으로 줄인다. 명령 발행을 이동 성공으로 간주하지 않는다.
- 자기 카메라의 최근 영상 연속성과 기존 면적 기준을 함께 검사한다. TOP에서 물체와 두 로봇의 동행도 별도로 확인한다. 큰 시각 변화·간격 이탈·관측 실패에서 정지하는 조건은 유지한다.
- 혼잡한 집기·회전 공간은 예약한다. 상자를 먼저 운반해야 할 때에는 실제 방출 확인 뒤 로봇이 영상으로 빈 대기 위치까지 이동해야 긴 물체 작업이 시작된다.
- 두 목적 슬롯의 인접 공간도 고려한다. 긴 물체는 허용된 슬롯 안에서 상자 쪽 공간이 넓게 남는 점을 선호하고, 상자는 영상 윤곽에 여유를 더한 범위가 목적 구역 안에 들어왔는지로 도착을 판정한다. 물체가 이미 구역 안에 있는데 중심점까지 계속 밀어붙이던 동작을 제거한다.

학습된 접근·파지 가중치는 유지한다. 다만 혼잡한 환경의 먼 배경만 달라져 생기던 파지 지원 범위 거부를 해결하기 위해, 기존 학습 방향이 모두 0인 고정 TOP 배경 영역만 제외한 입력 어댑터를 기록한다. 자기 영상·배운 방향·기존 지원 기준을 임의로 낮추지 않는다.

`diagnostics.json`과 `diagnostic-full-reports.json.gz`에 R1–R11, 후보 1–3의 여섯 실패, 후보 4의 네 시험과 후보 5의 한 시험을 모두 보존한다. 현재 총 23회 중 성공 3회·실패 20회이며, 최종 비교의 분모에 섞지 않는다.

- R3의 open/B는 기록 계획을 투표한 물리 진단의 성공이다. 실제 LLM 요청은 0회이며 새로운 LLM 합의 E2E로 세지 않는다.
- R4–R8은 배경 변화, 바퀴/바닥 분리, 손가락과 빔 윤곽 연결 문제를 좁혔다.
- R9/R10에는 영상 위치 추정의 누적 오차가 있었다. R9의 실패를 특정 물체와의 실제 충돌로 확정하지 않는다.
- R11은 초기 기록 계획 거부 뒤 실제 모델 재합의·상자 운반·양보를 수행했지만, 운반 완료된 상자가 차지한 공간 때문에 빔의 기본 도착점에 경로가 없었다.
- 후보 1은 독립적인 두 자세 보정이 들고 있는 물체에 서로 다른 힘을 주는 문제를 드러냈다. 후보 2는 자기 카메라의 고정 기준점 거부와 영상에서 추정한 대형 간격 이탈로 멈췄다. 관측 간격을 실제 몸체 간격과 동일시하지 않는다.
- 후보 3의 일반 장애물 시험은 빔 운반과 방출을 일단 마쳤으나, 뒤따른 상자 운반 로봇이 놓인 빔과 접촉해 최종 전체 판정에 실패했다. 북쪽 차단 시험은 영상 간격 오차가 지속됐고, 물체/자기 영상의 급격한 변화로 정지했다. 이 정지를 단순 오인식으로 분류하지 않는다.

`body-perception-replay.json`은 이전 RGB 985프레임의 몸체 관측 재생이다. 대형 방향과 개별 방향의 영상 추정 일치를 확인한 것으로, 정답 자세 정확도나 새 물리 성공이 아니다. `box-region-replay.json`은 기존 상자 영상에 새 목적 구역 판정을 적용한 진단이다. 해당 시점에도 빔 접촉이 남아 있었으므로, 이를 성공으로 부르거나 도착 판정 변경만으로 충분하다고 주장하지 않는다. 최종 후보는 배치 공간 확보를 함께 적용한다.

별도 평가 로그를 사후 비교하면 후보 3의 실제 몸체 간격은 대부분 일정했지만, 든 물체는 100초 동안 약 2.4cm 내려왔다. 영상 간격에는 팔·물체 이동과 투영 오차도 섞인다. `retention-diagnostic.json`에 이 관측을 남긴다. 최종 후보의 완주는 해당 작업 길이의 검증이며 임의로 오래 들고 있기의 해결을 뜻하지 않는다. 이 평가값은 제어에 사용하지 않는다.

후보 4는 중앙 장애물·북쪽 차단 운반에 성공했다. B 직선 운반에서는 반복된 영상 기울기 보정으로 멈췄고, 좁은 남쪽 통로 조건에서는 빔을 배치한 뒤 북쪽을 지나는 상자의 파지 영상 비교에서 실패했다. 후보 5의 B 재시험으로 약한 채도의 노란 바닥이 중심선 측정에 섞이는 문제를 확인했다. 최종 후보의 색 추출 수정은 `photometric-diagnostic.json`과 재현용 영상에 근거한다. 미확정 파지를 재시도로 통과시키는 변경은 채택하지 않았다.

세 LLM은 역할·경로·선행 작업에 합의한다. 이후의 연속 주행은 RGB 기반 기하 제어기와 기존 학습 스킬이 수행한다. 이를 LLM이 모든 모터 동작을 새로 추론하거나 미지 지형 전반에 일반화한 결과로 표현하지 않는다. 지도에 없는 장애물은 시작부터 존재한다. 주행 도중 새 장애물 생성, 운반 중 온라인 재합의, 요철 직접 통과는 별도 검증이다.

## 보관과 재현

원본 RGB·실제 모델 요청/응답·영상은 로컬 `outputs/dispatch-adaptive-*`에 보존한다. Git에는 요약, 선택한 검토 이미지, 출처와 해시를 남긴다. 원격 raw 백업은 아니며 Drive는 사용하지 않는다. USD 비용은 확인되지 않아 null이며 공급자가 보고한 토큰만 합산한다.

모델은 [기존 스킬 통합 번들](../dispatch-skill-integration-20260917/README.md)의 `models.zip`을 사용한다. 새 출력 경로와 본인의 모델 프록시를 준비하고 `cohort.json`의 조건·인자·모델 해시를 따른다. `--plan-replay`를 지정하면 새로운 LLM E2E가 아닌 기록 계획 진단이 된다.

```sh
python scripts/ugrp_session.py run dispatch-NEW -- \
  .venv-sim-worker-mac/bin/mjpython scripts/run_dispatch_e2e.py \
  --executor skills --variant north_blocked --seed 11 --required-dock dock_a \
  --grasp-model-dir outputs/dispatch-models/models/grasp \
  --stage-model-dir outputs/dispatch-models/models/varied \
  --output outputs/dispatch-NEW --max-wall-s 1500 --max-input-tokens 600000
```
