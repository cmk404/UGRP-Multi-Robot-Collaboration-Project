# 2026-09-25 구역 배송 협업 벤치마크 (교사 실행기)

사용자 요청(2026-09-25): 지도를 넓히고 물건을 늘린다. 목표를 "A에 빨강 2, B에 청록 1, C에 초록 1·빨강 1"처럼 구역별로 둔다. 이 조건에서 계획 먼저(plan_first)와 필요할 때만 대화(dynamic)의 차이를 본다. 사전 등록과 두 번의 보완은 [protocol.md](protocol.md)에 있다.

**모든 결과는 교사 실행기 조건이다.** 이동·IK는 정답 좌표로 하고, 잡기는 실제 집게로 한다(weld OFF). 로봇(LLM)이 받는 입력은 다음뿐이다: 자기 RGB, TOP 두 대 RGB, 목표·작성 지도, TOP RGB로 만든 상자 이름·추정, 팀 게시판(실행기 영수증), 자기 작업 이력, 동료 메시지. 성공은 심판 기준 구역 개수 일치이며 RGB 스킬 성공이 아니다. TOP RGB 개수 일치(`goal_met_rgb`)는 따로 적었다.

## 해석과 범위

- 조건마다 1회라 성공률·속도 우열을 일반화하지 않는다. 아래는 사례다.
- 교사 실패가 없었던 실행(Z2-G5, Z3 전부)은 두 방식 모두 목표를 달성했다. 완료 SIM 시간은 한쪽으로 기울지 않았다(Z3 G5 dynamic 25초 빠름, G8 plan_first 9초 빠름). 차이는 배분의 질에서 나온다.
- LLM 호출·토큰은 모든 성공 짝에서 dynamic이 적었다. Z3: G5 11 대 18회(50k 대 92k 토큰), G8 14 대 18회(68k 대 100k).
- 사용자가 기대한 "지도·물건을 늘리면 동적 협업의 효과가 드러난다"는 이 코호트에서는 **실패 뒤 재배분**으로만 보였다(Z2-G8-dyn의 red-1 재선언). 실패가 없으면 SIM 시간 차이는 작다. 실패 주입이나 반복 실행으로 확인하는 일은 아직 하지 않았다.
- 교사 비킴 규칙은 Z3 실LLM 실행에서는 한 번도 발동하지 않았다. 발동 확인은 diag-plan-replay와 단위 테스트뿐이다.
- 이 결과는 RGB 스킬로 옮긴다는 주장이 아니다. 교사 실행기가 정답 좌표를 쓰기 때문이다.
