# 공동 작업 입출력·단계 동기화 검증

2026-09-16. 창민의 동기화 담당 범위에서 T1 입출력 계약과 T2 공통 단계 전환을 구현했다.
실행 소스: `89b93d81e45670f09c0d0d90842d6ddcac376d56` (main `1b3b576` 기반).
이후 결과·설명 추가 커밋은 실행 코드 버전과 구분한다.

## 변경과 판정

- 상위 계획, 로봇의 영상 근거 보고, 실행 허가를 구분하는 엄격한 JSON 계약을 추가했다.
- 기존 `PairCarrySync`를 사용해 GRASP → LIFT → CARRY → LOWER → RELEASE의 준비·완료 합의를 구현했다.
- 발행 전 허가·기간·명령 중복·단계를 확인한다. 명령 발행/접수는 물리 완료를 뜻하지 않는다.
- 한쪽의 부정 보고·불확실성·기간 만료 후에는 새 epoch의 양쪽 관측을 다시 받는다.
  이미 HOLD 중인 새 부정 보고도 부분적으로 모인 준비를 무효화한다.
- 같은 단계의 이미 발행한 행동을 새 영상으로 재확인할 수 있으므로 HOLD 후 해제 등을 무조건 재실행하지 않는다.
- 기본 보고 유효시간 0.6초, 명령 상한 0.25초, confidence 하한 0.8은 시험 설정이다.

9/9 조건에서 603개 명시적 검사가 예상과 일치했다. 이는 **7개 완료 보고 수집과 2개 의도된 대기**다.
물리 운반 성공률 9/9라는 뜻이 아니다. 계획 변경은 PLAN_UPDATED로 별도 기록하므로 HOLD 사건 수에 합산하지 않는다.
조건당 한 번의 결정적 프로토콜 fixture 실행이며 실제 시간 측정은 이 작은 예제의 CPU 실행 비용만 뜻한다.
모델 호출·토큰·비용은 0이다. 로봇 제어·영상 인식·MuJoCo·네트워크·별도 OS 프로세스는 실행하지 않았다.

전체 기존 회귀검사: **655 tests + 154 subtests 통과**, 로컬 실행 16.92초.
신규 테스트 60개는 전체 단계 준비/완료, 결손·중복·역순·시계·허가·계획·종료 및 예제 포트를 포함한다.
그중 한 테스트는 25개 seed의 보고 순서/정지 시점 조합으로 다섯 단계의 조기 전환을 검사한다.
이는 새로운 물리 시작 조건에서의 일반화나 실제 통신 장애 복구 시험이 아니다.

## 재현과 증거

```sh
python scripts/demo_task_stage_sync.py --output outputs/task-stage-sync-NEW-ID
python scripts/run_ci_tests.py
```

첫 명령은 Python 표준 라이브러리만 필요하다. 두 번째 명령의 의존성은 `requirements-test.txt`를 따른다.
예제는 clean checkout과 새 출력 경로를 요구한다. 실행 전에 소스를 커밋하고 코호트 동안 바꾸지 않았다.

- [전체 설정·환경·집계·원본 해시](protocol/summary.json)
- [정상 사건 로그](protocol/normal.json), [보고 단절·재개](protocol/report_gap.json)
- [지지 확인 누락](protocol/missing_support.json), [명령만 발행](protocol/command_only.json)
- 나머지 조건도 `protocol/`에 생략 없이 보관했다. 모든 9개 원본 파일의 SHA256을 재확인했다.
- [팀원 연결 계약](../../docs/task_stage_sync_contract.md), [계획 JSON](../../examples/task_stage_sync/plan.json)

이 디렉터리는 소규모 프로토콜 fixture의 원본 JSON을 포함해 Git으로 보관한다.
`fixture://` 영상 참조는 합성 입력 식별자이며 실제 이미지 파일이 아니다. 실제 로봇 영상은 생성하지 않았다.
CI는 같은 9조건의 원본 기록을 `task-stage-sync-protocol` artifact로 14일간 보관한다.
이 문서 작성 시점의 로컬 결과와 GitHub CI 결과는 PR의 실행 상태를 통해 별도로 확인한다.

## 남은 연결 작업

이번에 끝낸 범위는 재사용 가능한 계약·다섯 단계 관리기·JSON 예제 포트와 회귀검사다.
기존 물리 운반 실행기는 이 새 관리기로 자동 교체하지 않았다. 기존 운반용 barrier의
기본 HOLD 동작은 그대로이며 새 선택 인자 `renew=True`만 추가했다.

다음은 실제 로봇별 영상 보고 생산자와 bounded submit/STOP/watchdog 연결, 메시지 버스와
별도 실행 프로세스의 지연·단절·재시작 시험이다. shared resource 실제 점유, 일반 공동 복구,
실제 지지 관측·내려놓기 성공도 별도 검증해야 한다. T1/T2 전체 완료로 표시하지 않는다.
