# Colab 중계 전송 최적화

기존 중계기는 네 모델 호출을 병렬 처리하지만 Contents API의 요청 다운로드와 응답 업로드를 하나의 제어 루프에서 순서대로 처리했다. SDK의 요청마다 새로운 HTTPS 연결도 만들었다. 긴 다운로드/전달이 다른 모델의 완료 응답 전달을 지연시킬 수 있다.

변경은 로봇 코드·모델·모델 호출 수·영상·반복 횟수를 유지하고, 기존 인증·동일 Colab 런타임·동일 Contents API를 사용하는 중계 경로에 한정한다. 네 개의 독립 파이프라인이 각자 연결을 재사용하여 다운로드→단 한 번의 모델 호출→응답 전달을 수행한다. 네 슬롯을 늘리지 않는다. 업로드 실패는 저장된 동일 응답만 다시 전달하며 모델 호출을 재시도하지 않는다. SIGTERM은 신규 접수를 중지하고 접수된 응답 전달을 마치는 drain으로 처리한다.

실제 교체는 기존 프로세스를 일시 정지한 뒤 로컬 요청/응답 감사 파일과 전달 카운터가 모두 일치하는 경우에만 진행한다. 미완료·불확실한 API 호출이 하나라도 있으면 기존 프로세스를 재개하고 교체를 미룬다. 새 프로세스는 이전 요청 ID를 인계해 중복 과금을 방지하며 기존 실행 종료 시각을 연장하지 않는다. 변경 시각·중계 소스 SHA를 별도 기록하고 변경 전후 및 교체에 걸친 시행의 wall time을 같은 전송 조건으로 합치지 않는다. 로봇 행동과 실패 기록을 지우거나 재시도로 대체하지 않는다.

벤치마크는 같은 살아 있는 Colab Contents API에서 별도 임시 파일의 동일 payload를 전송한다. 모델 호출·시뮬레이션·카메라 변경이 없는 I/O 측정이며 전체 로봇 실행 속도 향상과 구분한다. 이전·변경 연결의 순서를 번갈아 측정하고 실제 결과 검증 기록은 별도 JSON에 보관한다.

실제 배포 준비 중 기존 D 런타임이 서버 할당 목록에서 사라졌다. 원인은 미확정이며 마지막 정상 수집 이후 접속 실패를 반복했다. D의 73개와 기존 C의 37개, 총 110개 체크포인트를 보존하고 서버 부재를 확인한 뒤 해당 작업의 호스트 프로세스만 정리한다. 미확인 응답 전달 1건과 미완료 시행은 인프라 중단으로 따로 기록한다. 이미 완료된 성공·실패를 다시 실행하지 않는다.

따라서 예정한 실행 중 hot handoff는 수행하지 않고, 같은 actor SHA와 남은 121개 시행으로 단 한 번의 유한한 E 실행을 준비한다. 원래 D의 종료 한도(20:06 KST)는 유지한다. 새 실행 전 동일 런타임에서 4요청 묶음 × 두 전송 방식 × 4쌍의 교차 순서 I/O 진단을 수행한다. 이 측정은 로봇 성능 비교가 아니다. 전송 오류와 일시적 파일 부재로 종료하지 않으며, 서버에서 해당 할당이 사라졌다는 독립 확인이 60초에 걸쳐 최소 3번 일치할 때만 호스트 작업을 정리한다. 자동 VM 재할당은 하지 않는다.

## 검증 결과

- 실행 코드: `b0288f09890eb881028139a4aabe67484c9e9b93`; actor는 `5a51a355fa6f8f535fbbe12a0a21d5fdb460e047` 그대로 유지.
- 전체 회귀검사 1,237 passed, 3 skipped, 191 subtests.
- T4 재할당 E/F는 둘 다 HTTP 503으로 거절돼 로봇 실행에 진입하지 못했다. 전송 성능 진단만 별도 Colab CPU 런타임에서 수행하고 정상 종료했다.
- 실제 동일 Contents API, 요청 8,207 bytes/응답 1,048 bytes × 4개, 두 방식 각 4번, AB/BA 순서 교차, 모델 호출 0, 응답 원문 전부 대조. 묶음 소요 시간 중앙값: 순차 2.09169초 → 연결 재사용/병렬 0.55538초(73.45% 감소, 처리 속도 3.77배).
- 이 수치는 네트워크 전송만 측정하며 모델 응답·영상 처리·로봇 전체 wall time의 개선율이 아니다. 최적화 중계가 실제 로봇 시행에 적용된 결과는 아직 없다.
- 기존 수집 110/231개를 로컬 숫자 스냅샷으로 회수하고 원격 archive 및 result 해시를 확인했다. 나머지 121개는 대기이며 실패로 대체하지 않는다. 새 회수 20개와 할당 실패 2개, I/O 진단 8개를 TensorBoard 새 스냅샷에 분리 표시한다. 신규 영상은 원격 원본에 남아 있다.
- Kaggle의 기존 108회 ACT 평가는 별도로 RUNNING 확인. 새 512px 학습이나 Mac 무거운 대체 실험은 시작하지 않았다.
