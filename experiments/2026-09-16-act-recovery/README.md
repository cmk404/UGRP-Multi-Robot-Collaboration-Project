# ACT 복구 학습과 조합 일반화 — 최종 결과

복구 시연과 학생 방문 상태의 교사 복구 궤적을 학습·평가했다. **정상 출발과 개발 조건에서는 개선이 있었지만, 미학습 복합 오류에 대한 엄격한 일반화 성공은 확인하지 못했다.** 현재 모델을 기존 제어기의 안정적인 대체재로 판단할 근거는 부족하다.

같은 16개 시작 장면에 교사 2종과 학생 3종×학습 seed 2개를 적용하여 128회 물리 시험을 완료했다. 복구 교사는 16/16으로 시험 조건의 물리적 해결 가능성을 확인했다. 학생의 정상 조건은 두 seed 합계 정상 시연 0/8, 복구 시연 3/8, 학생 상태 추가 6/8이었다. 복합 오류는 세 학생 조건 각각 0/24였다. 두 seed는 동일 장면의 반복이며, 독립 장면 수가 두 배가 된 것은 아니다.

| 조건 | 정상 | yaw+횡오차 | 먼 거리+yaw | 지나침+yaw | 전체 기준 | 물리 들기 | 성공 시 평균 접근 SIM초 |
|---|---:|---:|---:|---:|---:|---:|---:|

전체 기준은 정렬·안정 유지·접근 접촉 없음·물리 파지/들기를 모두 요구한다. 물체를 든 것만으로 채점하면 복구 ACT에는 복합 오류 성공이 2건 더 있다. seed16의 `yaw_lateral-02`는 최대 yaw 1.345°로 1° 기준을 넘었고, seed17의 `overshoot_yaw-03`은 x 10.0mm/yaw 1.984°로 5mm/1° 기준을 넘었다. 따라서 “학생은 복합 오류에서 한 번도 들지 못했다”는 설명도 정확하지 않다. 모든 사례의 두 판정은 [final-audit.json](final-audit.json)에 보존했다.

학습 seed에 따른 변동도 크다. 복구 ACT의 정상 성공은 3/4와 0/4, 학생 상태 추가 ACT는 4/4와 2/4였다. 소수 장면의 결과를 안정적인 성능 우위로 일반화하지 않는다.

## 영상

[78초 비교 영상](../../outputs/recovery-overview-v1.mp4)은 첫 36.5초에 정상 출발, 이후 yaw+횡오차를 보여준다. 네 화면은 정상 ACT·복구 ACT·학생 상태 추가 ACT·정답 상태를 쓰는 복구 교사이며, seed16의 사전 지정된 각 그룹 첫 사례다. 같은 SIM 시간에 맞췄고 녹화가 끝난 화면은 표시와 함께 마지막 프레임을 유지한다. 두 사례 사이에는 SIM 시계가 다시 시작한다. 성공 사례를 골라 묶은 영상이 아니다.

두 seed의 최종 영상 8개와 개발 영상 4개를 모두 보관했다. 원본 위치·해시는 [seed16](videos-seed16.json), [seed17](videos-seed17.json), [개발 영상](videos-development.json)에 있다. 전체 디코딩과 8개 최종 프레임, 시작·중간 및 개요 전환 프레임을 확인했다. 모든 프레임을 실시간 시청했다는 뜻은 아니다. [시각 검토 범위](final-video-qa.json).

## 속도와 실행 비용

이 실험은 기존 “2배 빠른 교사” 설정을 그대로 유지한 속도 실험이 아니다. 복구 교사는 세밀한 정렬을 우선하며 전진 gain 0.3/최소 0.005를 사용한다. 별도 단순 전진 교사는 이전 2배 제어기의 gain 0.4/최소 0.02다. 성공한 장면끼리 맞춰 비교하면 복구 ACT seed16은 평균 17.73 SIM초 대 복구 교사 11.27초, 학생 상태 추가 seed16은 16.25초 대 10.95초, seed17은 18.50초 대 11.50초였다. **속도 개선도 입증되지 않았다.** 전체 성공 집합이 다른 표의 평균을 직접 비교하여 속도 우위를 주장하지 않는다.

조건별 행동 수·벽시계 시간·전체 SIM 시간은 [results.json](results.json), 동일 성공 장면의 속도 비교는 [final-failure-analysis.json](final-failure-analysis.json)에 있다. 외부 모델 API 호출은 0회이며 로컬 CPU를 사용했다. 파지 스킬은 공통 기존 RGB 모델이다.

## 질문과 비교
정상 접근 시연만 배운 정책에 비해, 단일 오류 복구 시연과 학생 방문 상태의 교사 복구 궤적을 배운 정책이 실제 폐루프 실행에서 더 잘 복구하는가? 정답 상태를 쓰는 강한 복구 교사와도 비교한다.

모든 학생은 동일한 upstream ACT(LeRobot 고정 SHA), 128px ImageNet 영상 특징, chunk 4/매번 1행동, 4출력(forward/left/turn/stop), 10,000 업데이트/로봇을 사용한다. 두 학습 seed를 별도로 실행한다. CNN은 고정하고 ACT 부분을 학습한다. 원 논문의 전체 학습 설정 재현이나 실물 로봇 검증은 아니다.

| 조건 | 시연 시도 구성 |
|---|---|
| 정상 ACT | 정상 48 |
| 복구 ACT | 공통 정상 24 + 단일 오류 복구 24 |
| 학생 상태 추가 ACT | 공통 정상 24 + 공통 단일 오류 12 + 학생 상태에서 교사 복구 12 |

세 학생의 시연 생성에는 모두 같은 복구 교사를 사용했다. 정상 시작 상태에서는 이 교사도 전진·정지만 출력했음을 라벨 집계로 확인했다. 별도 비교 조건인 단순 전진 교사는 이전 2배 명령의 x-only 제어기이며, 이번 정상 48개 시연의 생성기를 뜻하지 않는다.

마지막 두 조건은 추가 시연 시도 예산을 맞췄다. 성공/적격 궤적 수와 고유 영상 수가 완전히 같은 비교는 아니므로 데이터 양 차이도 함께 보고한다. 부트스트랩 학생은 정상 24+단일 오류 12, seed 20260916, 5,000 업데이트/로봇으로 만들며 최종 비교 모델에 포함하지 않는다. 마지막 조건도 새 초기화로 동일 예산을 학습한다.

## 입력 경계와 성공 기준
독립 학생은 자기 RGB와 공용 top RGB 두 장만 받는다. 현재 코드에서는 명령 이력도 입력하지 않는다. 교사는 훈련 시연 및 별도 비교 조건에서만 정답 위치·각도를 사용한다. 학생이 연속 3회 두 로봇의 준비 완료를 예측하면 공통 RGB 파지 스킬을 시작한다. 정답 위치·접촉으로 학생 행동이나 파지 시작을 보정하지 않는다.

위치 축별 5mm, yaw 1도, 0.4초 안정 유지(선속도 5mm/s, 각속도 0.02rad/s 이하), 실제 파지/들기, 접근 중 물체 접촉 없음, 실행 오류 없음을 모든 조건에 동일하게 사후 채점한다. 물리 파지 성공과 이 엄격한 전체 성공을 별도로 기록한다. 카메라/FOV/외관은 고정하고 weld는 끈다.

## 데이터 누출 방지
최종 시험은 정상 4, yaw+횡오차 4, 먼 거리+yaw 4, overshoot+yaw 4로 사전 고정했다. 학습용 교사 라벨이 붙은 어떤 프레임이라도 yaw 3도 초과와 (횡오차 8mm 초과, 남은 거리 0.33m 초과, 또는 3mm 넘는 지나침)이 겹치면 해당 궤적 전체를 제외한다. 혼합 오류 교사 파일럿은 학습하지 않는다. 개발 조건으로 체크포인트를 선택하고 최종 시험을 보고 튜닝하지 않는다.

학생 방문 상태 수집은 정답 기반 개입 판정 없이 20/60/100스텝(4/12/20 SIM초)에 고정 개입한다. 교사는 그 시점의 실제 물리 상태에서 리셋 없이 이어받는다. 학생 prefix에는 교사 라벨을 붙이지 않고, 이후 연속 교사 tail만 action chunk로 만든다. 한 번의 tail aggregation 실험이며 모든 학생 상태에 전문가 라벨을 붙이는 완전한 DAgger 구현은 아니다. 모든 prefix가 실패 상태였다고 가정하지 않고 실제 잔여 오차와 이미 정지 선언했는지를 기록한다. 조합 영역과 접촉 기준 때문에 가장 어려운 방문 상태가 제외될 수 있으므로, 이 조건은 제한된 성공 tail aggregation의 효과를 평가하며 전체 실패 분포를 해결했다는 주장을 뒷받침하지 않는다.

## 교사 검증과 구현 진단
첫 교사 파일럿은 6/8이었다. 횡이동 명령의 최소 크기 0.005에서 정지 마찰을 충분히 넘지 못하는 궤적을 확인했고, 이 값만 0.012로 바꿨다. 해당 실패 조건 2개를 다시 실행해 모두 성공한 뒤 전체 파일럿 8/8을 재확인했다. 이후 정상 48/48, 단일 오류 24/24, 개발 12/12 시연을 수집했다. 이는 교사 성공이며 아직 학생 성공의 근거가 아니다.

## 한계
같은 장면·물체·카메라에서 제한된 perturbation 조합을 평가한다. 두 seed는 같은 16개 시작 장면을 반복하며 32개의 독립 장면이 아니다. 강한 교사보다 약한 고정 교사를 이겼다는 사실만으로 교사보다 새로운 능력을 배웠다고 주장하지 않는다. 공통 파지와 두 로봇 준비 완료 게이트는 기존 구조이며 학습된 협상/통신/운반 동기화가 아니다. 시뮬레이션 시간과 행동 수를 주로 비교하고, CPU 동시 학습 등의 영향을 받는 벽시계 시간은 별도 보고한다.

## 최종 시험 전 개발 점검

seed 20260916, 학습 및 체크포인트 선택에 쓰인 개발 분포의 고정 4개 사례를 독립 실행했다. 교사 개입 없이 정상 ACT 0/4, 복구 ACT 2/4(정상·지나침), 학생 상태 추가 ACT 3/4(정상·횡오차·지나침)였다. 세 모델 모두 yaw 사례는 실패했다. 이는 개발 점검이지 최종 조합 일반화 결과가 아니다.

로봇당 학습 영상은 정상 2,693장, 복구 2,984장, 학생 상태 추가 2,518장이다. 추가 수집 12회 중 yaw 3회는 교사 구간 접촉 및 미학습 조합 영역 침범으로 제외됐다. 남은 9개의 교사 tail은 로봇당 333프레임이고, 2개 prefix에서는 학생이 이미 준비 완료를 선언했다. 훈련 수집에서는 예정된 개입 시점까지 접근 루프를 계속하므로, 이 2개를 자율 실행의 실패 사례로 부르지 않는다. 어려운 yaw 방문 상태가 제거되어 데이터 구성도 단순 추가와 다르다.

횡오차 실패에서 남은 거리 약 11mm, 전진 명령 0.0046의 저속 정체를 관찰했다. 고정 최소 명령/작은 출력 제거 후보를 가중치·준비 완료 판정 변경 없이 별도로 시험했다. 정상 ACT는 0/4→1/4, 복구 ACT는 2/4→1/4로 합계 2/8이 같고 기존 복구 모델의 정상 성공이 사라졌다. 사전에 정한 ‘전체 성공 증가 및 기존 복구 성공 유지’ 기준에 따라 후보를 기각했고 모든 최종 학생은 원래 명령 변환을 유지한다. 이 진단을 학습된 복구 능력으로 집계하지 않는다.

최종 비교의 정상 ACT는 이번 실험의 동일한 4출력 구조와 이번 교사 데이터로 다시 학습한 기준 모델이다. 이전 2출력 빠른 ACT와 동일한 모델이 아니며, 이전 속도 실험의 성공률과 직접 이어 붙이지 않는다. 이번 실험의 우선 질문은 복구 데이터의 효과이고, 속도는 성공 여부와 함께 별도로 보고한다.

체크포인트는 모든 모델에서 10,000 업데이트를 수행한 뒤 동일한 개발 점수(정지 누락률 + 조기 정지율×10 + 정규화 행동 오차)로 선택했다. 따라서 실제 배포 체크포인트는 중간 단계일 수 있다. 정상 기준 모델의 r3는 seed16에서 2,000, seed17에서 1,000 단계가 선택됐다. 복합 오차를 포함한 개발 분포에서 조기 정지를 크게 벌점 주는 선택 규칙이, 보정을 배우지 않은 기준 모델에서는 정지를 거의 하지 않는 보수적인 모델을 고를 수 있다. 이 선택 절차도 결과의 일부이며, 현재 기준 모델의 실패를 ‘정상 ACT가 정상 주행을 배울 수 없다’는 근거로 삼지 않는다. 이전 빠른 ACT와의 직접 비교가 아닌 이번 데이터·구조·선택 절차 내 비교로 해석한다. 모든 선택 단계와 원본 점수는 training-summary에 기록한다.

최종 결과의 사후 진단에서 recovery17의 정상 사례 nominal-02/03/04는 공통 위치·각도·안정성 기준을 만족했지만 준비 완료를 선언하지 않아 파지를 시작하지 못했다. 마지막 r1 정지 점수는 각각 0, 0, 약 0.070이었다. 이때 예측 이동 명령도 매우 작았다. 따라서 이 세 실패는 단순히 아직 목표에 못 갔기 때문이라고 설명할 수 없고, 정지 표적/영상 표현/폐루프 분포를 포함한 완료 판단의 문제를 별도로 봐야 한다. 정답 위치를 이용해 대신 파지를 시작시키는 보정은 하지 않았다. 이 관찰만으로 해상도나 특정 구조가 원인이라고 확정하지 않는다.

이 최종 시험 결과를 보고 바꾸는 후속 학습·튜닝은 새 시험 분할로 평가해야 한다. 같은 16개 조건을 다시 사용한다면 이미 확인한 회귀 시험으로 표시하고 새로운 일반화 검증으로 부르지 않는다.

## 후속 실험의 우선순위

현재 결과에 근거하면 먼저 완료 판단을 분리 진단해야 한다. 이미 정렬했으나 정지를 선언하지 않는 상태와 아직 정렬하지 않았으나 선언하는 상태를 모두 포함해 RGB 기반 정지 표적과 개발 점수의 선택 편향을 점검한다. 다음으로 학생이 실제 방문하는 yaw 실패 상태의 안전한 복구 시연을 확보해야 한다. 이번에는 가장 어려운 yaw tail 3개가 모두 제외되어 그 효과를 시험하지 못했다.

새 데이터 수집 전에 학습/시험의 조합 정의를 다시 고정한다. 조합 라벨 누출을 막으면서 어려운 상태를 충분히 포함할 수 없는 경우, 단일 오류 학습→조합 일반화와 복합 오류 학습→새 강도/새 장면 일반화를 별도 질문으로 평가한다. 수정 후에는 새 holdout을 사용하고, 이번 16개는 회귀 시험으로만 사용한다. 현재 결과만으로 ACT 구조 자체의 가능성이 없다고 단정하거나 학습 시간만 늘리면 해결된다고 가정하지 않는다.
