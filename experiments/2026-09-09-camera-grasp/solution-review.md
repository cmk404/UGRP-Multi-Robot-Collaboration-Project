# 카메라만 사용하는 파지: 해결방안 검토

2026-09-09. 요청: 실패 원인을 검토하고 해결방안을 찾기. 이번 작업은 코드·보존 입력·연구 자료 검토이며 새 제어 구현이나 추가 모델 실험은 하지 않았다.

## 확인된 사실과 미확정 원인

기준 실행 SHA `15db9f58f65eb3ba7289e7ec7c90402a851d7833`, seed 11, 각 로봇 30회 판단. 실제 요청 60건의 입력 경계 검증 통과. 결과는 README.md, summary.json, result.json, input-audit.json에 보존했다.

- 총 60회 중 48회는 집게 열기였다. 닫기와 서보 3/4/5 조절은 없었다. 따라서 이번 실패는 집은 뒤 미끄러짐보다 집기 동작에 진입하지 못한 문제다.
- 정책은 매번 고정 설명과 현재 자기/상단 이미지로 요청을 새로 만든다 (`harness/camera_pair_policy.py`, `decide`). 직전 명령을 전달하지 않는다. 이것은 확인된 설계 특성이지만 기억 부족이 실패 원인이라고 확정할 A/B 실험은 없다.
- 보존한 8번째 자기 영상에서는 집게 손가락을 식별하기 어렵고 상단에서는 매우 작다. 반복 열기 구간에 원본 이미지 해시가 동일한 사례도 있다. 시각적 피드백 부족 가설을 지지하지만 전체 원인으로 확정하지 않는다.
- 응답에서 r3가 자신을 상단/하단 로봇으로 번갈아 지칭한다. 정체성 혼동은 관측됐으나 영향은 별도 비교가 필요하다.
- 실행기는 물리 진행 전 같은 시점의 영상을 수집하고 두 명령을 적용한다. 현재 증거로 동기화 구현 결함을 지목할 수 없다.

## 우선 실행할 비교

각 비교는 한 변수만 바꾸고 모델·seed·행동 예산·물리·weld OFF를 고정한다. 실행 소스를 먼저 커밋하고 SHA와 결과를 연결한다. 초기 선별은 조건별 10회 판단으로 반복 행동과 관측 가능성을 비교하고, 유망 후보를 기존 30회 예산과 여러 seed에서 재검증한다. 선별 실험에서 반복이 줄어드는 것만으로 파지 성공이라고 보고하지 않는다.

1. **집게가 보이는 자기 시야.** 카메라 장착 위치/프레이밍만 바꿔 양쪽 손가락과 물체가 같이 보이도록 한다. 고정 fixture에서 열림/닫힘 이미지가 실제로 구분되는지 먼저 확인한다. 진단용 개폐는 작업 성공 시험에 포함하지 않는다. 관측은 여전히 자기 카메라와 상단 카메라 두 장이며 정답 위치에 따른 자동 crop이나 overlay를 쓰지 않는다.
2. **정적 작업 설명 개선.** 별도 조건에서 “집게가 이미 열려 있을 수 있다. 시각적으로 물체를 감싸도록 팔을 조절한 뒤 닫는다”라는 단계 설명을 추가한다. 이력이 없으므로 모델이 과거 반복을 알고 있다고 가정하지 않는다. 좌표, 미리 정한 파지 자세, 평가 기반 단계 전환은 넣지 않는다.
3. **영상에서 로봇 구별.** 필요하면 로봇/집게에 실제로 렌더되는 서로 다른 색·형태 표식을 붙여 자기 영상과 상단 영상의 연관을 돕는다. 물체 손잡이나 정답 좌표 라벨을 추가하는 것이 아니다. 현재 무표식 기준과 별도 조건으로 보고한다.

지표: 동일 명령의 연속 길이, 최초 팔 조절/닫기 시점, 시각적 정체성 판단 일관성, 파지 성공률, 소요 SIM 시간·행동 수·토큰 사용량. 성공은 기존처럼 양 로봇 bilateral 접촉 + 3cm 상승 + weld OFF가 2초 유지되는 것으로 출력 평가만 한다. 판정값은 모델과 제어기에 돌려주지 않는다.

## 다음 단계의 구조적 대안

추천 방향은 상위 모델의 단계 판단과 이미지 기반 미세 제어를 나누는 것이다. 이미지에서 보이는 집게와 물체의 간격/정렬 오차를 줄이도록 작게 움직이고 다시 관측한다. 이는 제안이며 현재 구현되거나 성공이 검증된 기능이 아니다. 영상의 픽셀 위치는 시뮬레이터의 정답 XYZ와 다르지만, 사용자에게 이 구분을 명시해야 한다. 영상 특징 추적과 동작-영상 변화 관계의 보정이 필요하고, 깊이·가림·시야 이탈 문제도 남는다. 기존 정답 좌표 매크로를 이 이름으로 재사용하지 않는다.

행동 기억 비교도 가치가 있다. 직전 **자기가 발행한 명령**만 보존하는 것은 센서의 실제 관절 상태나 동작 성공을 아는 것과 다르다. 다만 현재 시험은 명시적으로 stateless이므로 그 조건을 바꾸는 별도 후보로 다룬다. 기억만 추가하면 해결된다는 결론은 내리지 않는다.

OpenVLA 등 로봇 행동을 학습한 모델은 장기 대안이지만 MasterPi에 곧바로 적용된다는 근거가 없다. 로봇별 행동 표현과 데이터 적응이 필요하므로 단순 모델 교체를 첫 해결책으로 삼지 않는다. 퇴역한 클라우드 GPU 환경은 재개하지 않는다.

## 연구 근거와 적용 한계

- [Hutchinson: Visual Servo Control](https://faculty.cc.gatech.edu/~seth/res.php?u=vs): 영상 특징의 오차를 이용하는 제어와 위치 기반 제어를 구분하며, 3D 장면 복원 없이 영상에서 측정되는 양으로 제어하는 연구를 소개한다. 카메라만 사용하는 제어 방향의 근거이지 이 MasterPi 파지의 성공 증명은 아니다.
- [OpenVLA 공식 연구 페이지](https://openvla.github.io/): 97만 로봇 에피소드로 행동을 학습하고 새로운 로봇 설정에 fine-tuning하는 접근을 설명한다. 범용 VLM에 raw PWM을 요청하는 현재 정책과 로봇 행동 학습 정책을 구분할 근거다.
- [Inner Monologue, CoRL/PMLR](https://proceedings.mlr.press/v205/huang23c.html): 피드백을 언어 계획에 통합하는 접근을 실험한다. 이 연구의 성공/장면 피드백을 현재 영상 전용 계약에 그대로 넣을 수 없으며, 기억만의 효과를 입증하는 자료로 사용하지 않는다.

검증 범위: 기존 실행 로그와 정책/실행기/포트 코드, 대표 입력의 시각 검토 및 원본 해시, 공식 연구 자료. 새 실험·제어 코드 변경 없음. 전체 raw 영상/요청은 기존 로컬 위치에 보존하며 원격 백업으로 주장하지 않는다.
