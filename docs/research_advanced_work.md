## 담당과 완료 기준

### A2 · 협상·복구 시나리오와 독립 검증

- 실제 현재 RGB/명령/수신 보고에서 확인 가능한 사건을 사용해 정상, 중복 작업/통로 경쟁, 실행 정체 후 도움 요청·재할당의 세 종류를 만든다. 공용 top 영상에 보이는 사건을 한 로봇만 아는 사건으로 부르지 않는다.
- 실패→자기 증거 인식→보고/침묵→역할 또는 계획 수정→명령 변경을 같은 event/decision ID로 검사한다. 메시지가 그럴듯하다는 평가만으로 효과를 인정하지 않는다.
- B2/C2/D2의 실제 serializer, 요청, 예약·깨우기, 완료 주장과 evaluator 분리를 독립 검사한다. 기존 코드의 결함 재현 테스트와 수정된 경로의 회귀 테스트를 분리한다.
- 동료 지연·중단, stale intent, 역할 충돌, 중복 요청, 재협상 중 취소 등 반례를 executable scenario와 검증기로 제공한다. 물리 이벤트 주입과 actor가 실제 관측한 사실을 따로 기록한다.
- 일반화/인과 주장은 작은 연결 파일럿과 분리한다. 이후 paired repeated trials와 메시지 제한/지연 제거 실험의 고정 조건·분석 기준을 준비한다. 전체 상태 복원 없이 메시지 차단 사례를 인과 효과라고 부르지 않는다.

소유: 새 `harness/rgb_communication_scenarios.py`, 대응 tests/fixture, `docs/research_parallel/a2-*`. B/C/D production 코드는 직접 수정하지 않는다.

### B2 · 실제 RGB 운동 스킬·동시 작업·회복 연결

- 기존 `CameraRobotPort`, `TaskStageExecution`, `BoundPairSkill`, `SoloBoxTransport`의 실제 사용 가능 경계를 확인하고 공통 포트에 연결한다. endpoint stub에서 멈추지 않는다.
- 고수준 선택은 각 LLM에 남기고, 선택된 단독/공동 작업을 허용 RGB 기반 접근·파지·운반·방출 스킬로 수행한다. 숨은 full-plan 생성, 고정 역할 배정, 정답 보정은 금지한다.
- 작업자 중 한 로봇의 무거운 스킬 호출이 다른 로봇의 진행을 막지 않도록 명시적 tick/수명·취소·만료 계약을 만든다. 한 simulator clock의 소유자를 정하고 각 worker가 같은 물리를 중복 step하지 않는다.
- RGB 기반 단계/완료 주장과 독립 물리 평가를 연결하되 분리한다. 정지·재개·도움 요청·새 임무 인계에서 기존 lease/명령이 남지 않는지 검사한다.
- 최소 단독+공동 운반 2회 deterministic replay를 실제 물리 backend로 검증할 수 있는 진입점을 제공한다. 실패와 미지원 조건을 숨기지 않는다. 해당 replay는 통신 효과 결과가 아니다.

소유: 기존 B 포트/계약의 후속 변경, 새 `harness/rgb_skill_execution.py`, 대응 tests/fixture, `docs/research_parallel/b2-*`. 기존 ACT/학습/출하 스크립트는 별도 담당과 충돌을 확인한 최소 수정만 한다.

### C2 · 실제 LLM·비동기 판단·실행 중 재협상

- 기존 프로젝트 모델 연결을 재사용해 자기 RGB·공용 top RGB·자기 명령/기억·허용 수신 보고를 실제 요청으로 직렬화하는 planner를 연결한다. 개발 담당의 Astra 설정을 로봇 실험 모델 선택으로 혼동하지 않는다.
- 순차 round-robin과 별도로 로봇별 한 개의 in-flight 판단을 허용하는 비동기 실행을 구현한다. 느린/실패한 동료 호출이 다른 로봇과 simulator clock을 막지 않게 한다.
- 관측/명령/동의 revision을 답변과 연결하고 늦은 답·중복 답·계획 변경 뒤 답·만료 보고를 실행 전에 거절한다. 무통신에서도 같은 스킬·동의·실행 가능성을 유지한다.
- 고정 계획에 한 번 합의하고 끝내지 않고, 도움 요청·거절/수락·계획 철회·파트너 변경·재할당을 각 agent의 선택으로 실행 중 처리한다. coordinator가 협상 결과를 대신 결정하면 안 된다.
- 호출/입출력 토큰/동시 요청/메시지 비용의 실제 상한을 연결한다. 제공자가 usage를 안 주거나 상한을 강제할 수 없으면 미측정과 실행 제한을 명시한다.

소유: 기존 C runtime, 새 `harness/rgb_communication_planner.py` 등 C 전용 모듈/테스트, `docs/research_parallel/c2-*`. B 포트 API 변경은 B와 합의한다. 최상위 실험 runner는 D 소유다.

### D2 · 통합 runner·단일 제출·분석·대시보드 연결

- B2/C2/A2를 실제로 조립하는 하나의 CLI/runner를 만든다. manifest 생성만으로 완료하지 않는다. API 계약·실제 backend capability·SHA/입력 해시·상한을 검사하고 미연결이면 fail closed한다.
- 정상·실패·오류·중단·미실행을 같은 분모에 남기고, actor finish 주장과 사후 mission success를 구분한다. runtime 종료 분류와 evaluator verdict가 충돌하는 경우 두 원본을 보존하며 뜻을 명시한다.
- 시행·코호트 전체 예산을 실제 제출/실행 경계에서 강제한다. 자동 무제한 재시도 없이 단일 제출자와 원본 회수/hash 검증을 제공한다.
- 로봇별 작업 겹침, 대기·교착, 협상 후 결정 변경, 복구 도달/완주, 메시지·모델·명령 비용을 함께 보고한다. 통신 조건과 scheduler/제어기를 동시에 바꾸지 않고 통신 주 비교와 비동기 실행 후속 비교를 나눈다.
- 새 결과용 TensorBoard adapter와 원자료 대응 검사를 구현한다. synthetic fixture는 테스트용 임시 logdir에서만 검사하고 실제 기본 대시보드 결과로 등록하지 않는다.

소유: D evaluator, 새 `scripts/run_rgb_communication_study.py`, `harness/rgb_communication_study.py`, TensorBoard exporter의 필요한 작은 adapter와 대응 tests, `docs/research_parallel/d2-*`.

## 실제 검증의 단계와 자원 경계

1. 통합 SHA에서 A/B/C/D 단위·계약 검사를 함께 실행하고 공용 CI 목록에 등록한다. 통합 담당이 공용 CI와 최종 PR 구성을 소유한다.
2. 실제 스킬 adapter가 준비되면 D 단일 제출자가 **외부 모델 0회인 물리 replay 2회**를 기본 Colab CLI에서 실행·회수한다. 회당 SIM 180초·wall 600초, 작업 전체 1,800초(설치/회수 포함) 상한이다. 자원/인증이 없거나 시간에 맞지 않으면 사실대로 중단하고 임의 Mac 대체·유료 구매·다른 세션 재시작을 하지 않는다.
3. 실제 모델 smoke/6회 파일럿은 위 물리 검증, A의 관측·정보 경계 확인, C의 현재 사용 가능한 기존 endpoint/모델·강제 예산, D manifest가 갖춰진 뒤에만 진행한다. 새로운 유료 provider나 공개 endpoint를 만들지 않는다. 비용 조건/접근 권한이 추가로 필요하면 사용자에게 정확한 선택을 요청한다.
4. 파일럿의 2×3은 연결 검사다. 사건에 도달하지 못한 물리 실패도 남긴다. 반복 수·시험 맵·최소 의미 있는 효과·분석법을 고정한 본실험 없이 통신 우열을 결론 내리지 않는다.
5. 새 실제 결과는 성공/실패 모두 원본을 보존하고 `experiments/<ID>/` 기록·TensorBoard 변환/로딩/화면 확인까지 한다. 코드 테스트 통과를 물리 성공으로 보고하지 않는다.

물리·모델 작업은 D 한 명만 제출한다. A/B/C는 필요한 진단 명령과 자료를 D에게 넘긴다. 기존 ACT 학습/검증과 로컬 시뮬레이션 뷰어 작업은 건드리지 않는다. 별도 세션을 추가하지 않고 기존 A/B/C/D 세션을 Astra/xhigh로 이어간다. main 병합은 여전히 해당 PR에 대한 사용자 명시 승인 뒤에만 한다.
