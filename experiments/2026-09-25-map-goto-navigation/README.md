# 2026-09-25 목적지 선택 + 지도 A* 이동 (`--navigation planned`)

PR #148. 사용자 요청: 로봇이 매 단계 조금씩 "운전하듯" 움직이는 대신, LLM이 목적지를 정하면 A* 같은 경로 계획으로 알아서 이동한다.

## 무엇을 바꿨나

- 기본값 `authored`: 모델이 dock과 상자의 north/south 통로를 고르고, 상자 로봇은 그 통로의 저작 경유점을 0.2초 명령으로 RGB 추적한다.
- `planned`(기본 OFF, 실행 번들 v55): 모델은 상자 목적지(dock)와 하역 뒤 대기 위치 `park`(region 이름 또는 `{"xy_m":[x,y]}`)만 정한다. 상자 로봇의 적재 경로(현재 TOP RGB 화물 위치 → dock)와 대기 이동(RGB 바퀴 형상 위치 → park)은 정적 지도 격자 A*가 계획한다. 빔은 합의 통로를 유지한다. 구현은 `harness/map_goto.py`, `harness/dispatch_goto.py`.
- 실행 전 가능성 검사가 경로 없음·막는 park를 이유와 함께 모델에 돌려준다. 정답 좌표·접촉·성공 신호는 제어에 쓰지 않는다.

## 후보(v48) 실패와 수정

첫 후보(`9fd4ed0`, 당시 v48로 등록)의 두 재생이 모두 실패했다. 이 번호는 병합 순서상 #146의 v48과 충돌해, 사용한 바이트를 `retired-bundle/map-goto-candidate-v48.json`(sha256 `5f6c100b…`)에 보존하고 수정본을 v55로 등록했다.

1. **R-beam-first**: A* 경로가 TOP 카메라 바로 아래(0.52, −2.05)를 지나며 자기 집게가 청록 상자를 가렸다. 이후 480결정 중 90%를 특징점 추적으로 이동했고, 부풀려진 화물 외곽이 슬롯 포함 판정에서 0.33 px 밖·오차 0.3 px < 허용 0.5 px의 교착에 빠져 결정 예산을 소진했다. → 화물 추적점이 카메라 직하 0.5 m 정사각형을 지나지 않게 했다.
2. **R-box-first**: 서쪽에서 슬롯에 진입했다. 들린 화물은 카메라에서 약 4 cm 더 먼 곳에 보이므로 영상상 포함 판정 직후 방출된 상자가 실제로는 슬롯 서쪽 경계 9 mm 밖이었다. → 기존 경로처럼 항상 동쪽 대기점을 거쳐 직선 도킹한다.
3. **R-box-first**: park 최종 허용 1.2 cm에서 명령 해상도 때문에 50 SIM초 진동해 400결정 예산을 소진했다. → 허용 2 cm, 근접 이득 절반.

## 해석과 범위

- 조건당 1회다. 성공률·시간 차이를 통계적 우열로 해석하지 않는다.
- 빔 먼저: A*는 도착한 빔 팀 금지 영역과 카메라 직하 영역을 피해 north로 우회했고 운반 시간은 기존과 거의 같다.
- 상자 먼저: A*는 south 통로로 내려가는 저작 우회 대신 직선으로 가 상자 운반 SIM 시간이 48.3 → 26.4초였다. 전체 임무 시간 차(216.1 → 199.3초)에는 park 위치 차이가 섞여 있다.
- 금지 영역(빔 팀 envelope, 카메라 직하 크기)은 보수적 저작 값이다. 다른 지도 변형(shared_crossing, narrow_south, rough_south, north_blocked)의 물리 실행, 실제 LLM이 목적지·park를 고르는 실행, 빔의 A* 경로, realtime·경로 겹침·동적 협업과의 결합은 검증하지 않았다.
- 지도 경로 계산은 물리 통과의 증거가 아니다. 성공 판정은 사후 평가(`evaluation-only.json`)이며 제어 입력이 아니다.
