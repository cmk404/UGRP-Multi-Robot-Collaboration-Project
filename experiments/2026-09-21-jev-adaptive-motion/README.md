# Jev/Gemini RGB short-skill comparison

## 사전 고정 설계

목적은 기존 70회 고정 모터 선택 실험에서 섞여 있던 관측 오류, 행동 해상도, 반복 요청, 질문 구성, confidence 사용, 추론 중 시간 정지를 분리해 비교하는 것이다. 범위는 로봇 한 대의 RGB 접근·우회·일시 가림 복구이며, 파지·운반·다중 로봇 협력 성공을 뜻하지 않는다.

- 입력: 자기/공용 TOP RGB, 자기 발행 명령, 정적 지도와 고정 카메라 보정. RGB 좌표 추정과 경로 후보 생성은 공통 코드가 수행한다. 모델에는 명시적 allowlist의 의미 상태와 후보 효과를 제공한다.
- 모델: Jev 1.13.0, Gemini 3.8 Flash. 같은 상태·질문·후보를 제공하되 Jev는 native Choice API, Gemini는 JSON 응답을 사용한다. Gemini의 confidence를 임의 생성하지 않는다.
- 공통 실행: 모델은 짧은 스킬을 선택하고 RGB 로컬 피드백이 선택한 스킬만 실행한다. 지도/RGB로 후보를 제한하며, 가림·충돌 경로·목표 안정화에 대한 공통 정지는 별도 기록한다. rule baseline도 같은 관측·후보·실행기를 사용한다.
- 목표: 제어는 RGB 거리 0.27–0.28 m, 각도 ±3°, 안정 관측 3회. 별도 물리 평가는 기존 거리 0.26–0.30 m, 각도 ±6°, 0.35 SIM초 유지, 접촉 0, weld 0, 카메라 불변을 요구한다. 평가 좌표/접촉/환경 이벤트 시간표는 제어에 전달하지 않는다.
- 시간: 0.25 SIM초 관측, 최대 6 tick 스킬 유지, 의미 변화/후보 변화/정체/종료 시 재질의. Jev action confidence <0.45는 유지 길이만 2 tick으로 줄인다. 이 문턱은 개발용 고정값이며 확률 보정이나 안전 보증이 아니다.
- 한도: trial당 90 SIM초, 1,200 벽시계초, 400 모델 요청, 1,000,000 입력 토큰. 모든 조건 동일한 물리 시간과 충분한 요청 한도를 사용하고 한도 종료도 실패로 보존한다.

## 코호트

`run_jev_skill_motion.py`의 DEVELOPMENT 6개만 수정·진단에 사용한다. HOLDOUT 12개는 본 시험 전에 고정하며, 본 결과를 본 뒤 후보를 수정해 같은 조건의 결과를 최종 독립 시험이라고 부르지 않는다. `run_jev_skill_cohort.py`는 seed 210922로 열거한 trial을 섞어 4 worker에 배정한다.

| 구분 | 조건 | 횟수 |
|---|---|---:|
| 새 조건 | open, yaw, known barrier, unknown barrier, physical target cover, temporary barrier 각각 2배치 × 3 API 반복 × rule/Jev/Gemini | 108 |
| 회귀 | 앞선 비교의 시작 자세 12개 × rule/Jev/Gemini | 36 |
| 고정 모터 행동 | open01/02, yaw01/02 × 2 반복 × Jev/Gemini | 16 |
| 매 관측 질의 | open01/02, yaw01/02, unknown01, occluded01, temporary01 × 2 반복 × Jev/Gemini | 28 |
| action 질문만 | 같은 4개 × 2 반복 × Jev/Gemini; Jev confidence 유지 | 16 |
| confidence 무시 | 같은 4개 × 2 반복 × Jev; 질문 분해 유지 | 8 |
| 연속 시간 | open01, known01, occluded01, temporary01 × 2 반복 × Jev/Gemini | 16 |
| 합계 | 개발 진단 제외 | 228 |

연속 시간 조건은 API 대기 중 physics/RGB를 계속 갱신하되 만료된 스킬을 제동한다. 4 SIM초보다 오래됐거나 의미 상태/후보가 바뀐 응답은 버린다. 계속 움직이는 비동기 제어를 검증했다는 뜻은 아니다. 공유 Mac의 동시 실행 때문에 벽시계는 독립 장비 지연 측정이 아니며 API 자체 지연도 함께 보고한다.

고정 모터 행동과 스킬 행동은 동일한 매 관측 질의 조건(open01/02, yaw01/02)에서 직접 비교한다. 호출 빈도의 효과는 full과 always의 같은 배치·반복을 맞춰 비교한다. 초기 216회 안에서 두 효과가 섞이는 것을 방지하려고 본 시험 전 always 12회를 추가했다.

## 분석 원칙

- 모든 열거된 실행과 실패를 포함하고 자동 재시도/유리한 trial 선별을 하지 않는다. 같은 물리 배치의 API 3회 반복을 독립 지도 3개로 세지 않는다.
- 전체·조건별 성공, SIM/벽시계 시간, 호출·입출력 토큰, 접촉, 종료 이유, 선택지 수와 공통 개입을 함께 보고한다. 실제 과금 내역이 없으면 비용은 `null`로 남긴다.
- 저장 RGB 재생, 이미지 해시, 실제 요청 allowlist/응답, 평가 재계산, 영상 디코딩과 대표 영상 시각 확인을 구분한다. 모델이 선택한 부분과 로컬 제어가 수행한 부분을 분리한다.
- raw는 `/Users/changmin/projects/ugrp/outputs/`의 로컬 자료이며 원격 백업이 아니다. 키를 결과·명령 인수·환경 파일·Git에 기록하지 않는다.
