## 1. 연구 목표와 판단 기준

**중앙의 역할·임무 계획자 없이 동등하고 독립적인 세 로봇 LLM 에이전트가 통신할 때, 자율적 역할 분담·협력 이송·예외 복구에 어떤 효과가 생기며 그 이득이 시간·통신 비용을 상쇄하는지 검증한다.**

주 질문은 명시적인 고수준 통신의 효과이며, 부 질문은 정형 메시지에 비해 자유로운 자연어가 더 도움이 되는 조건이다. 통신이 불필요하거나 오히려 성능을 낮추는 조건도 결과로 남긴다. 근거는 [통신 연구 설계](coela_communication_study.md), [역할·관측 계약](warehouse_research_contract.md), [연구 배경](research_brief_20260813.md)이다. 과거 문서의 RGB-D·ideal-SIM·weld·운영 설정은 현재 [AGENTS.md](../AGENTS.md)를 대체하지 않는다.

ACT·RGB 스킬은 결정한 작업을 수행하는 실행 수단, Jev·Gemini는 모델 후보, 맵·물건 수는 협업 조건의 변화 축이다. ACT의 최고 성능 달성이나 모든 맵 완주는 통신 본실험의 선행 조건으로 두지 않는다. 통신 효과를 측정할 수 있는 지원 범위를 먼저 고정한다.

### P0 · R0. 연구 질문·실험 단위·코드 기준 고정

- [ ] 주 결과를 **전체 임무 완료율**, 보조 결과를 완료 시간·복구·통신/추론 비용으로 정한다. 무엇을 의미 있는 차이로 볼지 파일럿 뒤 본실험 전에 수치로 고정한다.
- [ ] 첫 범위는 세 로봇·공동 봉 1개+단독 상자 1개처럼 현재 실행기가 지원하는 작은 임무로 정한다. 출발점·ID·역할은 교차 배정하고, 특정 로봇의 고정 역할을 일반 역할 분담으로 보고하지 않는다.
- [ ] 원래 계획의 규칙 기반·중앙 계획 기준선도 별도 비교로 범위를 정한다. A/B/C는 통신 효과를 분리하는 비교이며, 이것만으로 규칙 기반·중앙 시스템보다 우수하다고 결론 내리지 않는다.
- [ ] main/작업 브랜치/실행 SHA, 모델·보정 파일·물리·지도·카메라 해시를 한 manifest로 연결한다. #89/#91/#92의 필요한 변경, 종속성, 검증·승인·병합 상태를 적는다.
- [ ] 기존 코호트를 통신 비교 / 운동·모델 비교 / 개발·인프라 진단으로 목록화하고, 다음 본실험에 사용할 수 있는 증거를 지정한다. 진행 중 작업은 소유자·종료 조건을 확인한 뒤 별도로 정리한다.

완료 증거: 연구 질문, A/B/C 정의, 실행 범위, 코드·모델 기준, 필요한 산출물과 미확정 수치가 담긴 프로토콜. 설계 문서 작성만으로 실행 완료 표시를 하지 않는다.

### P0 · R1. 로봇별 정보와 통신 경계 감사

- [ ] 각 로봇에 들어가는 자기 RGB·공용 top RGB·자기 명령/기억·정적 지도/과제·실제 수신 메시지를 필드별로 열거하고 출처·시각을 기록한다. 평가 정답·접촉·측정 관절은 제어와 완료 통보에 넣지 않는다.
- [ ] 프롬프트뿐 아니라 기억 갱신, 재판단을 깨우는 조건, 완료 목록, 예약 거부, 경로 후보, 중앙 계획 사본을 검사한다. 관측하지 않은 동료의 비공개 상태만 바꿨을 때 자기 입력·깨우기가 달라지지 않아야 한다.
- [ ] 공용 top RGB로 이미 보이는 장애물·위치를 비공개 정보라고 가정하지 않는다. 실제 관측과 최근 자기 명령·의도·기억에서 정보 차이가 생기는지 저장 입력으로 확인한다. 통신 효과를 키우려고 카메라/FOV를 바꾸지 않는다.
- [ ] 무통신에서도 공동 동작의 최소 시작·정지·허가 동기화는 유지한다. 역할표·의도·동료 관측을 ACK·계획 hash·공유 메모리·예약 응답에 실어 우회 전달하지 않는다. 공통 동기화가 공개하는 최소 정보는 모든 조건에 명시한다.

완료 증거: 로봇×정보 채널 표, 실제 모델 요청 표본, 비공개 상태 변경·수신자 격리·오래된 메시지·무통신 검사. 기존 CoELA 테스트를 현재 RGB 경로에서 다시 적용한다.

### P0 · R2. 비교군이 공통으로 사용할 운동 능력 확보

- [ ] 기존 RGB 스킬 중 지원 조건이 확인된 접근→파지→들기→운반→내리기→RGB 완료 확인 경로를 선정한다. 교사/평가 정답 보정 없이 카메라와 weld OFF를 유지한다.
- [ ] 로봇별 작업/명령 큐와 기억을 격리하고, 공동 동작 참여자만 필요한 동기화를 한다. 독립 작업의 진행을 전원 장벽이나 화물 전체 예약으로 불필요하게 직렬화하지 않는다.
- [ ] 고정 계획 재생으로 단독·공동 운반, 하중을 든 정지/재개, 자원 충돌, 통신 만료를 먼저 검사한다. 이는 실행기 진단이며 역할 협상 결과로 세지 않는다.
- [ ] 모든 정책이 접근에서 멈추면 접근 병목부터 해결한다. 전체 실패는 보존하고, 운반에 진입하지 않은 시행으로 ACT 운반 품질을 판정하지 않는다. 제어기 전체를 다시 만들기보다 첫 연구 범위를 줄여 지원 가능한 경로를 확정한다.

완료 증거: 선정 조건에서 물건별 단계·명령·RGB·사후 성공 판정이 연결된 실행 기록, 지원/미지원 조건 목록, 동일 실행기를 A/B/C에 제공할 고정 버전. 물리 작업 실패가 전부를 가려 통신 효과를 측정할 수 없으면 아직 통과하지 못한 것이다.

### P1 · R3. 같은 실행기에 무통신·정형·자연어 조건 연결

| 조건 | 달라지는 항목 | 공통으로 유지할 항목 |
|---|---|---|
| A · 무통신 | 명시적 고수준 peer 메시지 없음 | 로봇별 독립 LLM·기억/계획 방식·허용 관측·운동 스킬·최소 동기화·평가 |
| B · 정형 통신 | 관측 보고·의도·도움 요청·수락/거절 등의 제한된 스키마 | 같은 모델·환경·과제·의사결정/실행 예산 |
| C · 자연어 통신 | 자유로운 문장으로 같은 종류의 보고·협상 | 같은 수신자 선택권·전달 규칙, 사전 선언한 메시지/토큰 예산 |

- [ ] `coela_modules.py`/`coela_runtime.py`의 경계를 재사용해 현재 RGB 실행 포트를 연결한다. `evaluate_coela.py`를 그대로 실행하는 것이 현재 관측 규칙 준수를 뜻하지 않으므로 구체적인 연결 지점을 지정한다.
- [ ] 화물·파트너·역할·작업 순서·대기/재개/재계획을 로봇별 LLM의 선택과 연결한다. 검증기는 형식·유효기간·충돌/점유를 검사하며, 유효하지 않은 선택을 성공 계획으로 자동 수정하지 않는다.
- [ ] A가 메시지나 상대 계획을 받지 않고도 합법적인 행동·공동 동작 요청을 낼 수 있게 한다. 자연어 합의 성공을 모든 조건의 실행 전제에 두어 A만 시작 불가능하게 만들지 않는다.
- [ ] 관측→기억→송수신→계획→선택→명령→물리 결과를 동일 ID로 추적한다. 공통 실행기의 개입, 침묵, 거절, 교착, 잘못된 역할 선택, 불필요한 반복 대기를 기록한다.

완료 증거: 같은 초기 조건에서 A/B/C 모두 실제 독립 모델 요청과 물리 명령을 생성하고, 메시지 허용 범위만 설계대로 달라지는 통합 검사. 조건 간 결과가 같아도 통과할 수 있다. 규칙 기준선은 추가 비교이며 A/B/C 중 한 조건을 대체하지 않는다.

### P1 · R4. 작은 파일럿으로 시나리오·예산 결정

- [ ] 첫 연결 검사는 **정상 1조건 + 관측으로 확인한 정보 차이/복구 1조건 × A/B/C = 6회**로 제안한다. 동일 seed·배치·모델·실행기를 쓰고 순서는 섞는다. 시행당 시간·호출·토큰 상한과 원격 작업 총 상한을 제출 전에 고정한다. 이 6회는 통합 점검이며 통계적 우열 검정이 아니다.
- [ ] 정상 대조군에는 통신이 없어도 충분히 해결 가능한 임무를 넣는다. 어려운 조건은 중복 화물 선택/파트너 요청, 통로 양보, 자기 영상으로 확인한 실행 정체와 복구 등으로 구성한다.
- [ ] 각 조건에서 실제로 의도한 사건을 겪었는지 검사한다. 사건에 도달하기 전 접근 실패는 전체 실패에 포함하되, 복구 필요 상황을 경험한 횟수와 복구 후 완주를 따로 기록한다.
- [ ] 이후 파일럿에서 배치·로봇 ID·환경 seed와 모델 반복을 늘려 실행 시간·실패 유형·변동성을 측정한다. 개발에 사용한 장면은 최종 시험에서 제외하고 본실험 표본 수·예산·분석법을 정한다.

완료 증거: 선언한 시행의 성공·실패·오류·중단·미실행 목록, 대표 성공/실패 영상, 실제 메시지가 바꿀 수 있는 결정 지점, 본실험 비용 추정. 결과가 불리하다는 이유로 시나리오나 모델을 교체하지 않는다.

### P2 · R5. 고정한 새 조건에서 통신 본실험

- [ ] 개발과 시험을 맵 인스턴스/임무 단위로 분리한다. 같은 장면 재초기화·모델 seed·새 연결 구조를 서로 다른 변화 축으로 기록한다. 맵을 많이 생성했다는 사실을 통신 일반화 증거로 세지 않는다.
- [ ] 정상, 작업/통로 경쟁, 관측·의도의 정보 차이, 복구 조건을 고정한다. 작은 물건 수에서 먼저 비교하고 반복 운반·파트너 교체·더 많은 물건으로 단계적으로 확장한다.
- [ ] 모든 비교군에 같은 환경·로봇 배치·물리·카메라·저수준 제어·예산을 사용한다. B/C의 표현 가능 정보와 토큰 소비 차이를 기록한다. 모델·해상도·기억 길이·제어기를 통신 조건과 동시에 바꾸지 않는다.
- [ ] 새 LLM 판단부터 시작해 전체 임무를 실행하고 모든 실패를 보존한다. 고정 계획 재생·저장 응답 재생은 별도 진단이다. API/전송 실패도 시스템 결과에 남기며 정책 실패와 원인별로 제시한다.
- [ ] 추론 중 SIM 정지 조건과 실제 물리가 진행되는 조건을 나눠 기록한다. 초기 주 실험의 clock을 하나로 고정하고, 실시간성을 주장하려면 지연 중 실행·명령 만료·오래된 응답 거부를 별도 검증한다.

완료 증거: 고정 프로토콜의 전체 시행과 독립 결과 감사, 누락을 설명한 분모, 조건별 효과와 불확실성. 부분 회수·한두 성공을 완료 비교로 표시하지 않는다.

### P2 · R6. 통신의 효과와 비용 분석

- [ ] 전체 임무 완료율을 우선 보고하고, 물건/작업별 완료·복구 도달/성공·충돌·낙하·잘못된 완료·교착·중복 작업을 함께 집계한다. 정지나 안전 거부를 임무 완주로 세지 않는다.
- [ ] SIM 시간, 모델 대기를 포함한 wall 시간, 로봇별 대기, 명령 수, 메시지 수/바이트, 호출·토큰·응답 지연을 보고한다. 확인할 수 없는 비용은 미측정으로 남긴다. 실패한 실행의 짧은 시간을 속도 이득으로 세지 않는다.
- [ ] 같은 맵/시나리오의 대응 차이를 비교하고 반복을 맵 단위로 묶어 불확실성을 계산한다. 성공한 시행끼리의 시간 비교와 전체 배정 시행의 완료/시간초과 처리를 구분해 사전 선언한다.
- [ ] A↔B/C의 통신 채널 효과와 B↔C의 지정한 표현 방식 차이를 구분한다. 전체 시험에서 이득이 없으면 조건별 한계와 비용을 그대로 결론에 포함한다.
- [ ] 특정 메시지의 인과 효과까지 주장하려면, 같은 시뮬레이터·로봇별 기억·명령 큐·난수 상태를 복원할 수 있는 체크포인트에서 전달/차단 분기를 반복한다. 복원이 검증되지 않으면 로그는 작동 과정의 사례로만 제시한다.

완료 증거: 통신이 도움/손해/차이 불명인 조건, 효과 크기와 불확실성, 실패 원인, 성능-비용 비교, 실제 메시지와 행동의 연결. 대화가 그럴듯하다는 평가만으로 효과를 결론 내리지 않는다.

### P2 · R7. 재현 가능한 보고서와 시연

- [ ] 연구 질문→비교군→관측/실행 경계→시나리오→결과→한계 순으로 보고서를 작성한다. 통신 본실험 표와 ACT/Jev/인프라 진단 표를 분리한다.
- [ ] `experiments/<ID>/`에 실행 SHA, 프로토콜, 모델·지도·환경 해시, 모든 결과·실패, 검토 범위, 원본 위치, 재현 명령을 남긴다. raw가 로컬에만 있으면 그 범위를 명시한다.
- [ ] 새로 완료·회수한 성공/실패는 [TensorBoard 절차](tensorboard.md)로 중복 해시 확인 후 새 스냅샷에 추가한다. 공통 logdir·고정 지표·열·영상 등록·실제 화면을 확인하고 미완료 단계를 표시한다.
- [ ] 대표 영상은 성공만 고르지 않고 무통신의 성공, 통신의 실패/비용, 복구 사례를 포함한다. 영상·평가 표본 주기와 확인하지 못한 구간을 명시한다.
- [ ] 관련 검증·CI와 사용자 확인을 거쳐 PR을 병합하고, 안전 조건을 만족하면 기본 체크아웃도 fast-forward로 최신화한다. 연구 결과와 코드 병합 상태는 각각 기록한다.

완료 증거: 질문에 답하는 비교표·그림·사례와 한계, 원본까지 추적 가능한 연구 기록, 고정 버전에서의 재현 경로.

## 4. 보조 과제 — 본실험과 연결할 때 진행

### S1. ACT와 학습 데이터

- [ ] 기존/새 모델과 보정의 대응, 실제 운반 진입, 잘못된 완료/방출을 먼저 검증하고 이미 시작한 유한 비교의 완료·회수 범위를 정리한다.
- [ ] 공동·단독 운반이 겹칠 때의 배경, 회전, 정렬, 복구·완료 경계 등 실제 실패가 지목한 자료만 보강한다. train/development/test는 궤적 단위로 나눈다.
- [ ] 데이터 효과를 주장할 비교는 학습 장치·정밀도·구조·seed·예산까지 맞춘다. 기존 GPU 모델과 새 CPU 모델의 배포 비교는 그 차이를 한계로 남긴다.
- [ ] 지원 범위·효율·정확도가 확인된 공통 실행기를 A/B/C에 동일하게 제공한다. 512px 확대, 여러 전문가/라우터, 대규모 맵 재학습은 구체적인 병목과 채택 기준이 있을 때 별도 실험으로 연다.

### S2. Jev와 모델 선택

- [ ] 단일 로봇 운동 선택 비교의 결과를 정리한 뒤, 실제 협업에서 맡길 한정된 결정(재관측·도움 요청·양보·재계획 시점 등)을 정의한다.
- [ ] 주 통신 비교에서는 모델을 고정한다. 모델을 바꾸는 후속 비교는 같은 메시지 조건·상태·후보·실행 능력·예산에서 진행하고 API 신뢰성과 선택 품질을 함께 기록한다.
- [ ] 규칙으로 충분한 운동 기능은 유지한다. 단순 접근에서 규칙이 성공했다는 사실만으로 상위 협상에서 LLM이 불필요하다고 결론 내리지 않는다.

### S3. 기억·선택적 소통·확장 환경

- [ ] 반복 실패에서 쓸 로봇별 기억을 자기 영상·자기 발행 명령·실제 수신 보고로 구성하고, 관측 사실과 동료 주장의 출처/시각을 보존한다.
- [ ] 주 실험 후 기억 길이, 사건 기반/주기적 소통, 메시지 지연·손실·오래된 보고를 한 축씩 바꿔 효과를 비교한다.
- [ ] 맵 연결 구조·물건 수·선행 작업·파트너 교체를 늘릴 때 기존 ID 추적·자원 계약·실행 지원을 먼저 확인한다. 통신 효과와 운동 난이도 상승의 영향을 구분한다.

## 5. H1 · 실물 MasterPi 확인

- [ ] 공식 제출계획의 실물 검증 범위와 현재 팀 계획을 대조해 필수 산출물·일정을 확정한다. 시뮬레이션 중심으로 범위를 바꾸었다면 승인·합의 근거를 기록한다. 시뮬레이션 우선 진행이 원래 실물 목표의 삭제를 뜻하지는 않는다.
- [ ] 실제 카메라·구동·통신·시계·정지/만료·하중 유지의 지원 범위를 실측한다. 시뮬레이션 성공을 실물 검증으로 대체하지 않는다.
- [ ] 단독 기본 동작→두 로봇 공동 동작→제한된 협업/통신 비교 순으로 진행한다. 실물 결과는 별도 조건표·로그·영상으로 보고한다.

## 6. 바로 착수할 세 가지

1. **R0/R1:** 현재 RGB 실행 경로 기준으로 A/B/C 입력·메시지·동기화 표를 쓰고, 옛 CoELA와의 차이 및 새 adapter 경계를 고정한다.
2. **R2/R3:** 지원되는 작은 임무 하나에서 공통 운동 스킬을 세 독립 에이전트에 연결하고 무통신·정형·자연어 전환 검사를 한다.
3. **R4:** 동일 조건의 6회 연결 파일럿으로 실제 협상/실행·실패·비용 로그를 회수한다. 성공 여부와 별개로 측정 가능한 설계인지 판단하고 본실험 크기를 정한다.

새 작업은 관련 TODO ID, 연구 질문과의 연결, 종료 조건, 필요한 원본을 첫 기록에 적는다. 첫 단계 완료 증거가 없으면 모델·맵·학습량 확대보다 해당 경계부터 해결한다.
