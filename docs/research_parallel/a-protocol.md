## 연구 질문과 첫 실험 단위

중앙의 역할·임무 계획자 없이 동등하고 독립적인 세 로봇 LLM 에이전트가 통신할 때,
역할 분담·협력 이송·예외 복구의 성과와 시간·비용이 어떻게 달라지는가?
주 비교는 명시적 고수준 통신의 추가 효과, 부 비교는 지정한 정형 표현과 자연어
표현의 차이다. 무통신이 유리하거나 차이가 불명인 결과도 보존한다.

첫 임무 후보는 기존 dispatch 환경의 **공동 봉 `beam` 1개 + 단독 `box` 1개**, 로봇
`r1/r2/r3`, 하나의 지정 목적 구역이다. 기존 CoELA의 `oak_plank_01` 및 상자 2개와
다른 객체 목록이다. ID를 혼용하거나 자동 변환하지 않는다. 초기 정상 후보는
`open`, seed11, `dock_a`; 이는 기존 지원 경로를 고르는 개발 선택이며 통신 효과의
검증된 조건이 아니다. 모델 이름·물리/지도/카메라/보정/가중치 해시·최종 배치와
통합 실행 SHA는 아직 미확정이다.

한 시행은 새 초기화 → 세 독립 LLM의 새 작업 선택 → 공통 실행 포트에서 동작 →
종료 → 독립 평가다. 고정 계획 또는 저장 응답 재생은 실행기 진단으로 기록한다.
첫 연결에서는 동일 배치를 세 조건에 대응시키고, 이후 ID와 출발 위치를 교차 배정한다.
특정 carrier pair만 지원하면 그 사실을 manifest에 고정하고 일반 역할 분담 주장을
보류한다. 실행기가 미지원 조합을 다른 역할로 자동 바꾸어 성공시키면 안 된다.

## 세 조건과 공통 입력

| 조건 | 바뀌는 채널 | 허용 내용 |
|---|---|---|
| A `none` | peer 메시지 송신/수신 없음 | 자기 RGB·공용 top RGB·자기 명령/기억·정적 과제/지도·자기 최소 동기화 결과 |
| B `structured` | 제한된 스키마 | 관측 주장, 의도/요청, 수락·거절, 완료 주장, 복구 요청; 자유문장 우회 필드 없음 |
| C `natural` | 자유 문장 | B와 같은 범주의 주장/협상; 동일 수신자 선택·전달·만료 규칙 |

모든 조건에 동일한 모델 버전·시스템 프롬프트 기본부·이미지 해상도/캡처 정책·기억
보존 정책·고수준 행동 선택지·저수준 스킬/가중치·동기화·예산·clock을 제공한다.
메시지가 달라져 발생하는 기억과 행동 궤적의 차이는 연구 효과다. A에만 역할표를
주거나, C에만 풍부한 운동/완료 기능을 주지 않는다. B/C의 정확한 표현 가능 범위,
카테고리·필드·최대 길이를 C의 최종 schema에 고정한다. 다른 표현 능력과 토큰
비용을 가진 두 시스템의 차이를 자연어만의 순수 효과로 표현하지 않는다.

수신 메시지는 sender의 주장이다. 메시지의 object ID, 완료 문장, image hash가
문법상 유효하다는 사실은 내용의 참을 보장하지 않는다. 로봇 자신의 RGB 판단과
보고 출처/시각/만료를 구분하며, evaluator 정답을 진실 확인 수단으로 사용하지 않는다.

## 최소 동기화의 허용 범위

A도 자기 관측으로 화물·파트너·역할을 선택하고 공동 요청을 독립 제출할 수 있어야
한다. 참여자의 요청이 일치하면 시작하며 전원 합의나 고수준 메시지를 요구하지 않는다.
pending 중인 봉 요청이 관계없는 단독 상자 작업을 막아서는 안 된다.

| 인터페이스 | 허용하는 최소 정보 | 반환하지 않을 정보 |
|---|---|---|
| 자기 요청 접수 | 자기 request ID, 자기 제출 내용, pending/accepted/rejected | 동료의 다른 요청·사적 역할/경로·응답하지 않은 동료 목록 |
| 공동 동작 허가 | 내가 요청한 tuple에 대한 GO/HOLD, lease/epoch, 로컬 command ID | 전체 역할표, 동료 관측·계획·private reason, supervisor가 고친 계획 |
| 자원 충돌 | 자기 요청의 generic unavailable/pending | 점유자 ID·그의 화물/의도/다음 작업 |
| 정지/만료 | 자기 동작의 hold/revoke, 시각·기계적 사유 | 보지 못한 장애물 위치/접촉/측정 관절·다른 작업의 완료 |
| 단계 완료 | 자기 RGB claim과 그 입력/명령 ID; 공동 준비 여부의 최소 bit | 평가 성공을 이용한 단계 전환·정답 기반 완료 통보 |

GO, 거부, 대기 시간, 공동 hold도 정보를 드러내는 공통 저수준 채널이다. 그 비용과
의미를 세 조건 모두 기록한다. 예약을 반복 질의하는 탐색은 같은 행동 예산에 과금한다.
자기 요청의 object/participants를 되돌려 받는 것은 새로운 peer 정보가 아니지만,
peer가 제출한 역할표나 전체 plan hash를 조회하는 것은 고수준 정보 전달이다.
동의 매칭에 필요한 내부 task key는 정적 임무에서 재구성 가능해야 하며, A가 알 수
없는 peer의 임의 request ID/plan hash를 먼저 얻어야 하는 구조는 허용하지 않는다.

## 정상 및 정보 차이/복구의 연결 파일럿

고정한 두 시나리오 × 세 조건 × 1회 = **6회**다. 대응 시나리오의 환경 seed·배치·
외생 사건 일정은 같게 하고, 순서를 사전 난수화해 저장한다. 대화 결과가 나쁘다는
이유로 장면/모델을 교체하거나 재시도 결과만 보존하지 않는다.

| 후보 | 관측과 결정 지점 | 도달/채택 기준 |
|---|---|---|
| `normal-supported-mission` | 모두 같은 top/지도에서 작은 2+1 임무를 보고 자기 작업·파트너를 선택 | 통신 없이도 합법적 공동 요청과 단독 실행 가능; 역할 고정 강제 없음 |
| `local-visual-misalignment-recovery` | 공동 접근/파지 중 한 참여자가 자기 RGB의 물체-그리퍼 불일치 또는 자기 명령 후 영상 정체를 발견하여 hold/재관측/재정렬/도움 요청을 선택 | 모든 actor의 실제 own/top 입력·직전 자기 명령을 함께 보존해 정보 차이를 판정; 아직 setup 및 시각 근거 미확정 |

두 번째 후보는 자연스러운 시점/시야·자기 명령 이력 차이를 사용한다. `known_to`로
좌표를 한 로봇에게만 주거나 카메라/FOV·물체·장애물을 통신에 유리하게 제한하지
않는다. 공용 top에 이미 드러난 불일치는 비공개라고 부르지 않는다. 표본에서 차이가
입증되지 않으면 정보 비대칭 가설은 보류하고 공개 복구 조건이라고 명시한다.
이를 새 장면으로 바꿀 때는 다음 코호트 이전에 이유·setup·예산을 다시 고정한다.

`tests/fixtures/research_visual_witness/cases.json`은 과거 false-grasp/prepare 시각
검사 자료의 출발점일 뿐이다. 기존 source 설명에 접촉 평가와 교사 초기화가 포함되어
있어 그것을 actor 관측이나 새 2+1 시나리오의 채택 근거로 사용하지 않는다.
이번에 `false-grasp-r1-current-own_rgb.jpg`, `false-grasp-r3-current-own_rgb.jpg`,
`false-grasp-r1-current-top_rgb.jpg` 세 장을 직접 확인했다. 두 자기 영상에서는
물체-그리퍼 관계를 판독하기 어렵고 top에는 봉과 로봇의 배치가 보인다. 따라서 이
표본만으로 한 로봇만 파지 불일치를 안다고 주장할 수 없다. 복구 후보의 관측 차이
채택 gate는 계속 미충족이다. 카메라를 바꾸지 않고 실제 자기 명령 전후 영상에서
확인되는 진척/불확실성을 사용하거나, 공개 복구 조건으로 가설을 명시해야 한다.

복구 전에 접근이 실패해도 전체 실패에 포함한다. `event_reached`, `local_stop_claim`,
`recovery_attempted`, `recovery_completed`, `mission_completed`를 따로 기록한다.
첫 6회는 연결·측정 가능성 검사이며 통계적 우열·인과 효과·일반화 결론을 내리지 않는다.

## 유한 예산 초안과 종료

후속 실행 제안 상한: 로봇당 고수준 24호출(재시도 포함), 호출당 출력 768토큰·요청
wall timeout 30초, 로봇당 24메시지·72,000바이트. 시행당 입력 600,000토큰,
저수준 command record 6,000개, SIM 180초, wall 900초. 6회 합계는 432호출,
출력 최대 331,776토큰, 입력 3,600,000토큰, command 36,000개, 시행 wall 5,400초다.
remote job은 provisioning 900초·회수 600초를 포함해 최대 6,900초로 제안한다.
숫자는 임시 계획이며 D의 통합 manifest에서 단위·집계·실제 강제 기능을 검증해야 한다.
이 수치는 실행 허가나 완료 가능한 성능 추정이 아니다.

기본 clock 후보는 모델 대기 동안 물리 시각을 멈추는 연결 검사다. 모든 로봇에
동일하게 적용하고 wall 비용은 계속 센다. 구현이 비동기 물리 진행만 지원하면 그
조건을 코호트 전에 다시 고정한다. 어느 방식이든 지연 중 부하 유지·실시간성의
주장은 별도 검증한다. 메시지/lease/frame 유효기간의 clock domain을 명시한다.

종료는 actor들의 로컬 작업 종료 선언, SIM/wall/호출/토큰/명령 예산 소진, 안전
중단 또는 치명적 오류다. 평가 완료 정답은 actor의 재판단·완료 선언을 깨우지 않는다.
종료 후 평가가 잘못된 완료를 판정하며, 정답 실패를 피하려고 제어를 재개하지 않는다.
최종 입력 사용량이 미상인 호출은 0으로 처리하지 않고 상한 관리 규칙을 사전 고정한다.

## 지표와 주장 제한

주 지표는 배정된 전체 임무의 완료 여부/완료율이다. 실패·API/전송 오류·중단·미실행
상태와 분모를 모두 보존한다. 미실행을 물리 실패처럼 혼동하지 않으며 계획된 6개와
실행된 개수를 함께 보여준다. 봉/상자별 완료, 잘못된 완료 주장, 중복 작업, 교착,
충돌·낙하, 복구 도달 및 도달 후 완주를 보조 지표로 둔다.

시간은 SIM과 모델 대기 포함 wall을 따로, 호출·토큰·응답 지연·메시지 수/바이트·
명령 수·로봇별 대기 사유와 함께 보고한다. 실패한 짧은 시간을 속도 이득으로
집계하지 않는다. 비용 미확인은 null이다. 성공 조건부 시간과 전체 배정 시행의
timeout 처리는 별도 분석이다. 본실험 표본 수·최소 의미 효과·대응 분석/불확실성은
파일럿의 변동·실패·비용을 본 후 시험 데이터 수집 전에 고정한다.

원래 규칙 기반 비교는 같은 관측·운동·평가 경계의 추가 정책 실험으로 유지한다.
중앙 기준선이 전역 정답을 쓰면 명시적 oracle baseline으로 구분한다. A/B/C만으로
규칙/중앙 시스템보다 우수하다고 주장하지 않는다. 실물 MasterPi의 카메라/정지·만료·
하중 유지/협업 확인(H1)은 별도 단계이며 시뮬레이션 결과가 대체하지 않는다.
ACT·Jev·맵 확대는 필요 운동 기능 또는 조건 지원을 위한 보조 연구다.
