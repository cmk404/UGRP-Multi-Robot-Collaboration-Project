# 세 로봇 목표 합의와 두 화물 실제 운반

이전 구성의 R2는 정지 관찰만 했다. 이번 기본 실행에서는 세 독립 LLM이 같은
물체·목적지·담당·완료 조건에 합의하고, R1/R3 공동 빔 운반과 R2 독립 상자 운반을 실행한다.
관련 이슈 #50, PR #62. [구성·재현](../../docs/three_robot_e2e.md).

## 최종 검증

최종 소스: `d4368ba58d9a7d7260f451259ef1ab766a1fc331`. 동일 소스에서 3/3 완주 및 전체 입력·명령 재생 감사 통과.

| 조건 | 상자 목적지 | 빔 / 상자 이동 | SIM / 실제 시간 | 실제 LLM 호출 |
|---|---|---|---|---|
| 연결 진단 (LLM 없음) | near_magenta | 48.3 / 41.7 cm | 99.4 / 160.9 s | 0 |
| 실제 LLM 자동 선택 | near_magenta | 48.3 / 41.7 cm | 99.4 / 178.7 s | 24 |
| 실제 LLM 먼 구역 지정 | far_magenta | 48.3 / 85.0 cm | 104.8 / 349.0 s | 26 |

세 로봇의 실제 이동이 겹친 시간은 각 실행 2.1 SIM초였다. 몸체 순변위는 R1/R3 각각 약 1.08m, R2 약 0.75m(가까운 구역) / 1.18m(먼 구역)다.

실제 시간은 모델 지연과 동시 실행한 감사/영상 처리 부하의 영향을 받는다. 부하를 통제한 속도 비교로 해석하지 않는다. 먼 구역 모델 실행에는 timeout 1회와 HTTP 오류 1회의 재시도가 포함된다.

각 조건 한 번의 검증이다. 성공률 일반화나 통신/기억의 효과 비교는 아니다.
LLM 없는 fixture와 실제 모델 실행을 구분한다. 상자는 출발점 x=0.50m에서 운반했고,
정답 좌표는 실행 후 별도 평가에만 썼다. 목표의 중심점 오차 대신 전체 물체가 선택한
구역 안에 들어와 지면에 놓이고 로봇과 분리된 채 안정되는지를 판정했다.

- 세 로봇 모두 실제 몸체 변위가 있었고, 세 대의 이동이 겹친 시간도 별도 검사했다.
- 두 화물 모두 들어서 이동·방출·분리·안정을 확인했다. 모든 weld OFF.
- 카메라 배치/FOV, 로봇·빔 외관, 생산용 small_box_01의 질량/마찰/외관은 유지했다.
- 실제 모델 요청/전송/응답, 선택된 계획의 ID/해시, 각 영상 판단과 발행 명령을 재생 감사했다.
- 오프라인 테스트 766개 + 154개 subtest 통과 (`local-tests.txt`). GitHub 최신 상태는 PR #62의 Checks에서 확인한다.

## 영상과 실제 검토 범위

[자동 목적지 선택 영상](auto.mp4) · [먼 목적지 지정 영상](far.mp4) · [전체 프레임 2배속 보기](far-2x.mp4)

대표 영상은 전체 실행 원본이며 SIM 표시 시간을 포함한다. 실제 LLM 대기 중에는 SIM이
정지하므로 영상 길이는 벽시계 시간과 다르다. `visual-review.json`에 직접 확인한 프레임과
관찰 범위를 기록했다. 정지 사진 검토와 모든 프레임의 연속 재생 검토를 구분한다.

R1/R3가 먼저 빔 작업을 끝내고 R2는 자기 작업을 계속한다. 현재 전체 완료 시간을 정하는
병목은 R2의 느린 단안 접근·팔 자세 보정이다. 세 대가 같은 물체를 동시에 드는 영상이 아니다.

## 수정한 병목과 보존한 실패

| 실행 | 관찰된 문제 | 대응 |
|---|---|---|
| v1 | 생성 뒤 기본 배치 초기화로 R2가 다른 위치에 있었고 작은 청록색 조각을 추가 물체로 셈 | 관측 전 초기 배치 적용, 잡음 면적 필터, 기존 단안 입력 해상도 유지 |
| v2 | 새 상자/R2가 TOP 배경을 바꿔 기존 공동 파지 모델이 학습 영역 밖으로 판정 | 학습 방향에 변화가 없던 TOP 배경만 제외; 자기 RGB와 학습 가중치/허용 오차 보존 |
| v3–v4 | 파지 확인 중 느린 미끄러짐이 최초 영상과 누적 차이를 만듦; 대기만 늘려서는 해결 안 됨 | 각 새 시점과 직전 반대 시점의 동반 움직임 검사, 실제 떨어진 상자 fixture 거절 유지 |
| v5 | 과거 단독 실험의 접촉 solver 설정을 공유하면 빔 운반이 실패 | 물리 설정을 원래 값 impratio=1, noslip=0으로 복원 |
| v6–v7 | 오래된 파지 영상과 차이가 커짐; 정지 후 재관찰을 해도 반복 정지로 진행이 느림 | 새 좌우 시점으로 파지를 재확인하고, 운반 명령 사이 불필요한 정지 대기 제거 |
| v8 | 목표 구역에 도착했지만 중심점까지 더 이동하다 파지가 풀림 | 구역 안에 들어온 전체 상자 폭을 확인한 뒤 바로 내려놓기 |
| v9 | 가까운 구역의 접근·운반·놓기 첫 성공 | 최종 성공률에 합산하지 않는 진단 성공 |
| far-v10 | 먼 구역 전에 긴 운반 시간으로 파지 확인 실패 | 기존 허용 속도 안에서 순항 속도 및 영상 오차 이득 조정 |
| far-v11 | 먼 구역 첫 성공, 입력/물리 감사 통과 | 이후 LLM 계약 수정으로 최종 코호트와 구분 |
| llm-auto-final | 목표 선택은 맞았지만 모델이 임의 계획 ID/해시를 만들어 합의 거절 | 실행기 발급 식별값을 응답에 그대로 복사하도록 명시; 유효성 검사 유지 |

실패 로그와 결과도 `results.json`/`raw-manifest.json`에 모두 연결했다. 실패에 맞춰 평가
기준을 낮추거나 weld를 켜지 않았다. 물리 파지 성공과 영상 판정 성공은 구분해 기록했다.

## 남은 범위

- 지원 기술은 R1/R3 빔 + R2 상자로 고정되어 있다. 모델은 두 상자 목적지 중 선택하고
  정확한 전체 계획을 수락/거절한다. 임의 물체·운반자·경로 선정은 아직 지원하지 않는다.
- 단독 운반은 두 개의 평행한 고정 작업 레인용이다. 새 지형·장애물 우회·경로 재계획은
  이 실험의 검증 범위가 아니다.
- 로컬 움직임은 RGB 기반 고정 기능이며, LLM이 매 바퀴/관절 명령을 생성한 결과가 아니다.
- 공유 SIM 프로세스에서 동작하고 LLM 추론 중 물리가 정지한다. 실제 네트워크/프로세스
  장애, 추론 중 하중 유지, 실물 로봇으로 일반화하지 않는다.

## 저장과 재현

코드·설정·환경·모든 결과·시간·행동 수·토큰·검토 범위는 이 폴더에 저장한다.
프록시가 청구액을 제공하지 않아 비용은 미확인으로 기록했다.
`raw-manifest.json`은 각 로컬 원본의 위치·크기·SHA256이며 원격 백업이 아니다.
모델 입력 RGB와 원시 로그는 로컬 outputs에 남고, 이 폴더의 대표 영상과 요약만 Git에 포함한다.
프로젝트 예외에 따라 Google Drive를 사용하지 않았다. 실행 종료 후 해당 세션/자식을 정리했다.
