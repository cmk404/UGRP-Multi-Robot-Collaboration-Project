## 1. GRASP에서 완료/준비 상태가 섞이면 진행이 막힌다

natural에서 다음 순서가 원본에 남았다. 턴 번호는 0부터 시작한다.

1. 턴 10: 양쪽 모델이 `READY + at_grasp_pose + stopped`를 보고해 GRASP에 진입했다.
2. 턴 11: 두 보고가 승인되어 GO가 발급됐다. r1에는 집게 닫기(servo 1, pulse 1500),
   r3에는 모델이 선택한 wait가 발행됐다.
3. 턴 12: r1은 `DONE + wait`, r3는 `READY + 집게 닫기`를 응답했다.
   두 보고가 승인되고 GO도 발급됐지만 실제 명령은 **0개**였다.
4. 같은 `DONE/READY + GO + issued={}`가 턴 **12, 15, 16, 17, 18, 23**에서 확인됐다.
   마지막에는 12턴 연속 새 명령 없음으로 종료했다.

직접 원인은 [E2E 실행기의 둘 다 READY 조건](../../scripts/run_research_camera_e2e.py#L291)이다.
공동 단계 코어는 DONE을 유지 가능한 상태로 받아 GO를 줄 수 있지만, 실행기는
양쪽이 동시에 READY일 때만 발행한다. 그 조건만 지우는 것도 완전한 수정이 아니다.
[pair 발행 API](../../harness/task_stage_execution.py#L154)는 모든 참여자 명령을 요구하고,
[개별 발행 코어](../../harness/task_stage_sync.py#L342)는 DONE 참여자의 새 명령을 거부한다.
따라서 완료측 유지와 미완료측 진행을 어떻게 처리할지 단계별 계약을 맞춰야 한다.
GRASP에서의 부분 완료 처리를 CARRY 등 다른 단계에 무조건 일반화해서는 안 된다.

이 결함은 동기화/실행 연결 범위의 다음 수정 대상이다. 이전 회귀 검사는
모든 로봇이 같이 READY/DONE이 되는 흐름을 확인했어도 이 실제 비대칭 흐름의
진행을 보장하지 못했다. 감사된 원본 `diagnosis.json`에 해당 턴과 명령을 추출했다.

## 2. 모델의 파지 완료 보고가 실제 파지를 보장하지 않는다

natural의 r1은 턴 12부터 파지를 완료했다고 **11번** 보고했다. 그러나 별도 물리
평가의 전체 시계열에서 어느 손가락도 빔에 접촉하지 않았다. 영상에서도 빔은
바닥의 원위치에 있다. 입력 형식·요청 ID·시각 출처 검사는 보고의 의미적 정확성을
보장하지 않는다. 동기화 교착을 고쳐도 이 시각 판단 문제는 별도로 남는다.

none은 PREPARE 41턴을 수행했으나 r1의 READY는 0회, r3는 17회였고 같은 턴에
양쪽이 준비되지 않았다. r1은 회전·직진·팔 조정을 반복했고, 마지막까지 미준비를
보고했다. 예산 확대만으로 영상 정렬·파지가 해결되지는 않았다는 이번 실행의 관찰이다.
추가 예산을 주어도 절대 불가능하다는 결론은 아니다.

다음 순서는 (1) 비대칭 완료 상태의 단계별 실행 계약과 회귀 검증,
(2) 영상 기반 집게 정렬·파지 판단의 실제 정확도 검증,
(3) 같은 시작 조건에서 전체 E2E 재실행이다. 평가 정답을 행동 입력으로 넣지 않는다.
