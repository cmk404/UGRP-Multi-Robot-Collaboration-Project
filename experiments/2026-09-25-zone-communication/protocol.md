# 2026-09-25 구역 벤치마크 통신 비교 — 사전 등록 (ZC1)

사용자 요청(2026-09-25): 연구 질문(통신의 효과)에 맞게 무통신 기준 조건을 추가하고, 동적 재배분이 드러나는 실패 조건을 넣고, 반복해서 비교한다.

## 질문

같은 장면과 목표에서 로봇 세 대가 (1) 통신 없이, (2) 출발 전에 전체 계획을 합의하고, (3) 필요할 때만 대화하며 일할 때, 목표 달성, 완료 SIM 시간, LLM 비용이 어떻게 다른가. 실행 중 파지 실패가 한 번 생기면 그 차이가 어떻게 바뀌는가.

## 조건

| 이름 | 통신 | 설명 |
|---|---|---|
| independent | 없음 | 각자 자기 영상, TOP RGB 추정, 자기 작업 영수증만 보고 다음 일 하나를 고른다. 메시지는 전달되지 않는다(`recipients=[]`). 팀 게시판도 없고 호스트 중재도 없다. null이나 무효 답은 10 SIM초 뒤에 다시 묻는다. 자기 작업이 멈췄을 때도 10초 뒤에 다시 묻는다. |
| plan_first | 출발 전 합의 | 제안자 순환·만장일치로 전체 배분을 정한 뒤 다시 대화하지 않는다. |
| dynamic | 필요할 때 | 쉬는 로봇이 다음 일 하나를 선언한다. 겹칠 때만 해당 로봇끼리 대화한다. 두 번 세기 수정(`9412326`)이 들어가 있다. |

- 장면: `zones/zone_wide`, 목표 G8(A 빨강2 · B 청록2 · C 초록1+노랑1), 여분 빨강1·청록1.
- seed 12, 13, 14(배치와 로봇 출발 순서가 다르다). seed별 1회씩.
- 시나리오: nominal(주입 없음), grasp-fail(두 번째로 배정된 작업의 집게가 열린 채로 남아, 정상 재시도 뒤 `grasp_failed_by_teacher`로 끝남). 로봇은 "끝내지 못하고 멈춤" 영수증만 받고, 주입 사실은 출력에만 남는다.
- 3 조건 × 2 시나리오 × 3 seed = LLM 실행 18회. 모델 `gemini-3.8-flash`, 동기 SIM, `local_contact_fine`, `--record-replay`, `--max-sim-s 900`, weld OFF. 모두 **교사 실행기 조건**이다(이동과 IK는 정답 좌표, 잡기는 실제 집게). RGB 스킬 성공이 아니다.
- 실행 순서: seed 12 → 13 → 14. seed마다 nominal의 independent, plan_first, dynamic, 이어서 grasp-fail의 independent, plan_first, dynamic 순서다. 모두 Claude 잠금 안에서 차례로 실행하고 실행마다 부하 평균을 기록한다.
- 소스는 이 문서를 넣은 커밋으로 고정한다.

## 시작 조건 (fixture, LLM 0회)

seed 12에서 6개 조합(3 조건 × 2 시나리오)을 규칙 응답으로 한 번씩 돌린다. 여섯 모두 오류 없이 끝나고 `teacher_path_blocked`가 0이어야 LLM 실행을 시작한다. 규칙 응답의 목표 달성 여부는 시작 조건이 아니다. 규칙 응답은 시각 판단이 아니고, 무통신 규칙 응답은 과잉 배달을 할 수 있다. 하나라도 조건을 못 채우면 기록하고 멈춘다.

## 측정

- 주 결과: 심판 기준 목표 달성(구역별 색 개수 정확히 일치). TOP RGB 개수 일치는 따로 적는다.
- 보조 결과: 완료 SIM 시간(첫 배정부터), LLM 호출, 입력·출력 토큰, 과잉 배달 수(목표보다 많이 놓인 상자), `box_taken_by_peer`와 슬롯 거부 수, 충돌·무효 선언, 교사 막힘·양보.
- wall 시간은 참고로만 적는다(LLM 지연 포함).

## 해석 범위 (사전)

- 조건마다 시나리오별로 3회라 경향만 본다. 성공률 차이를 통계적으로 확정하지 않는다. 3회 모두 같은 방향일 때만 "이 조건에서 관찰됨"이라고 쓴다.
- plan_first는 실패 뒤 다시 계획하지 않도록 설계돼 있다. grasp-fail에서 plan_first가 실패하는 것은 설계에서 예상되는 결과이며, "대화 없이 고정된 계획의 비용"으로 보고한다.
- 교사 실행기 결함(교착 등)이 나오면 그 실행을 빼지 않고 결함으로 적는다. 고친 소스로 새 코호트(ZC2)를 따로 사전 등록한다.
- Z3, ZW1, ZW2와는 목표, seed, 조건 구성이 달라서 합치지 않는다.
