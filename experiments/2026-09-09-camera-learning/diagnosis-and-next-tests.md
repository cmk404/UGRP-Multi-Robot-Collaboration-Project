# 파지 실패의 구조적 진단과 다음 검증

2026-09-09. 요청: “뭐가 문제지? 해결 방안 찾아봐바”. 대상 실행 SHA `6d33e089dba10c172edfb5caff6174ff341ed3a0`. 이번 작업은 기존 코드·원본 입력·응답·결과 검토와 문헌 조사이며 새로운 제어 실험이나 구현은 하지 않았다. 카메라 위치와 물리를 바꾸지 않는다.

## 확인한 사실

네 조건 240호출에서 닫기 명령이 0회이고 양쪽 손가락 접촉도 0회다. 따라서 현재 병목은 물체를 잡은 뒤의 마찰·운반보다 앞선 접근·정렬·닫기 전환에 있다. 마찰이 충분하다는 뜻은 아니다. 단일 seed 비교는 일반 성공률이나 특정 원인의 인과 효과를 확정하지 않는다.

1. **온라인 학습의 목표와 표현이 파지에 맞지 않는다.** `harness/camera_action_learning.py:22`는 각 영상의 2×2 영역 RGB 평균을 만든다. `:131`의 회귀 입력은 자기 명령과 이전 같은 채널 명령의 차이뿐이고 현재 영상 특징은 입력에 없다. 현재 영상은 학습 표적의 전후 차이에만 쓰인다. 따라서 같은 학습 이력에서 같은 후보 명령은 현재 팔·물체 배치와 무관한 예측을 받는다. 집게-빔 간격, 방향, 열린 폭이나 목표 오차를 최적화하는 코드도 없다. 전체 VLM은 원본 영상을 보므로 전체 정책이 영상에 무관하다는 뜻은 아니다. 작은 색 변화 예측기를 파지 학습의 대안으로 연결한 설계가 부족했다.
2. **자기 식별 오류가 실제 명령으로 이어졌다.** learned r3 round 11은 자신을 상단 영상의 아래쪽 로봇으로 설명하고 전진했다. 같은 입력 및 출력 전용 평가와 대조하면 반대다. 이름만으로 위치를 추정하지 말라는 문구는 이 오류를 막지 못했다. 사례는 `learned/result.json`과 `learned/representative/r3/`에 있다.
3. **행동 효과를 분리해서 익히지 못한다.** 두 로봇이 동시에 움직인 상단 영상 변화를 각자의 자기 명령과 연결한다. 후보는 대기·주행 및 최근 명령뿐이라 닫기를 스스로 시도하지 않으면 학습 자료에도 없다. 학습기가 새 탐색 행동을 만드는 구조는 아니다.
4. **복구 행동이 제한되어 있다.** `sim/camera_robot_port.py:92`와 정책 형식은 forward ≥ 0이므로 직접 후진할 수 없다. 팔 명령은 절대 PWM 한 관절씩이며 카메라도 팔과 함께 회전한다. 이런 제약은 제어 난도를 높이지만 이번 실패의 주원인이라는 인과 증거는 아직 없다.

가시성은 추가 검증 대상이다. 재검토한 learned r3 round 11 자기 영상에는 빔은 보이지만 집게 양쪽 끝을 식별하기 어렵다. 프롬프트는 열린 집게를 빔 주위에 놓고 닫으라고 요구한다. 필요한 관계를 영상에서 확인할 수 없으면 이 전환 조건을 충족하지 못할 수 있다. 모든 시점·두 영상에서 항상 불가능하다고 단정하지 않는다.

## 우선순위와 통과 기준

### 1. 한 로봇씩 작은 명령을 주는 시각 식별·동작 진단

카메라를 그대로 두고 동료는 대기한다. 자기 로봇만 짧게 한 관절 또는 베이스를 움직여 전후 원본 영상에서 움직인 로봇과 집게/빔 특징을 추적한다. 각 관절은 작은 양·음 명령 변화를 각각 반복한다. 명령 이력은 발행값일 뿐 실측 위치로 간주하지 않는다. 관측은 두 카메라뿐이며 세계 좌표나 접촉값은 정책에 주지 않는다.

제안 통과 기준: 각 방향 5회 진단에서 자기 식별 5/5, 같은 국소 배치에서 특징 이동 방향 4/5 이상 재현, 변화량이 정지 영상의 흔들림보다 큼. 기준을 못 넘으면 협동 집기 재실행을 보류하고 해당 식별/가시성 문제를 좁힌다. 이는 제안 기준이지 달성 결과가 아니다. 진단의 순차 동작은 원인 분리용이며 최종 협동 제어의 성과가 아니다.

### 2. 색 평균 예측을 목표에 대한 영상 오차 제어로 교체

두 원본 영상에서 추적 가능한 집게 끝·빔 가장자리·상대 방향을 사용한다. 이것은 영상에서 추정한 픽셀 관계이며 시뮬레이터 세계 좌표 입력이 아니다. 위 진단으로 작은 자기 명령이 영상 오차를 어느 방향으로 바꾸는지 국소적으로 추정하고, 한 번 움직인 뒤 오차가 실제 줄었는지 다시 본다. 현재 영상과 동작 이력을 조건으로 삼아 자세 변화에 따라 모델을 갱신한다.

보이지 않는 특징은 검출 성공으로 꾸미지 않는다. 두 카메라에서도 필요한 관계가 지속적으로 가려지면 동일 카메라의 실제 시연 영상으로 정렬 목표/단계 인식기를 학습하는 방안을 별도로 검토한다. 고정 좌표 파지나 고정 동작 재생으로 성공을 대체하지 않는다. 성공 기준은 여러 시작 배치에서 오차 감소 및 닫기·시험 들어올리기로 이어지는 실제 영상이며, 단순 RGB 예측 RMSE가 아니다.

### 3. 한 팔의 정렬·닫기 검증 후 협동으로 확장

한 로봇으로 빔 한쪽에 정렬하고 닫는 단계부터 검증한다. 한 로봇이 전체 빔을 들어야 한다는 기준은 두지 않는다. 시각적으로 정렬됐을 때 닫기, 짧은 시험 움직임, 영상에서 물체가 함께 움직이는지 확인, 실패 시 작은 재정렬을 명시적으로 설계한다. 보이지 않는 상태를 “잡았다”로 확정하지 않는다. 두 로봇의 최종 공동 들기는 이전처럼 출력 전용 접촉·높이·유지시간으로 사후 판정한다.

## 문헌과 적용 범위

- [Jin et al., ICRA 2019](https://arxiv.org/abs/1810.00159): 영상 시연에서 목표 함수를 배우고 비보정 시각 서보의 연속 피드백으로 사용한다. 우리 설계에 필요한 것은 목표 오차의 정의라는 점을 뒷받침한다. 이 시스템의 MasterPi·두 로봇 파지를 보장하는 근거는 아니다.
- [Sadeghi et al., Sim2Real View Invariant Visual Servoing](https://arxiv.org/abs/1712.07642): 과거 움직임으로 현재 시점의 행동 효과를 익히는 recurrent controller를 시뮬레이션 데이터와 강화학습으로 훈련한다. 단순히 이전 사진을 VLM 프롬프트에 추가한 것과 같은 방식은 아니다. 해당 학습 파이프라인을 현재 입력 제한에 그대로 채택한다고 주장하지 않는다.

첫 실행 후보는 1번이다. 메모리 확대, 모델 교체, 장시간 협동 재실행보다 현재 명령과 실제 영상 변화가 연결되는지를 먼저 검증해야 한다. 이후 2·3번은 각각 통과 기준을 확인하며 진행한다.
