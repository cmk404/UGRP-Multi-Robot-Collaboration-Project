# 시뮬레이션 전 환경·통신·진행률 검증

사용자 요청: 기존 문제를 시뮬레이션 실행 전에 해결한다. 이 작업에서는 새 로봇 시뮬레이션이나 학습·코호트를 시작하지 않는다. 기존 Kaggle `04832043e57f`는 고정 소스에서 이미 실행 중이므로 코드·데이터를 변경하지 않고 유한 실행의 결과를 보존한다.

- Jev 원문 진단: HTTP 503 `no healthy upstream`, 529 `system_overloaded`, 30초 timeout. 제공자 장애 자체를 코드 수정으로 제거했다고 주장하지 않는다. 명시적 429/503/529 거절만 총 시간·호출 한도 안에서 최대 3번 호출한다. 불확실한 시간 초과와 502/504·잘못된 JSON·인증 오류는 재호출하지 않는다. 최초 실패, 모든 HTTP 응답, 복구 여부와 추가 호출 수를 보존한다. 기존 실패 시행을 성공 재시도로 교체하지 않는다.
- 중첩 로그의 진행률 누락: 원본 전체는 파일에 보존하고 허용된 구조화 진행 메시지만 상위 로그로 전달한다. 단계·진행 중 프로세스·실제 완료/실패/미완료 수가 Kaggle 로그에 나타난다. 수집기는 없는 진행률을 0으로 표현하지 않고 미계측/오래된 관측을 구분한다. 일시적 수집 오류 3회로 종료하지 않으며 원래 deadline을 유지한다.
- Kaggle `sitecustomize`의 `wrapt` import 요구를 전용 요구 파일에 반영했다. 시작 경고·패키지 불일치·필수 import 실패는 평가 전 차단한다. ACT 환경에도 같은 의존성을 설치하고 import를 별도 검사한다. [Kaggle 원본 시작 코드](https://github.com/Kaggle/docker-python/blob/main/patches/sitecustomize.py).
- sparse 소스 갱신은 깨끗한 일회용 실행 사본에만 적용한다. 누락된 과거 docs blob을 읽는 checkout 경로 대신 검증된 대상 tree의 인덱스를 직접 구성하고 실제 파일 내용·깨끗한 상태를 검사한다.
- Colab 비교 실행기는 최근 5분 내 Jev/Gemini 각 3회 연결/응답 형식 검사 통과 기록 없이는 런타임을 만들지 않는다. GPU 할당 실패는 시뮬레이션 실패와 구분하고 자동 무한 재할당·유료 구매·CPU 대체를 하지 않는다.

원격 검증은 별도 유한한 GPU 환경 검사만 제출한다(최대 900초). 의존성 설치·import·장치 조회와 진행률/산출물 회수만 수행하며 시뮬레이터 step/렌더링·학습·로봇 명령은 없다. 실제 실행·회수·해시·원본 및 오류는 후속 JSON에 기록한다. 짧은 사전 검사 통과는 장시간 서비스 무오류 보장이 아니다.

기존 231회 코호트의 조건 보존: relay 기본과 기존 이어달리기는 HTTP 1회 정책을 고정한다. 최대 3회 복구 정책은 연결 사전 검사와 명시적으로 별도 구성한 후속 코호트에만 사용한다. 재시도 조건이 다른 결과를 기존 분모에 섞지 않는다.
