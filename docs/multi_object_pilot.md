# 가변 물건 수·다중 작업 파일럿 v1

2026-09-20: 12개 임무 템플릿, 가변 작업 계획 계약, 합의 이후 자원 예약을 구현했다.
현재 검증 범위는 **오프라인 프로토콜 fixture**다. 물리 장면·모델 협상·실제 운반은 아직 실행하지 않았다.
기존 봉 1개+상자 1개 dispatch와 ACT 체크포인트의 의미는 그대로 유지한다.

[실행 기록](../experiments/2026-09-20-multi-object-protocol/README.md): 36/36 합성 trace 완료,
관련 테스트 55개와 전체 회귀 1,065개 통과(별도 184 subtests, 1 skip).

## 대표 조건

[파일럿 설정](../maps/act_generalization/multi_object_pilot_v1.json)을 단일 기준으로 사용한다.
물건 수뿐 아니라 로봇 재사용, 짝 변경, 목적 슬롯, 선행 관계와 작업 수를 바꾼다.

| 조건 | 봉 | 상자 | 물건 수 | 작업 수 | 주요 확인점 |
| --- | ---: | ---: | ---: | ---: | --- |
| single_box | 0 | 1 | 1 | 1 | 단독 작업 선택 |
| single_beam | 1 | 0 | 1 | 1 | 두 로봇의 짝·역할 선택 |
| mixed_pair | 1 | 1 | 2 | 2 | 공동·단독 작업 병행 |
| three_boxes | 0 | 3 | 3 | 3 | 세 로봇 배분·서로 다른 목적 슬롯 |
| two_beams | 2 | 0 | 2 | 2 | 공동 운반 반복·파트너 변경 |
| three_beams | 3 | 0 | 3 | 3 | 연속 공동 작업과 로봇 재사용 |
| mixed_four | 1 | 3 | 4 | 4 | 혼합 작업 부하 |
| box_heavy_five | 1 | 4 | 5 | 5 | 단독 작업이 많은 조건 |

총 12조건이며 개수 축은 1·2·3·4·5·6·8개다. 모든 조건과 지형의 전수 조합을
바로 실행하지 않는다. 특히 6·8개가 고정 카메라와 이동 공간 안에서 가능한지는 미검증이다.
`clear_first`는 작성자가 부여한 작업 순서 요구다. 아직 보이지 않은 장애물 발견 사건이나
실제 통로를 막고 있다는 관측으로 제시하지 않는다.

## 구현된 계약과 입력 경계

`sim/multi_object_suite.py`는 물건 목록과 임무 요구를 만든다. `object_id`와 `task_id`를
분리해 한 물건의 임시 적치와 최종 배송을 다른 작업으로 기록한다. 물건 ID는 논리 참조이며
물체에 새 표식이 생기거나 정확한 위치가 알려진다는 뜻이 아니다. 외관은 기존 주황 봉과
청록 상자의 복제를 전제로 한다. 식별은 후속 RGB 추적에서 바인딩해야 한다.

`harness/multi_object_plan.py`는 다음을 검증한다.

- 임무에는 물건 종류, 목적 슬롯, 논리 경로 자원, 필수 선행 관계만 허용한다.
  시작 좌표, seed, 평가 판정, 접촉 등 추가 필드는 거부한다.
- 계획은 임무 hash와 모든 작업을 포함해야 한다. 계획 제안자가 작업마다 로봇·파트너·끝 역할·경로를
  선택하고 추가 대기 관계와 자원 경쟁 시 우선순위를 정한다. fixture의 역할 배분은 테스트 전용이다.
- 기존 `TeamAgreement`로 세 로봇이 같은 버전/hash를 ACK해야 예약 프로토콜을 만들 수 있다.
- 동일 로봇의 여러 작업 배정을 허용한다. 동시 실행 자격은 로봇·물건·경로 자원·목적 슬롯을
  원자적으로 예약해야 얻는다. 자원이 겹치지 않는 작업은 함께 허가할 수 있다.
- READY/DONE은 작업·물건·제안/hash·로봇·증가하는 sequence와 자기/TOP 프레임 참조를 묶는다.
  수신 시각과 관측 시각은 실행기 소유의 같은 단조 시계를 가정한다. 최신성 기본값 2초는 fixture용이며
  실제 모델 지연 예산이 아니다. 이미지 내용이나 ID 추적의 정확성은 이 모듈이 판정하지 않는다.
- 모든 운반자의 최신 완료 **보고**를 받아야 작업 완료를 기록한다. 오래된 보고, 다른 작업 ticket,
  과거 계획의 완료는 다음 작업을 해제하지 않는다. 임시 적치는 최종 물건 완료 수에 포함하지 않는다.
- 적치된 슬롯은 해당 물건의 다음 운반 작업이 완료될 때까지 보수적으로 점유한다.
  계획 무효화 시 기존 예약을 유지하고 전이를 차단한다. 안전 중지·현장 확인·새 계획으로의
  예약 인계는 후속 실행기 작업이며, 객체를 새로 만들어 점유 상태를 지우면 안 된다.

여기서 `lane_a/lane_b`, `goal_a_01` 등은 **기하가 연결되지 않은 논리 자원**이다.
기존 `north/south`의 별칭이나 ACT 입력이 아니다. DAG 검증은 자원 교착 부재를 보장하지 않으며,
점유된 슬롯이 막히면 대기한다. 교착 탐지·복구는 실제 실행 연결 전에 추가해야 한다.
이 모듈에는 모터 호출, 실제 파지 단계 동기화, 재계획 후 재개 기능이 없다.
보고 기반 완료(`whole_mission_claimed`)와 평가 전용 물리 성공(`physical_success`)을 분리한다.

## 다음 구현 순서와 완료 기준

정적 장면 생성과 공간 검사는 [다중 물건 장면 검토](multi_object_scenes.md)의 실행기로 진행한다.

1. **물리 장면과 물건 ID:** 개방 맵에 기존 화물을 복제하고 자유 joint/geom 이름을 분리한다.
   1·2개부터 3·4·5·6·8개를 순서대로 검사한다. 카메라/FOV·외관을 바꾸지 않고 초기 겹침,
   가림, 접근·파지 여유, 남은 물건을 포함한 회전·운반 공간, 별도 최종 슬롯과 임시 적치 공간을
   확인한다. map/scene/mission hash를 연결하고 불합격 배치도 남긴다.
2. **영상 식별과 실행 연결:** 동종 물건을 영상에서 지속 추적하고 모호하면 정지·재확인한다.
   모든 명령·영상·단계·완료 보고·평가 행에 `task_id/object_id/plan_version`을 넣는다.
   선택된 역할을 실제 로봇 포트와 `TaskStageSync`의 GRASP→LIFT→CARRY→LOWER→RELEASE에
   연결한다. 단독 작업 경로도 연결하며, 전체 작업 허가가 개별 단계 허가를 대신하지 않는다.
3. **일반 경로와 반복 운반:** 작성 경로/최종 방향, RGB 기반 지역 추정, ACT 텐서를 함께 버전 갱신한다.
   먼저 개방 맵에서 상자 여러 개와 봉 2개의 실제 연속 운반, 이후 혼합·선행·임시 적치를 검증한다.
   교사 성공·학생 독립 성공·fixture 성공을 구분한다.
4. **계획 효과 비교:** 같은 맵·배치·물건·모터 정책·예산에서 고정 순서/배분, 공동 계획,
   관측 사건 이후 재계획을 비교한다. 물건별 최종 성공, 전체 임무 성공, 누락/중복/식별 전환,
   선행 위반·교착·시간·로봇 유휴·통로 대기·행동·비용을 함께 기록한다.

물건 수와 작업 패턴은 맵 분할을 가로지르는 새 독립 표본이 아니다. 같은 물리 맵의 모든
배치·작업·사건 변형은 기존 train/dev/test 분할을 상속한다. 이 12개는 개발용 템플릿이며
새 holdout 성적으로 세지 않는다. 물리 파일럿 후 예산·반복 수·seed·판정 규칙을 동결한다.

## 재현

```sh
.venv-sim-worker-mac/bin/python -m pytest -q tests/test_multi_object_plan.py
# 소스/설정을 먼저 커밋한 깨끗한 작업 트리에서 새 출력 경로로 실행
.venv-sim-worker-mac/bin/python scripts/prepare_multi_object_pilot.py \
  --output outputs/multi-object-pilot-NEW
```

12조건 각각에 로봇 배분을 회전시킨 세 계획을 합의·예약·보고까지 재생한다(총 36 fixture).
`fixture-only://` 이미지 참조와 READY/DONE은 합성 자료이며 실제 영상·모델 판단이 아니다.
출력은 임무 12개, 계획/합의/자원 이벤트 36개, manifest, 모든 결과, 소스 SHA·환경·해시다.
`protocol_ticks`는 논리 테스트 진행 횟수로 SIM 시간·운반 효율에 사용하지 않는다.
시뮬레이터/지속 서비스/API를 시작하지 않는다. 기존 출력 경로는 덮어쓰지 않는다.
