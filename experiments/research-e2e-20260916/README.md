# 연구 목적의 실제 RGB·LLM E2E 병목 진단 — 2026-09-16

**현재 경로는 역할 합의와 실제 접근까지 수행하지만, 공동 파지부터 해제까지의
전체 성공은 확인하지 못했다.** 수정 후보의 자연어 ON/OFF 각 2회에서 GRASP까지
도달한 실행은 0회다. 평지의 최소 2대 공동 운반부터 시도했으므로, 다양한 지형이나
3대 혼합 작업의 가능성을 이 결과로 판정할 수 없다.

실행기를 통합한 최종 시스템은 아니다. **누락된 로컬 실행기 자리에 직접 RGB→원시
명령 LLM을 연결한 파일럿**이다. 성공 판정을 fixture로 채우거나 교사 동작을 재생하지 않았다.

| 자연어 역할 제안 → 동일 배정 합의 | 1회 4턴 진동, 나머지 수정 후보 3회는 합의 |

| 공동 GRASP → LIFT → CARRY → LOWER → RELEASE | **미도달·미검증**; 코드 연결만으로 실제 검증 완료라 하지 않음 |
| 물리 성공 평가 | 전 실행 실패, 보조 weld 사용 0, beam 상승·운반 없음 |

## 병목과 다음 작업

### 1. 서로 동의하는 말만으로는 같은 역할 계획이 확정되지 않는다

natural 최초 실행의 역할안은 다음처럼 교차했다. 모든 응답은 accept=true였지만
한 번도 같은 턴에 같은 배정을 제출하지 않았다.

| 턴 | r1이 낸 배정 | r3가 낸 배정 |
|---|---|---|
| 0 | r1 아래 / r3 위 | r1 위 / r3 아래 |
| 1 | r1 위 / r3 아래 | r1 아래 / r3 위 |
| 2 | r1 아래 / r3 위 | r1 위 / r3 아래 |
| 3 | r1 위 / r3 아래 | r1 아래 / r3 위 |

상대의 이전 발언을 동시에 따라 바꾸면서 진동했다. 현재 입력은 자기 발행 명령은
기억하지만 **자기가 이전에 제안한 역할안 이력은 별도로 보존해 제공하지 않는다**.
영상에서 자기 위치를 해석하는 불확실성과 이 제안 맥락 부족도 기여 가능성이 있다.
원인 전체를 특정 모델의 추론 능력으로 단정할 수 없다.

**창민 담당 다음 작업:** 동일 제안 ID·버전·배정 해시에 대한 ACK와 확정/취소를
구분하고, 제안 충돌 시 순서를 정하며 제한 시간 후 재협상한다. 누가 어떤 역할을
제안할지는 고수준 담당의 판단으로 두고, 동기화층이 배정 정답을 선택하지 않는다.
검증은 위 교차 발언 재생에서 서로 다른 버전을 합의 완료로 처리하지 않는지,
지연 ACK·중복 ACK·계획 변경에서 오래된 허가가 차단되는지다.

### 2. 짧은 원시 명령마다 LLM을 호출하면 접근부터 비용과 지연이 쌓인다

natural-repeat는 로봇당 14개 명령 중 13개가 바퀴 명령이다. 약 165초·32요청·
보고 입력 175,850토큰을 쓰고 7.44~8.56cm 이동했으며 물체에는 닿지 않았다.
성공 응답의 보고 지연 중앙값은 6.14초다. 원시 명령은 한 번에 .2 SIM초,
관측 간격은 .3 SIM초다. 방향을 번갈아 수정하는 행동도 관찰했다.

이는 **현재 직접 원시 제어 경로의 처리량 문제**다. 정렬·파지 기술이 원천적으로
불가능하다는 증거는 아니다. 단순히 턴 수나 명령 지속 시간을 늘리는 처방은 이번에 검증하지 않았다.

**창민 담당 다음 작업:** 고수준 의도와 로봇 로컬 실행의 수명 주기를 연결한다.
예를 들어 접근 작업 ID·취소·HOLD·진행/실패 보고·명령 임대 갱신을 계약화하고,
준오의 영상 기반 로컬 실행기가 짧은 제어 주기를 맡게 한다. 접근/파지 알고리즘 자체를
동기화층이 다시 구현하는 범위는 아니다. 경빈/현승의 고수준 판단은 목표와 재계획을 담당한다.

### 3. 한 번의 모델 오류가 전체 작업을 끝낸다

수정 후보 4회 중 2회는 HTTP 응답 대기 30초 초과, 1회는 drive의 kind 필드 누락으로
멈췄다. 이는 물리 실패와 다르다. 이번 실행기는 실패 보존을 위해 오류를 임의 보정하거나
재시도하지 않았고, 한쪽의 응답만으로 새 동작을 실행하지 않았다.

**창민 담당 다음 작업:** HOLD 상태에서 제한된 재요청을 수행하고 요청 ID·관측 ID·
단계 버전을 유지한다. 오래된 응답/중복 명령을 차단하고, 형식 복구와 실제 행동 재시도를
구분한다. 재시도 예산 소진은 명시적 실패로 남긴다. 모델이 실제로 관측하지 않은
READY/DONE을 복구 과정에서 생성해서는 안 된다.

위 1·3의 계약을 우선 검증하고 2의 팀원 실행기를 연결한 뒤 같은 최소 평지 과제를
다시 돌리는 순서가 적절하다. 그다음 실제 공동 파지·상승까지 통과하면 적재 이동과
지형/좁은 통로 확장에 들어간다. 현재 결과로 #55/#56 공동 단계 관리기의 실제 적재
운영이나 미병합 물리 개선의 필요/충분성을 판정할 수 없다.

## 입력 감사와 시각 검토

- 전 5회 **66개 실제 전송 요청**, 현재/직전 영상 **244개 참조**를 재구성해 대조했다.
  커밋 당시 actor 코드 → 저장된 허용 입력 → 실제 HTTP 본문이 동일하다.
- 자기 명령은 실제 앞선 발행 기록, 상대 발언은 실제 상대 응답과 일치한다.
  none 입력의 상대 발언은 비어 있다. 좌표/접촉/평가 파일은 요청 생성 입력에 없다.
- 모든 기록에서 카메라 위치·FOV와 형상 불변, weld OFF, 정리 오류 없음을 확인했다.
  이 감사는 신뢰된 로컬 코드의 호출 경계와 원본 일치 검사이며 프로세스 격리 증명은 아니다.
- natural-repeat 영상 40프레임 중 전체 구간에 분산한 12프레임을 검토했다.
  나머지 4개 영상은 처음/중간/끝을 검토했다. 시작부터 종료까지 별도 평가 시계열도
  읽어 실제 접근·빔 미접촉·상승 없음과 비교했다. 전 프레임 육안 검토로 표현하지 않는다.
- 모델 추론 중 SIM은 정지한다. 이번 영상은 SIM시간 동작이며 실제 대기시간을 압축한다.
  네트워크/물리 비동기 지연과 실물 watchdog 검증을 대신하지 않는다.

## 검증 범위

오프라인 회귀 테스트는 실제 모델/물리 성공과 별도로 기록한다. 잘못된 GT 필드,
