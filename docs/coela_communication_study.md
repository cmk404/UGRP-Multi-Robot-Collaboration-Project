# CoELA식 통신 효과 실험 설계

작성: 2026-09-05. 사용자의 연구 목표: AI 에이전트끼리의 통신이 필요한지 검증한다.
상태: CoELA식 별도 실행 경로와 A/B/C 통신 조건을 구현했다. 아래 설계 중 반복 수 확정,
통신 손실/지연 주입, 메시지 차단 분기 실험은 아직 본실험 단계의 남은 작업이다.

## 연구 질문과 주장 범위

주 질문은 “부분 관측과 동적 작업 상황에서 명시적 고수준 메시지가 세 로봇의
완료율·완료 시간·실패 복구에 어떤 영향을 주며, 그 이득이 통신 비용을 상쇄하는가?”이다.
부 질문은 “정형 정보 공유에 비해 자유로운 자연어가 추가 이득을 주는가?”이다.
유한한 실험으로 모든 AI 협업에서 통신이 반드시 필요하다는 보편적 결론을 내리지 않는다.
무통신이 동등하거나 더 좋은 결과도 연구 결과로 보존한다.

참고: [CoELA 논문](https://arxiv.org/html/2307.02485v2), 특히 4장 모듈 구성과
5.4절 통신 제거 실험. CoELA 전체 재현을 주장하지 않고 모듈 분리 방식을 적용한다.

## 로봇마다 독립적으로 유지할 다섯 모듈

| 모듈 | 입력과 책임 | 경계 |
| --- | --- | --- |
| 관측 | 자신의 카메라·센서·자신의 실행 결과에서 사실 추출 | 전역 정답, 타 로봇의 비공개 상태를 읽지 않는다 |
| 기억 | 관측과 수신 보고를 출처·시각·확신도와 함께 저장 | 직접 관측과 타인의 주장을 구분하고, 오래된 정보의 불확실성을 유지한다 |
| 소통 | 무엇을 누구에게 언제 보낼지 선택 | 보낼 내용이 없어 침묵하는 선택을 허용한다 |
| 계획 | 자신의 기억과 받은 정보를 이용해 다음 작업·복구 행동 선택 | 기존 코드가 선택을 대신 수정하거나 역할을 배정하지 않는다 |
| 실행 | 선택된 행동을 공통 이동·파지·운반 제어기로 수행하고 결과 반환 | 세 로봇은 독립 진행하며 공동 동작 참여자만 필요한 동기화를 한다 |

기억·계획·실행 구현은 모든 조건에서 같다. 메시지를 받았으므로 기억의 내용이
달라지는 것은 의도된 효과이며, 동일 기억 내용을 강제하지 않는다.

## 주 비교 조건

| 조건 | 고수준 통신 | 검증 질문 |
| --- | --- | --- |
| A | 명시적 메시지 없음 | 각자 관측·기억·계획만으로 어느 정도 가능한가? |
| B | 정형 메시지: 관측 보고, 의도, 도움 요청, 수락·거절 | 기본적인 정보 공유가 도움이 되는가? |
| C | 자유로운 자연어 메시지 | B보다 유연한 설명·협상이 도움이 되는가? |

A-B는 정형 통신 채널을 추가한 효과, B-C는 지정한 메시지 표현 체계를 바꾼 효과다.
B와 C의 차이를 자연어 자체만의 순수 효과라고 과장하지 않는다. 메시지 생성 비용,
표현 가능한 정보, 전달 예산을 기록하고 가능한 한 맞춘다. 의미가 같은 사실을 정형/자연어로
인코딩하는 별도 실험은 표현 형식의 효과를 더 좁게 검증할 때 사용한다.
주 비교 후, 필요 시 C의 주기적 통신과 사건 기반 선택적 통신을 비교한다.
경매·중앙 계획 같은 별도 정책은 추가 기준선이며 소통 모듈 제거 실험과 구분한다.

## 현재 코드에서 먼저 분리할 경로

- `harness/mixed_warehouse_runtime.py`: actor context에 전역 `available_ids`,
  `idle_robots`가 전달된다. actor용 로컬 뷰와 실험 관리자용 전역 상태를 분리한다.
- 같은 실행기의 깨우기 조건이 전역 작업·유휴 상태·history 변화에 의존한다.
  프롬프트에서 필드만 지워도 정보 누출이 끝나지 않는다. 동일한 로컬 주기,
  자신의 실행 사건 및 해당 조건에서 실제 수신한 메시지만으로 재판단한다.
- `sim/mixed_warehouse.py`의 관측 기억 목록은 전역 `completed`를 이용해 항목을
  제거한다. 다른 로봇이 완료했다는 사실은 관측·보고 없이 기억에서 자동 제거하지 않는다.
- 현재 결정마다 `message`가 필수이고 전원에게 자동 방송된다. 행동 결정과
  실제 송신 사건을 분리하고, 무통신 조건의 내부 설명은 “송신 메시지”로 표시하지 않는다.
- 현재 장애물 recovery 사건을 여러 참여자에게 동시에 알려 주는 경로는
  국소 정보 조건과 구분한다. 상황의 원인을 한 로봇만 아는 경우, 다른 참여자에게는
  자기 제어기의 중단 결과만 제공하고 원인·좌표를 자동 전달하지 않는다.
- 정적 작업 목록·팀 구성·공통 규칙은 모든 조건에 같은 초기 지식으로 허용한다.
  실제 실행 가능성 검사·예약 거부 결과는 공통으로 유지하고, 이를 통해 드러나는
  최소 정보와 물리 환경을 통한 간접 관측은 정보 채널 목록에 명시한다.

## 무통신의 정의와 물리 제어

A는 “명시적 고수준 에이전트 메시지 없음”이다. 공동 운반 제어기의 최소한의
시작·정지·안전 동기화까지 없애서 A만 물리적으로 불가능하게 만들지 않는다.
공통 실행 계층이 제공하는 동기화·반환값을 세 조건에서 고정한다. 이 설계로는
모든 수준의 통신을 제거한 물리 시스템과의 비교를 주장하지 않는다.
현재 실행 계층의 ideal SIM geometry 사용도 모든 조건에서 동일하게 유지하고 공개한다.

## 시나리오와 반복

- 정보가 충분하고 작업이 단순한 정상 조건: 통신이 불필요하거나 손해일 수 있는 대조군.
- 한 로봇만 장애물·작업 변경·자기 능력 변화를 아는 조건: 정보 비대칭의 효과.
- 여러 로봇의 관측을 합쳐야 유리한 조건: 정보의 상호 보완성.
- 작업 중 실패·재배정 조건: 복구와 협상의 효과.
- 통신 조건 내 지연·손실·오래된 보고 조건: 전달 품질에 대한 민감도.

로봇 ID와 시작 위치를 바꾸고, 특정 ID에 유리한 분담 유도를 피한다.
환경 seed, 초기 관측 조건, 사건의 작업 단계, 제어기, 모델·언어·프롬프트 버전,
관측/의사결정 일정 정책, 중단 기준, 시간·통신 예산을 사전에 고정한다.
실행 순서를 무작위화하고 모델의 비결정성 때문에 같은 seed도 반복한다.
예비 실험으로 분산과 비용을 확인한 뒤 본실험 반복 수와 분석 기준을 고정한다.
통신 유무로 정책 경로가 달라지는 것은 정상이며, 동일 관측 궤적 자체를 강제하지 않는다.

## 지표와 인과 확인

완료율·전체 완료 시간·복구 완료율/시간을 주 지표로 삼고, 충돌·낙하·중복 작업,
유휴 사유, 송신 수·바이트·토큰·추론 지연을 함께 기록한다. 영상의 SIM 시간과
LLM 응답 대기를 포함한 실제 경과 시간을 따로 보고한다. 녹화 부담은 비교에서 통제한다.
실패·시간초과를 분모에서 빼지 않고 완료 시간의 실패 처리도 사전에 정한다.
짝지은 시나리오별 효과 차이와 신뢰구간을 보고한다.

로그는 observation → memory update → message sent/received → planning input
→ chosen action → physical outcome을 연결한다. 특정 메시지의 효과를 검사할 때는
동일 체크포인트에서 메시지를 전달/차단하는 반복 분기 실험을 사용한다.
계획 변경에 붙인 에이전트의 설명이나 대화 영상만으로 메시지의 인과 효과를 입증하지 않는다.

## 구현 순서와 통과 기준

1. actor 입력·기억·깨우기 조건에서 비공개 전역 상태가 흘러들지 않는지 검증한다.
   자신에게 보이지 않는 타 로봇 상태만 바꿔도 로컬 입력/깨우기가 변하지 않아야 한다.
2. 기존 물리 실행을 재사용하며 다섯 모듈의 경계를 나누고 세 로봇의 독립 진행을 유지한다.
3. A/B/C 통신 모드를 연결하고 송신/수신/기억/행동 로그를 동일 형식으로 저장한다.
4. 정상·정보 비대칭·복구 시나리오 예비 실험 후 본실험 설계를 확정한다.

## 구현과 확인 결과

- `harness/coela_modules.py`: Perception, Memory, Communication, Planner, Execution.
  메시지는 선택적이며 수신 대상을 지정한다. B는 열거된 필드·값만 허용한다.
  직접 관측과 타인의 보고는 분리하고, 관측 시각은 기억 갱신 시각으로 덮어쓰지 않는다.
- `harness/coela_runtime.py`: 로봇별 스레드와 모듈 인스턴스. 초기 센서 준비 이후 전역
  판단 장벽 없이 실행한다. 감독자의 전역 상태는 채점/사건 주입/종료에만 사용한다.
- `sim/mixed_warehouse.py`: strict_local 관측과 mixed_local_status/mixed_local_submit.
  팀 상태를 actor에게 전달하지 않고, 자기 작업 결과·최소 동기화만 반환한다.
  장애물 known_to로 정보 비대칭을 만들되 실제 카메라 감지라고 주장하지 않는다.
- `scripts/evaluate_coela.py`: A/B/C, 고정 seed 목록, 반복, 무작위 실행 순서,
  source hash, 실패 포함 분모, 원문·송수신·실행·토큰 로그를 보존한다.
  공통 초기 센서 준비 시간과 실험 실행 시간을 따로 기록한다.
- TEAM의 `/api/warehouse/decision`과 실험 실행 경로에도 연결했다.
  `scripts/serve_sim_coworker.sh`의 기본 architecture는 coela이다.
  `UGRP_WAREHOUSE_MODE`의 llm_no_comm/llm_structured_comm/llm_peer_comm이 A/B/C에 대응한다.
  `UGRP_WAREHOUSE_ARCHITECTURE=legacy`로 이전 경로를 명시적으로 사용할 수 있다.
  새 remote worker contract는 `masterpi-v2-coela-local-view-v8`이다.

모든 아티팩트는 `outputs/warehouse_research/` 아래에 있다. 각 실행의 source hash는
해당 design.json에 보존되며 서로 다른 버전을 무조건 합치지 않는다. private-video-03은
녹화 실행이므로 앞의 세 조건과 경과 시간을 비교하지 않는다. dev-01은 초기 센서 준비가
작업 시간 예산을 소모한 개발 실행으로 disposition.json에 비교 제외를 기록했다.

39개 집중 회귀 테스트가 통과했다. 로컬 입력·기억·깨우기의 전역 상태 비의존성,
수신자 격리, 무통신, 정형 메시지의 자유문장 차단, 느린 동료와 독립적인 판단,
반복 제안의 멱등성, 잘못된 모델 응답의 원문 보존을 포함한다.

```sh
/opt/anaconda3/bin/python -m scripts.evaluate_coela --seeds 11 --modes none,structured,natural --scenarios normal,private_obstacle --repeats 1 --output outputs/warehouse_research/NEW_RUN
```

선택적으로 `--record`를 붙이면 자연어 조건의 실제 한국어 발화를 영상에 표시한다.
상기 1회 성공들은 연구 질문에 대한 통계적 결론이나 메시지의 인과 효과 증명이 아니다.

실제 TEAM 통합도 확인했다. `/api/team/chat`에서 SIM의 A→B 전체 운반을 요청한
`team-cr000006-1788610980402339000.jsonl`은 `study_begin`, strict_local로 시작해
R1/R2/R3 각 HTTP LLM 서버의 12/7/12회 판단, 실제 메시지 9개, 3화물 성공으로 종료했다.
bridge·worker·coworker를 새 버전으로 갱신했고, 최종 queue_depth=0, inflight=null,
remote_authoritative=true를 확인했다. 요약은 `outputs/warehouse_research/coela-live-verification.json`이다.
