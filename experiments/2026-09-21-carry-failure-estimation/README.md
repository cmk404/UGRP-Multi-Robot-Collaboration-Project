# ACT 반복 실패 측정 — 2026-09-21

목표는 단일 성공 시연이 아니라 고정된 비교 조건에서 시도·성공·실패 횟수와 실패 단계를 측정하는 것이다. 이전 Kaggle E는 접근 진단 실패 뒤 전체 평가를 차단하여 실패율을 추정할 수 없었다. 그 진단 두 건은 기존 기록에 보존하고 이번 분모에 섞지 않는다.

## 고정 평가

- 기존 4개 환경 조건 × 3회 초기화 × 9개 제어 조건 = **108회**. 모델당 12회이며 환경별 분모는 3이다.
- 9개 조건은 기존 RGB 스킬 기준선(`teacher`라는 기존 식별자를 유지하지만 실행 중 정답 보정은 없음)과 128/256px × 과거 영상 1/4장 × 학습 seed 2개의 ACT 8개다. 기존 8,000-step 모델을 해시 검증해 재사용하며 512px는 제외한다.
- 환경 seed11, 지도·카메라·배치 오프셋·고정 계획을 유지한다. 같은 환경 반복은 새로운 독립 환경 표본이 아니다. 각 환경·모델별 실패 분율을 기술하며 독립 이항 표본으로 가정한 신뢰구간이나 일반 환경의 실패 확률을 주장하지 않는다.
- 접근·파지 보정 학습은 평가 전에 수행하고 평가 중에는 모델·소스·성공 판정을 고정한다. 테스트 성공에 따라 모델을 선택하거나 실패한 시행을 성공한 재시도로 대체하지 않는다.
- 접근 또는 파지 실패도 전체 작업의 실패 분모에 포함한다. ACT 의사결정 진입 횟수와 운반 진입 후 조건부 실패율은 별도로 기록한다. 운반 진입 0회면 조건부 실패율은 **측정 불가(null)** 다.
- 실패는 종료 단계, 실행 오류, 통신 오류, 시간 초과, 결과 유실로 나눠 보존한다. 결과 유실을 관측된 물리 실패로 꾸미지 않는다. 미실행은 대기 건수로 남기며 실패 분모에 넣지 않는다.
- 단일 실행의 비정상 종료·시간 초과·잘못된 결과 JSON은 후속 시행을 중단하지 않는다. 소스/입력 무결성 위반·필수 설치/학습 자료 준비 실패는 실행 가능한 고정 조건을 만들지 못한 상태이므로 별도 준비 실패로 중단한다. 클라우드 실행은 최대 4시간이며 자원 종료 시 전체 완료로 표시하지 않는다.

`protocol.json`은 기존 학습 조건을 보존한 별도 프로토콜이다. `scripts/run_carry_input_ablation.py`가 실행 전에 108개 trial ID를 기록하고 종료할 때마다 원본 결과와 누적 실패 분율을 저장한다. `scripts/carry_failure_metrics.py`의 판정은 사후 출력 전용이며 제어기로 전달하지 않는다. 감사 시 초기 조건 대응 키에도 반복 번호를 포함하여 세 번의 기록이 덮이지 않도록 한다.

## 검증 범위

모든 자식 실행이 접근 단계 실패로 끝나도 3회 반복 × 2개 제어 조건의 6개 실행이 전부 수행되는 회귀검사, 미실행/결과 유실/운반 진입 0회 및 전체·조건부 분모 검사를 추가했다. 이는 실행기 검증이며 실제 원격 로봇 성공률이 아니다. 원격 실행 식별자·소스 SHA·완료 건수는 별도 실행 기록에 저장한다. 결과·실패 원본은 기존 작업을 보존하고 새 출력 경로를 사용한다.
