- **상대에게 응답하는 대화는 약했다.** M1 V2만 `r1의 cyan-1 선택을 확인했습니다. 저는 green-1을 구역 C로 운반하겠습니다`처럼 상대 발화를 받아 말했다. 그러나 두 번째 라운드는 이미 합의한 내용을 되풀이한 것이었다. 나머지 창은 차례로 선언한 뒤 두 번째 라운드에서 침묵했다. 질문·거절·정정은 한 번도 없었다. 직접 전달(한 명 지정)도 0건이었다.

## 5. 대화 행위 라벨 (규칙 v1 기록 → v2 신설)

`results.json`의 `acts`는 **규칙 v1**(`harness/zone_dialogue_metrics.ACT_RULES_V1`)이 붙인 것이다. v1은 부분 문자열만 보므로 **언급을 행위로 셌다**: "Accepted proposal."이 `propose`가 되고, "Standing by for r1 proposal."도 `propose`가 된다. 2026-09-26 리뷰 후속 수정에서 **규칙 v2**를 새로 만들었다(단어 경계, 부정 억제, 남의 행위 언급 억제). v1은 이 기록의 라벨이므로 동결했고 `results.json`은 재생성하지 않았다.

- 수동 라벨 20개(한국어 V1/V2·V2 창, 파일럿 작성자, `manual_labels.json`): 완전 일치 **v1 18/20 → v2 20/20**. v1이 놓친 제출형 `propose`와 권유형 `request`를 v2가 잡는다.
- 영어 포함 수동 표본 12개(V0, `manual_labels_en.json`, Kiro가 비맹검 단독 라벨): 완전 일치 **v1 6/12 → v2 10/12**. 남은 2건은 "All goals have been achieved/are complete" 같은 **완료 상태 보고**를 v2가 `report`로 잡지 못한 것이다. 이 표본에 맞춰 규칙을 더 고치지 않고 `rule_misses`로 남겼다.
- 기록된 자유 텍스트 83건 중 라벨이 달라진 것은 9건이다. `propose` 총계는 20 → 16, `request`는 13 → 15로 바뀐다. 비교·미스·규칙 해시는 `act_rules_v2_check.json`에 있다.
- V3 구조 메시지의 `act` 열거값에는 `propose`와 `standby`가 **없다**(`harness/zone_dialogue_ko.ACTS` 9종). 따라서 V3의 행위 분포를 V0–V2 자유 텍스트 분포와 직접 비교하지 않는다. 두 어휘의 차이는 `ACTS_FREE_TEXT_ONLY`로 명시했다.
- 수동 라벨은 양쪽 모두 한 명이 비맹검으로 붙였고 교차 검토가 없다. 규칙 라벨은 평가 전용이며 로봇 입력·깨우기로 돌아가지 않는다.

## 6. 실행기 통합 권고(이 수치 기준, 잠정)

아래는 위 표본(변형당 20개, 창 6개, 신뢰구간 없음)에서 나온 **잠정 권고**다. 어느 항목도 작업 효율·성공률로 검증되지 않았다.

1. **프롬프트:** C 조건의 후보로 **V2(전체 한국어)**를 권한다. 관찰값은 한국어 준수 19/20 대 16/20, 코드 전환 1 대 4, ID 오류 0 대 1이고 reason도 한국어였다. n=20이고 차이가 3건이므로 V1 대비 우위는 **관찰된 방향**이며 유의성을 판정하지 않았다. claim 결정 분포는 V0와 달라진다(6/10 동일). 언어 효과와 통신 효과가 섞이지 않게 **A·B도 같은 한국어 과제 설명을 쓰고 메시지 형식만 바꿔야** 한다. B는 V3 스키마를 한국어 과제 설명 위에 붙이는 형태를 권한다. 호스트가 만드는 user JSON의 영어 문자열(`rgb_view.source`, `executor_receipt`, 기록된 영어 peer 메시지)은 이번에는 그대로 두었다. 통합할 때 번역하거나 literal 코드로 바꿀지 정해야 한다.
2. **턴·길이 한도:** 창당 6발화, 로봇당 2발화에서 한도에 걸린 발화는 없었다. 새 정보가 담긴 발화는 로봇당 1회였고 두 번째 라운드는 침묵이거나 반복이었다. 길이 한도는 **모드별로 다르게** 잡아야 한다.
   - 창(claim 모드, V2): 메시지 최대 114자, 턴당 출력 92–172토큰. V3 창은 최대 215토큰. → 발화당 240자·출력 256토큰으로 충분했다(6개 창 36턴 모두 256 이하).
   - 단일 턴 plan_first: 출력 256토큰을 **넘는 응답이 있다.** V2는 20건 중 6건이 256을 넘고 최대 365토큰(스키마 유효)이며, V0 6건/최대 324, V1 5건/최대 313, V3 5건/최대 395다. 초과는 모두 plan 모드(계획 JSON 포함)였다. → plan 계획을 같은 응답에 담는 경로에는 256토큰을 적용하면 잘린다. 원본 실행값인 `max_tokens=1400`을 유지하거나, 모드별 상한을 따로 측정해 정해야 한다.
   - 검증 상한 600자는 그대로 유지한다. 한도 도달 시 호스트 합의 생성 금지도 유지한다. 비용은 이미지 재전송이 좌우하므로, 창 안의 두 번째 턴에 이미지를 다시 보낼지는 조건 공통으로 따로 정해야 한다.
3. **사건 기반 훅:** 기록에는 할 일이 남은 3로봇 동시 결정이 첫 라운드뿐이어서, 사건 트리거는 이 파일럿에서 검증하지 못했다. 설계안대로 (a) 자기 RGB 정체·파지 후 영상 불일치, (b) 집결 대기 초과, (c) **실제 수신 메시지**로 창을 열고, 동료 작업 종료가 전원을 깨우지 않게 한다. 사건 발생을 호스트 정답으로 알려서는 안 된다.
4. **지표 파이프라인:** `harness/zone_dialogue_metrics.py`(한글 비율, 코드 전환, ID 오류, 행위 라벨, 상대 언급)와 이 분석의 usage 집계를 평가 전용 출력에 연결한다. 행위 라벨은 **규칙 버전을 함께 기록한다**(현재 v2). 미보고 토큰(total−prompt−completion)을 별도 열로 둔다. 발언 순서는 **교란 변수**다: 이 파일럿은 A(동시)와 C(순차)를 같은 조건에서 비교하지 않았으므로, C−A를 언어 효과로 읽으려면 순서·창 구조를 두 조건에서 같게 맞추거나 순서를 별도 조건으로 분리해 측정해야 한다.

## 7. 검증하지 않은 것

- 작업 효율, 완료율, makespan은 측정하지 않았다(SIM 없음, 바뀐 결정을 실행하지 않음).
- 표본이 작다(단일 턴 변형당 20개, 창 6개). V0 반복은 8쌍뿐이다. plan 결정 변화는 기준 잡음과 구분할 수 없다. 신뢰구간·검정을 계산하지 않았다.
- **동시 응답 대 순차 응답을 같은 프롬프트·언어로 비교하지 않았다.** 창의 충돌 0건을 직렬화의 효과로 확정할 수 없고, 충돌이 기록된 창은 M1 하나뿐이다.
- 출력 토큰 상한은 모드별로만 관찰했다. plan 모드 256토큰 초과 사례는 있으나, 실제로 상한을 256으로 걸었을 때의 절단·실패율은 실행하지 않았다.
- 미보고 토큰이 0이 되는 원인(숨은 추론 여부)은 확인하지 않았다.
- 사건 기반 창, 이동 중 발화, 미지 장애물, 2로봇 직접 전달 상황은 기록에 없어서 검사하지 않았다.
- 수동 라벨은 한국어 20개·영어 12개 모두 한 명이 비맹검으로 붙였고 교차 검토가 없다. 행위 규칙 v2는 이 두 표본 밖에서 검증되지 않았고 완료 상태 보고 2건을 놓친다.
- 규칙 v2·재개 동작 변경은 **코드 변경이며, 기록된 결과를 다시 만들어 확인하지는 않았다.** `results.json`은 계속 규칙 v1·스키마 v1 기록이다.
- 원시 wire(이미지 포함 요청 본문)는 worktree의 `outputs/zone-dialogue-ko-pilot-20260925/`(gitignore)에만 있다. 원격 백업은 없다. 커밋된 `calls.jsonl`에는 프롬프트 전문, 이미지별 SHA-256, 응답 HTTP 본문 원문, usage, wire SHA-256, 원시 파일 경로가 모두 들어 있다. 원본 이미지는 기본 체크아웃의 ZC2 요청 파일에 있으며 해시로 연결된다.

## 8. 파일과 재현

- `sample.json`: 선택한 결정 지점, 원본 파일 해시, 원래 결정·usage·설정
- `calls.jsonl`: 모든 HTTP 시도 124건(프롬프트 전문, 이미지 해시, 응답 원문, usage, 원시 경로). 커밋 시점 SHA-256은 `results.json.calls.calls_jsonl_sha256`에 있다.
- `dialogues.json`: 창별 턴, 전달 기록, 최종 claim (2026-09-25 기록, `episode` 필드 없음 = episode 1)
- `results.json`: 평가 전용 집계, 스키마 `ugrp.zone_dialogue_ko_pilot.results.v1`, 행위 라벨 규칙 v1
- `manual_labels.json`: 한국어 수동 행위 라벨 20개 (2026-09-25, 변경 없음)
- `manual_labels_en.json`: 영어(V0) 수동 행위 라벨 12개 (2026-09-26 신설)
- `act_rules_v2_check.json`: 규칙 v1/v2 재라벨 비교와 수동 표본 일치·미스 (2026-09-26 신설)

```
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py select     # 표본(결정적)
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py single     # 88회, 동시 2개
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py dialogue   # 36회, 순차
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py analyze --out <새 파일>
PYTHONPATH=. .venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue_act_recheck.py --out <새 파일>
```

재실행하면 `calls.jsonl`에 이미 있는(완료된) 호출은 건너뛴다. 예산(`--max-calls 150`)을 넘을 계획이면 호출 전에 멈춘다. `analyze`와 행위 재검사는 기존 출력 파일이 있으면 중단하므로 `--out`에 새 이름을 준다.
