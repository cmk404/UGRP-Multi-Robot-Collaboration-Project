# 공동 출하 연구 환경 v1

공동 목표는 빔과 상자를 **같은 출하 구역**의 각 슬롯에 내려놓아 한 주문을 완성하는 것이다.
세 로봇이 출하 구역 A/B, 빔 운반자 두 명, 상자 운반자 한 명, 북/남 경로, 작업 의존 관계를 합의한다.
로봇 ID별 역할은 고정하지 않는다. 호스트는 계획 형식·동의·자원 사용 허가만 검사한다.

## 이번 검증 범위

- 실제 MuJoCo 지형과 동적 물체, 생산 로봇 세 대, 자기 카메라·고정 TOP 구성.
- 다섯 환경의 물리 로딩·안정화·동시 모터 진단, 충돌·weld·카메라 불변성 검사.
- 실제 LLM 세 개의 동일 계획 합의와 로봇별 프로그램 생성. 입력 원문과 모델 wire 보존.
- 프로토콜 검사: 독립 준비, 협력 단계 대기, 공용 구역 배타 사용, 의존 순서, 오래된 계획 거부, 점유 상태 보존.
- **새 환경에서 접근·파지·운반·방출의 물리 E2E는 이번 환경 구성 검증에 포함하지 않는다.**
  생성한 로봇 프로그램은 `unbound_new_arena_skill`이며 기존 고정 레인 성공을 재사용하지 않는다.
  고정 명령 모터 진단과 fixture 계획은 명시적으로 표기한다.

## 통제 조건

| 환경 | 변경 | 연구에서 분리할 효과 |
|---|---|---|
| open | 중앙 섬 없음 | 역할·목적지 협상 비용 |
| shared_crossing | 중앙 섬과 두 통로, 공용 출하 앞마당 | 순서·공간 예약·동시 준비 |
| north_blocked | 사전 지도에는 없는 북쪽 장애물, 실행 전 배치 | 지도와 RGB 불일치, 경로 수정 |
| narrow_south | 남쪽 최소 여유 폭 0.39m | 단독/공동 운반 경로 차이 |
| rough_south | 남쪽 8mm 낮은 턱 | 지형 선택과 하중 유지 병목 |

예외 장애물은 초기 장면에만 배치한다. 주행 중 물체를 순간 이동시키지 않는다.
북쪽 막힘 조건의 지도는 기본 조건과 동일하며, 장애물 정답·조건 이름·seed는 모델에 전달하지 않는다.
seed는 로봇 ID와 초기 슬롯의 대응만 재현 가능하게 바꾼다. 난이도 전체 무작위화가 아니다.
새 물체 모양·손잡이·식별 마커·관측 카메라를 추가하지 않는다. 천장 조명은 새 환경 전체에 동일하게 적용한다.

## 후속 본실험 설계

같은 환경/seed/물리/관측/로컬 실행 스킬/호출 예산에서 다음 조건을 비교한다.
본실험 실행기는 아직 연결하지 않았으므로 아래는 비교 설계이며 측정 결과가 아니다.

1. 고정 역할 + 규칙 기반 통행 예약.
2. 중앙 계획 LLM + 같은 실행기.
3. 동등한 세 LLM + 초기 자연어 합의.
4. 동등한 세 LLM + 초기 합의 + 사건 기반 재합의.

세 LLM의 초기 계획 합의 여부, 역할/경로 선택, 계획부터 각자 시작까지의 지연을 먼저 측정한다.
물리 E2E 연결 후에는 공동 주문 성공률, cargo별 파지 유지/도착/방출, 전체 시간,
준비/통로/파트너별 대기 시간, 충돌/교착/재계획/실행 불가율, 메시지 수·토큰·비용을 측정한다.
응답 지연·누락은 센서나 물리 시간과 분리하여 주입하고, 점유 중인 자원은 timeout으로 해제하지 않는다.
현재 계획 프로브는 LLM 추론 중 물리 시간이 멈추므로 실시간 비동기 성공으로 해석하지 않는다.

## 정보 경계와 증거

`actor-mission.json`에는 정적 지도와 작업 설명만, `episode-setup-only.json`에는 seed/초기 배치/예외 정답만 보존한다.
`evaluation-only.json`은 종료 후 진단 평가 전용이다. 어느 파일도 이름만으로 학생 입력이 되지 않는다.
실제 요청은 자기 RGB + 공용 TOP RGB + 정적 임무 + 자기 발행 명령 + 상대 주장으로 한정한다.
운반 물체/로봇의 실시간 좌표·접촉·관절 측정·평가 레이블은 입력에 없다.
지도 canonical JSON hash, 컴파일 XML hash, 생산 로봇/물체 XML hash를 저장한다.
원시 wire/RGB/로그는 로컬 `outputs/`이며 대표 카메라 프레임·결과·뷰어만 Git에 보관한다.
