# 세 번째 ACT 후보: 남쪽 회전 경로 시연과 배포 정렬 입력

이번 후보는 고정된 [수집·학습 규약](route-coverage-protocol.json)에 따른 **결합 후보**다. 성공 시연 추가와 고정 CNN의 수치 경로, 개발 선택 배치를 함께 바꾸므로 데이터 증강만의 인과 효과로 해석하지 않는다. ACT 구조, 원래 행동 chunk 손실, 배포 첫 행동의 종료 보조 손실과 가중치 1.0, seed 20260924, 8,000회 업데이트, 종료 임계 0.65는 유지한다. 원본 v28 `931d910...`의 두 번째 8,000회 학습과 실패 최종화 결과는 그대로 남긴다.

기존 9회 학습 2,934행에는 남쪽 경로가 0행이다. 기존 개발 4회 2,128행에서 남쪽 F3/F4가 1,692행이며, 이 두 회의 좌우 명령 오차와 종료 오판이 집중됐다. 현재 저장된 성공한 v28 원위치 RGB 진단 두 회는 이미 입력 이미지와 실제 발행 명령 정합을 확인했고, 고속 북쪽 주행 표적을 새 학습에 보충할 수 있다. 하지만 같은 원위치 반복이므로 새 남쪽 장면을 대신하지 못한다. 다른 남쪽 성공 시연 `candidate4-F4`의 원본 RGB는 현재 참조 경로에 없어 학습 입력으로 쓰지 않는다. 이 진단의 행별 근거는 로컬 `outputs/act-action-training-20260924/act-next-diagnosis-20260924.json`과 `act-next-data-diagnosis-20260924.md`에 있다.

고정 소스 v28과 F3의 저장된 beam=south/box=south 직렬 계획으로 `shared_crossing` 새 RGB 교사 세 회를 순서대로 수집한다. 새로운 시작 위치 둘은 학습, 다른 하나는 개발로 지정하고 기존 F3/F4·v25-repeat·v26-full 개발 회차를 이동하지 않는다. 각 회 1,500초, 세 물리 시행 총 4,500초와 시작·정리 최대 120초를 상한으로 한다. 과거 F3/F4는 시뮬레이션 말미가 약 292초였으나 실제 wall은 1,215–1,268초여서 900초 제한으로 성공 가능성을 미리 배제하지 않는다. 고정 세 시행의 실패는 보존하고 대체 시행을 추가하지 않는다.

소스 동결·독점 물리 실행 확인 후 [교사 수집기](../../scripts/run_act_route_teachers.py)는 **새** `--record-root`에서 세 고정 조건을 기존 `dispatch-skills` 표준 관리 workflow로 호출한다. 계획의 입력 해시와 소스 `931d910...`을 시행 전후 대조하고, 각 raw·관리 manifest·stdout과 실패/미시작 상태를 보존한다. 수집기가 모두 성공으로 끝나도 아래 데이터 품질 게이트를 별도로 통과해야 학습할 수 있다. 수집기는 아직 실행하지 않았다.

학습 전 세 교사는 모두 실제 물리·프로토콜 성공, 원본 RGB SHA와 발행 명령·갱신 정합, 슬롯별 종료 라벨 각 1개, 각 슬롯 비종료 횡축 및 회전 정규화 명령의 절대값 0.1 초과 각 200행 이상을 충족해야 한다. 이 0.1 기준은 기존 F3/F4의 각 슬롯에서 횡축 최소 314행, 회전 최소 294행이 넘는 고정 기준이다. 전체 훈련·개발 간 이미지 SHA 교집합도 0이어야 한다. 하나라도 실패하면 세 번째 학습은 시작하지 않는다.

다음 학습의 새 `deployed_window` 캐시는 각 행의 이전 4개 RGB를 배포와 같은 순서·배치 4로 인코딩한다. 선택·최종 예측은 실제 한 요청처럼 배치 1로 수행한다. 기존 캐시 모드는 기본값으로 남는다. 앞선 최종화에서 문제가 된 기존 개발의 23개 첫 행동 입력과 추가 3개 경계 입력에 대해서 새 캐시는 특징·전체 chunk가 원본 경로와 동일했고, 기존 전체 chunk `atol=rtol=1e-5` 검사는 26/26 통과했다. 이 제한된 회귀 결과를 전체 데이터 검증으로 확장하지 않는다. 완전한 8,000회 업데이트 및 개발 선택이 끝난 뒤 고정된 선택 상태로 **모든 훈련·개발 행**의 원본 RGB 배포 경로와 캐시 경로를 전체 chunk 원래 1e-5와 모든 종료 결정을 비교한다. 어느 행이든 실패하면 artifact를 미완료로 남기고 모델을 사용하지 않는다.

기존 F3 길이를 대입하면 새 전체 데이터가 약 7,944행이고 특징 캐시만 약 2.08 GB다. 전처리, 개발 평가 17회, optimizer, 전 행 native 검증의 예상 시간과 peak RSS를 별도의 128행 제한 측정으로 먼저 확인한다. 2,400초 관리 상한 안에 여유가 있다는 근거가 없으면 학습을 시작하지 않고 상한 재판단을 보고한다. 적격 조건은 고정된 개발 5회에서 조기 종료와 누락 종료 모두 0회다. 적격 모델이어도 학생의 실제 운반 성공은 별도 동일 조건 물리 시험 전에는 주장하지 않는다.

허가된 CPU 공백에서 선택된 진단 가중치·저장 F3 말미 128행으로 제한 측정했다. B4 캐시 생성 5.537초, B1 개발 예측 0.187초, 전체 native-캐시 비교 8.606초였고 원래 전체 chunk 1e-5와 종료 결정이 128/128 일치했다. peak RSS는 637.3 MB다. 같은 행당 시간을 예상 7,944행·개발 2,974행×17회에 대입하고 기존 8,000회 실행에서 flat 캐시 시간을 뺀 값을 더하면 약 1,793초로 2,400초 상한보다 약 607초 짧다. 이것은 **선형 비용 추정**이며 실제 큰 캐시의 메모리·시간 증가를 증명하지 않는다. 읽기 전용 원본 기록은 `outputs/act-action-training-20260924/native-window-b1-evaluation-benchmark.json` (SHA-256 `a6442d80f50f27c8be13d14f80366da30d1d2b211711f6d9df19b50cb9f55582`)이다.

배포 worker는 이전 프레임의 CNN 특징을 재사용하므로, 시간창 0→1→2→3의 연속 입력에서 새 프레임만 다른 배치 크기로 CNN을 계산할 수 있다. 저장 모델 읽기 검사에서 각 split 처음 네 연속 입력과 마지막 입력을 캐시 ON/OFF로 비교하고, 연속 입력에서 실제 특징 cache hit·miss 모두 발생했는지 기록한다. 이 표본에서도 첫 행동 원래 1e-5 검사와 종료 결정 동일성을 지켜야 하며, 전 행 물리 동등성을 주장하는 것은 아니다.
