# 맵 다양화와 국소 ACT 개선 계획

작성일: 2026-09-20

상태: A의 맵·분할·정적 검토 v1 완료. A2의 12조건 다중 작업 계약·예약 검증과 다중 화물 정적 장면 검증 완료. 교사 수집·학습·다중 물건 물리 운반 평가는 미착수.

2026-09-20 실행 기록: [맵·프로토콜 v1](act_map_suite.md),
[22개 맵 정적 검토 결과](../experiments/2026-09-20-act-map-protocol/README.md).
새 맵의 실제 dispatch/ACT 실행 연결, 협업 사건 스케줄러와 최종 평가 수치 동결은 후속 작업이다.

관련 작업: [공동 운반 작업 목록 #39](https://github.com/kcm0127-dotcom/ugrp/issues/39)

## 목표와 방향

서로 다른 맵에서 두 로봇이 봉을 운반할 때, 같은 목표 조건부 ACT가 이동·회전·최종 정렬·완료 판단을 수행하도록 개선한다. 맵 다양화, 정상/복구 시연 수집, 입력 표현 개선, 새로운 맵에서의 평가를 하나의 작업으로 진행한다.

상위 계획·협상·공동 실행 허가의 합의 원칙은 유지하며, 물건 수와 작업 수가 달라지는 임무로 계약을 확장한다. 상위 계획은 로봇·파트너·작업 순서·대기 관계를 선택하고, 국소 ACT는 선택된 한 작업의 운동을 수행한다. 두 계층의 개선 효과를 분리해 평가한다. 단일 ACT의 수행 범위를 넓힌 뒤 실제 보완성이 확인되면 하중 복구 전문가와 외부 라우터를 비교한다. Jev는 교체 가능한 의사결정 후보로 둔다.

이 문서는 실행 계획이다. 문서 추가가 실험 수행, 제안 구조의 성능 입증 또는 main 병합 승인을 뜻하지 않는다.

## 유지할 제약

- 학생의 동적 관측은 자기 RGB, 고정 공용 top RGB, 허용된 과거 영상 및 자기 발행 명령 이력에서 얻는다. 작성된 정적 지도·목표·역할·카메라 보정은 허용된 경로에서 사용한다. 상대 정보는 허용된 수신 메시지로 전달하며 로봇별 비공개 상태를 합치지 않는다.
- 실시간 정답 위치·측정 관절·접촉·시뮬레이터 상태·평가 판정으로 학생 행동, 단계 전환, 완료 판단을 보정하지 않는다. 영상에서 얻은 추정치에는 출처·시각·불확실성을 남긴다. 발행 명령을 실제 이동이나 성공으로 간주하지 않는다.
- 교사 시연 생성에는 승인된 정답 상태·IK·접촉 정보를 사용할 수 있다. 교사 원시 정보와 학생 학습 입력을 분리하고 라벨의 출처를 기록한다. 정답 기반 교사 성능은 진단 기준으로 따로 보고한다.
- 카메라 배치/FOV, 로봇·화물 외관, weld OFF를 유지한다. 첫 맵 확장은 기존 고정 카메라의 관측 범위 안에서 구성한다.
- 지도와 물리 환경을 버전·해시로 연결한다. 새 경사·마찰·하중 조건의 통과 가능성을 미리 확정하지 않는다.
- 결과는 로컬 프로젝트와 Git 절차로 관리한다. Drive 및 퇴역한 클라우드 시뮬레이션 환경은 사용하지 않는다.

## 1단계: 맵과 평가 조건 설계

맵 다양화는 ACT 학습 이후로 미루지 않고 데이터 수집 전에 설계한다. 처음에는 한 요소씩 바꿔 원인을 구분하고, 이후 여러 요소를 조합한다.

| 변화 축 | 구성할 사례 | 주 검증 대상 |
|---|---|---|
| 통로 기하 | 폭, 코너 각도, 회전 공간, 장애물 간격 | 하중 이동·회전·정렬 |
| 연결 구조 | 갈림길, 막다른 길, 우회 분기, 코너/통로의 새로운 연결 순서 | 계획·경로 선택과 운동 재사용 |
| 시작·목표 | 다른 접근 방향, 목적지 위치·최종 방향, 다양한 운반 진입 자세 | 목표 조건과 완료 판단 |
| 협업 사건 | 로봇의 통로 점유, 메시지 지연, 지도에 없는 장애물 | 양보·대기·질문·재계획 |
| 물건 수·작업 구성 | 1·2·3·4·5·6·8개, 단독/공동 운반 비중, 목적지 분산, 선행 작업, 임시 적치 | 작업 배분·파트너 선택·로봇 재사용·누락 없는 전체 임무 완료 |
| 통과 불가능 대조 | 화물을 포함하면 통과할 수 없는 문, 완전 차단 | 무리한 진입 방지와 공동 정지 |

경사·마찰 등 역학 변화는 평면 기하·연결 구조 평가와 분리해 후속 단계에서 다룬다. 통로 점유·통신 지연 등의 사건은 맵 구조 자체와 별도 축으로 기록한다.

- [x] [기존 지도 목록](../maps/README.md)의 형식과 dispatch 실행기의 차이를 확인하고 공통 맵/임무 연결 방식을 정의한다. v1은 정적 지도/과제/장면 연결이며 실제 운반 API는 후속이다.
- [ ] north/south에 한정된 경로 이름을 확장할 때 계획 생성, 합의, 실행기, ACT 입력을 함께 연결한다.
- [x] 생성 설정에 맵 계열, 기하 파라미터, 연결 구조 ID, 생성 seed, 시작/목표 구역, 목표 방향, 사건 설정을 기록한다. 사건은 baseline none만 활성화한다.
- [x] 시작 배치와 사건 스케줄은 초기화/평가 정보로 분리하고 관측되지 않은 사건을 학생에게 미리 알려주지 않는다. 비기본 사건 실행은 스케줄러/감사 구현 전 거부한다.
- [x] 두 로봇과 화물 전체의 회전·이동 공간으로 경로를 검사한다. 기하 경로 존재와 실제 교사 통과 여부를 별도로 기록한다. 실제 교사 시험은 모두 not_run이다.
- [x] 각 맵을 렌더링해 카메라/FOV, 장애물·목표 표시, 실제 충돌 형상과 지도 일치를 확인한다. 새 16개는 고정 TOP 범위 내, 기존 회귀 6개는 일부 벽 윗면의 시야 한계를 기록했다.

**완료 기준:** 재현 가능한 맵 생성/로딩, 지도-물리 해시 연결, 통과 가능 후보/불가능 대조 구분, 시각 검토 자료가 있어야 한다. 기하 검사 통과만으로 운반 성공을 선언하지 않는다.

## 1-2단계: 가변 물건 수와 다중 작업

사용자 추가 방향에 따라 [대표 12조건 파일럿](multi_object_pilot.md)을 맵 확장과 함께 진행한다.
최대 8개까지의 모든 지형 조합을 곧바로 학습하지 않고, 먼저 물리 배치가 가능한 조건을 확인한다.
3개 물건을 5번 운반하는 재적치 사례처럼 물건 수·필수 작업 수·완료 수를 별도로 센다.

- [x] 12개 임무 템플릿과 `object_id/task_id`를 분리한 계약을 만든다.
- [x] 작업별 로봇·파트너·역할·경로·순서 선택과 같은 로봇의 반복 사용을 검증한다.
- [x] 세 로봇의 동일 계획 ACK, 선행 작업, 자원 예약, 오래된 보고 차단을 오프라인 fixture로 검증한다.
- [x] 카메라/FOV·외관을 고정한 다중 화물 장면과 정적 공간 검사를 만든다. [12조건 검증](multi_object_scenes.md)은 yaw=0 평행 이동 및 주차점에서의 독립 접근 기준이며, 회전·실제 운반 가능성은 별도다.
- [ ] RGB에서 동일 외관 물건의 ID를 추적하고 모호하면 정지·질문·재관측한다.
  [초기 파일럿](multi_object_execution.md): 12조건 초기 바인딩·16프레임 자세 변화 진단과 모호성 정지 검사 완료.
  실제 파지/운반 중 가림·교차·재식별 일반화는 미검증.
- [ ] 선택된 작업을 실제 단계 동기화·일반 경로·ACT 입력·평가 로그에 연결한다.
  단독/협동 작업의 실제 포트와 5단계 허가 어댑터 및 ID별 로그를 연결했다. 실제 모델 5작업 완료 0/5;
  기존 RGB 파지 정책·ACT·일반 경로 연결은 아직 남아 있다.
- [ ] 반복 운반/파트너 변경을 물리 검증한 뒤 고정 배분·공동 계획·관측 후 재계획을 비교한다.

**완료 기준:** 논리 계약 통과, 물리 장면 수용, 영상 식별, 실제 단계 실행, 물건별/전체 임무 성공을
각각 확인한다. 현재 계약·예약 fixture와 정적 장면/기하 후보를 확인했으며 실제 운반 성공으로 세지 않는다.

## 2단계: 학습·개발·시험 분리와 교사 시연

### 데이터 분리

| 집합 | 용도 | 분리 원칙 |
|---|---|---|
| 학습 | 정상 운동·복구·완료 경계 학습 | 다양한 맵 인스턴스와 실제 운반 진입 상태 포함 |
| 개발 | 체크포인트·입력 구성·임계값 선택 | 학습과 다른 맵 인스턴스·생성 seed, 별도 폐루프 실행 |
| 시험 A | 익숙한 지형 유형의 새 배치 | 같은 유형의 미사용 폭·배치·목표 조합 |
| 시험 B | 새로운 연결 구조의 일반화 | 학습에 없는 통로/코너 연결 구조 전체를 보류 |
| 회귀 | 이미 확인한 실패가 되살아나는지 점검 | 기존에 결과를 보고 조정한 조건은 새 일반화 성적으로 세지 않음 |

분할 단위는 궤적/맵 인스턴스이며 인접 프레임을 무작위로 나누지 않는다. 맵 생성 seed, 물리 초기 조건 seed, 모델 학습 seed를 구분한다. 하나의 맵에서 시작점을 반복해도 새로운 맵 수가 늘었다고 세지 않는다. 최종 시험 결과를 보고 튜닝하면 새로운 holdout을 준비한다.

### 시연 수집

- [ ] 정상 운반뿐 아니라 회전 진입/탈출, 목표 주변 감속·정렬, 정상 상태로 돌아오는 복구 궤적을 수집한다.
- [ ] 학생이 실제로 방문한 이탈 상태에서 교사가 이어받는 복구 자료를 수집한다. 인계 시 물체·로봇을 성공 위치로 이동시키지 않는다.
- [ ] 한쪽만 완료한 상태, 목표 근처지만 방향이 잘못된 상태, 아직 이동 중인 상태, 실제 완료 상태를 구분한다.
- [ ] 교사로 해결되지 않는 조건은 실패로 남기고 물리적 가능성·교사 능력을 진단한다. 성공 자료만 보고 전체 범위의 가능성을 주장하지 않는다.
- [ ] 수집 시도 수, 성공/실패/제외 수와 이유, 고유 궤적·프레임·완료 표적 수를 기록한다.
- [ ] 정답 기반 교사 출력과 학생에게 제공할 두 RGB·작성 조건·자기 명령 이력을 분리해 입력 누출을 감사한다.

**완료 기준:** 분할이 고정되고, 학습 대상 운동의 교사 성공과 실패 범위가 확인되며, 학생 입력 감사와 정상/복구/완료 경계의 데이터 집계가 있어야 한다.

## 3단계: 단일 목표 조건부 ACT 개선

기존 운반 실행기와 현재 ACT를 비교 기준으로 보존한다. 아래 변경을 모두 동시에 넣지 않고 개발 비교로 효과를 분리한다.

| 개선 후보 | 구현 방향 | 확인할 결과 |
|---|---|---|
| 완료 판단 | 경계 자료 보강, 운동과 완료 출력의 학습/평가를 분리 진단 | 잘못된 완료·완료 누락·한쪽 완료 대기 감소 |
| 지역 경로 조건 | 가까운 목표/경로 구간, 목표 방향, 역할을 실제 입력 텐서로 연결 | 새 배치와 회전·최종 정렬 수행 |
| 짧은 이력 | 과거 두 카메라 영상과 자기 발행 명령의 제한된 이력 | 정체·움직임·회전 진행 구분 |
| 시각 표현 | 기존 128px/동결 특징을 기준으로 해상도와 특징 학습 여부를 각각 비교 | 폐루프 성공과 추론 비용의 변화 |
| 체크포인트 선택 | 기존 교사 프레임 오차와 별도 개발 폐루프 성능을 함께 확인 | 개발 점수만 좋고 실제 실행은 나쁜 후보 구분 |

- [ ] 완료 선언이 서로 다를 때 새 영상 재확인, 제한된 대기, 합의된 정렬 복구/중단을 연결한다. 한쪽 완료 시 공동 정지 규칙 삭제나 임계값 완화만으로 해결하지 않는다.
- [ ] 지역 좌표는 허용 영상에서 추정하고, 작성 지도 좌표와 측정 정답 좌표를 구분한다. 경로 구간 전환도 평가 정답을 사용하지 않는다.
- [ ] 현재 chunk 8의 첫 행동만 실행하는 경로를 기준으로 유지한다. 실행 길이/temporal ensembling 변경은 별도 실험으로 다룬다.
- [ ] 각 변경의 개발 결과를 확인한 뒤 최종 후보·모델·성공 기준을 고정한다.

**완료 기준:** 완료·회전·정렬의 실패 유형별 변화, 기본 성공 조건 유지 여부, 시간·행동 수·비용이 대응 조건 비교로 제시돼야 한다. 개선되지 않으면 현재 실행기를 유지하고 원인을 다시 분리한다.

## 4단계: 새로운 맵에서 검증

- [ ] 같은 맵·초기 상태·카메라·물리 설정·과제 예산에서 기존 RGB 운반 실행기, 현재 ACT, 개선 ACT를 비교한다.
- [ ] 정답 상태를 사용하는 교사 비교는 실행 가능성 진단으로 분리하며 동등한 배포 입력 비교에 섞지 않는다.
- [ ] 학습형 정책은 여러 학습 seed로 반복하고 맵별 성적을 함께 기록한다.
- [ ] 국소 운반 평가는 실제로 파지·들기에 성공해 운반에 진입했는지를 별도로 집계한다. 새 LLM 합의부터의 전체 임무 평가는 별도 코호트로 실행한다.
- [ ] 정지한 SIM에서의 판단/운동 진단과, 추론·통신 지연 중 물리가 진행되는 조건을 분리한다. 지연 포함 실행 기반을 검증하기 전에는 실시간 성능을 주장하지 않는다.
- [ ] 원본 입력·발행 명령·정책 결정·평가 로그와 연속 영상을 함께 확인한다.

| 평가 축 | 필수 기록 |
|---|---|
| 성과 | 전체 임무 성공, 운반 진입률, 운반 진입 후 성공, 최종 위치·방향·방출 안정 |
| 실패 | 낙하, 충돌, 잘못된 완료/방출, 완료 누락, 한쪽 완료 대기, 교착, timeout |
| 효율 | 성공한 대응 조건의 완료 시간, 전체 시도 예산/timeout, 행동 수, 복구·전환 횟수 |
| 지연·비용 | SIM 시간과 wall 시간, 추론/통신 지연 p50·p95, API 호출·토큰·비용, 측정 가능한 로컬 계산 비용 |
| 일반화 | 맵 계열/연결 구조/학습 seed별 성적, 새 배치와 새 구조의 구분 |

빨리 실패한 시간을 속도 개선으로 세지 않는다. 맵 단위 묶음을 보존한 대응 차이와 신뢰구간을 제시하며, 표본이 부족하면 차이 없음으로 결론 내리지 않는다.

**시험 전에 고정할 항목:** 맵/조건 수, 학습 seed 수, 최대 시간·행동·비용 예산, 성공률 허용 감소폭, 필요한 시간/비용 개선폭, 낙하·충돌 판정과 표본 주기. 작은 파일럿에서 비용·분산을 확인한 뒤 이 값을 프로토콜에 기록하고 최종 시험 전에 동결한다. 아직 정하지 않은 수치를 검증 완료 기준처럼 사용하지 않는다.

## 5단계: 전문가 분리와 Jev의 조건부 비교

단일 ACT가 여러 운동을 함께 배우면서 특정 운동군을 반복적으로 놓치고, 별도 하중 복구 정책이 같은 상태에서 이를 해결할 때 전문가 분리를 추진한다.

- [ ] 같은 전체 데이터를 학습한 단일 조건부 ACT와 운반 ACT + 하중 복구 ACT를 비교한다.
- [ ] 같은 상태에서 후보별 결과를 보는 진단으로 수행 능력 부족과 선택 실패를 구분한다. 미래 결과를 본 선택은 실제 라우터 성적으로 보고하지 않는다.
- [ ] 앞 정책이 실제 도달한 상태에서 뒤 정책의 진입·유지·종료 조건을 검증한다.
- [ ] 공동 전환 버전·관측 시각·만료, 명령 취소, 로봇별 큐/누적 예측 상태 분리, 하중 유지와 중단을 검증한다. 기존 제어기로 복귀하는 경우도 해당 상태에서 재진입 가능한지 확인한다.
- [ ] 역할 변경은 별도 합의와 실행 계약 확장이 필요한 작업으로 다룬다.

Jev는 동일 실행기·관측·메시지·후보를 사용하는 규칙/기존 LLM과 비교한다. 먼저 저장 관측 또는 제안 기록만으로 선택 품질·지연·비용을 확인하고, 이후 지원된 대기·질문·재계획·전문가 선택의 폐루프 비교로 확대한다. 영상 요약·후보 생성·재호출 비용도 포함한다. confidence는 실제 과제 라벨로 보정하며 성공·안전 확률로 곧바로 해석하지 않는다.

**독립 실행 가능한 후속 과제:** 상위 의사결정의 가치를 먼저 보고 싶다면 기존 RGB 실행기를 고정한 Jev 비교를 진행할 수 있다. 다중 ACT 완성을 필수 선행 조건으로 삼지 않는다. 단, 새로운 실행 API나 유료 실험은 이번 문서 작성에 포함하지 않는다.

**채택 기준:** 다중 ACT는 같은 데이터의 단일 ACT 대비 실익이 확인될 때 유지하고, Jev는 같은 실행 능력에서 성공률·복구·시간·비용 중 사전 정의한 목표를 만족할 때 채택한다. 전문가도 실패하면 데이터/운동 능력을, 전환 시에만 실패하면 인계 계약을 우선 개선한다.

## 실행 단위와 산출물

| 작업 묶음 | 범위 | 산출물/종료 조건 |
|---|---|---|
| A. 맵·프로토콜 | 1단계와 2단계의 분할 설계 | 맵 생성/로딩, 시각 검토, 분할 manifest, 평가 프로토콜 |
| A2. 다중 작업 | 1-2단계 | 12조건 계약·예약 fixture → 물리 장면/영상 ID → 반복 실행/재계획 연결 |
| B. 교사·데이터 | 2단계의 실제 수집 | 모든 수집 결과, 정상/복구/완료 경계 자료, 입력 감사 |
| C. 단일 ACT | 3단계 | 독립 비교 결과, 모델·설정 해시, 개발 폐루프 기록 |
| D. 최종 검증 | 4단계 | 새 맵 holdout 성적, 영상·감사·실패 분석, 채택 판단 |
| E. 선택적 확장 | 5단계 | 전문가 보완성/전환 검증 또는 Jev 비교 |

A 정적 맵과 A2 논리 계약·다중 화물 정적 장면을 각각 PR로 남긴다. 다음 실행 단위는 후보 장면의 RGB 물건 ID 추적과 작업 ID별 실제 단계 실행 연결이다. 이후 각 묶음은 작업 브랜치·커밋·PR로 남기고 main 병합은 별도 사용자 승인 후 수행한다. 각 실험 전 실행 소스를 커밋하고 코호트 동안 소스를 고정한다.

실험 기록은 `experiments/<새 실험 ID>/`에 프로토콜, 코드 SHA, 환경·지도·모델 해시, 전체 결과, 검토 범위, 원본 위치를 저장한다. raw 영상·입력·가중치는 `outputs/<새 실험 ID>/`에 저장하며 실제로 업로드하지 않은 자료를 원격 백업이라고 표현하지 않는다. 지속 프로세스는 `scripts/ugrp_session.py`로 관리하고 해당 작업 종료 시 시작한 프로세스만 정리한다.
