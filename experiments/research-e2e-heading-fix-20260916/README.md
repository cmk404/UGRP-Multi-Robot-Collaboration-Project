# 출발 각도·거리 E2E 정렬 병목 수정

**최종 고정 후보: 19개 배치 × local/LLM 38회, 로컬 19/19·LLM 19/19 성공.**
거리 30–70 cm, yaw ±10°, 좌우 ±6 cm의 선택 배치에서 접근→파지→들기→
목표 50±3 cm 운반→내려놓기→해제→안정을 확인했다. 같은 평지·물체·카메라의

## 고친 세 가지 병목

1. 기울어진 상태의 먼 거리 직진이 옆 편차를 키웠다. 기존 TOP 영상의 노란 바퀴
   사각형에서 방향을 구하고 ±1.5° 밖이면 먼저 회전한다. 매 0.2초 새 RGB를 확인한다.
   고정 카메라·오른쪽을 향하는 작업 배치 및 ±18° 형태 지원 범위를 사용한다.
   앞뒤 구분이나 임의 방향 인식 기능은 아니다. 카메라나 외관을 바꾸지 않았다.
2. 정지 이후 오차가 다시 커져도 확인 상태에서 대기만 하던 흐름을 수정했다.
   다음 새 RGB부터 보정을 재개한다. 기존 이동 예산, 총 정지 확인 4회,
   연속 확인 2회와 허용 오차는 유지한다.
3. 마지막 앞뒤 보정이 이미 확인한 좌우 정렬을 흐트러뜨릴 수 있었다.
   마지막 전 축 검사에 실패했을 때만 최대 40회 새 RGB에서 필요한 축을 보정하고,
   모든 축을 서로 다른 두 정지 영상에서 다시 확인한다. 지원 범위 밖이면 중단한다.

근거리 학습 모델·시연 팔 명령·물리 성공 기준은 그대로다. 정답 위치/관절/접촉으로
오차를 보정하거나 작은 실패를 성공으로 바꾸지 않았다.

## 입력 경계와 검토 범위

- 실행 SHA `d863e74702902253bebd40b5429bad85bd5e6612`를 코호트 전체에서 고정했다. 모델·배치·참조 영상은
  실행마다 해시를 확인했다. 비교 배치 설정은 원래 38회와 같다.
- 로봇 입력은 자기 RGB, 공용 TOP RGB, 자기 발행 명령, 상대의 영상 설명이다.
  실시간 정답 좌표·관절 측정·접촉·성공 판정은 제어와 LLM 입력에 넣지 않는다.
- 입력 재생 감사 38/38: 실제 이미지 바이트·예측·
  발행 명령·LLM 요청/응답을 재구성했다. 새 전 축 보정도 저장된 RGB로 재생했다.
  운영체제 수준 정보 격리 검증은 아니다.
- 전 실행 접근 화물 접촉 0·weld 활성 0, 카메라/FOV·형상·마찰·질량 불변 여부는

## 재현과 보관

기존 Mac MuJoCo 환경과 사용 가능한 모델 프록시에서 실행한다. 다음 명령은 실제
모델 호출과 비용이 발생한다. 깨끗한 실행 SHA 체크아웃과 새 출력 폴더를 사용한다.

```sh
python3 -m zipfile -e experiments/2026-09-10-rgb-varied-start/models.zip outputs/goal-models
.venv-sim-worker-mac/bin/python scripts/ugrp_session.py run goal-heading-validation -- \
  .venv-sim-worker-mac/bin/python scripts/run_camera_goal_cohort.py \
  --cases-json experiments/research-e2e-varied-start-20260916/cases.json \
  --grasp-model-dir outputs/goal-models/models/grasp \
  --stage-model-dir outputs/goal-models/models/varied \
  --reference-top tests/fixtures/camera_goal_transport/reference-top.jpg \
  --mjpython .venv-sim-worker-mac/bin/mjpython \
  --out-dir outputs/goal-heading-NEW-ID
```

최종 raw 약 1.37 GB는 `results.json`의 `raw_root`에
명시한 로컬 폴더에 보관한다. 중간 코호트와 개발 진단 원본도 보존한다.
이 작업에서 시작한 실험 세션은 완료 후 종료했고 기존 공유 모델 프록시는 유지했다.
Git에는 설정·모든 결과·해시·대표 영상·검토 자료를 저장한다. 해시 목록은 전체 raw의
원격 백업이 아니다. Google Drive는 사용하지 않는다.
