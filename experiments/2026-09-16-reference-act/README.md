# 공식 ACT 재사용과 RGB 접근 비교

2026-09-16. 공식 LeRobot ACT를 RGB 전용으로 연결하고 기존 학생과 비교했다.
**최종 물리 파일럿은 기존 커널 3/3, 작은 ACT 설정 0/3이다. 기본 제어기는 유지한다.**
이는 축소 모델·300회 업데이트의 연결 검증이며 ACT 일반 성능이나 원 논문의
재현 결과가 아니다. 학습 예측 오차와 물리 성공을 분리해서 기록한다.

## 데이터와 작은 모델 설정

기존 교사 성공 25개를 사전 선언한 학습 20개/시험 5개로 나누었다. 로봇별 학습
1,146프레임과 동일한 목표 RGB anchor 하나를 사용한다. 시험은 로봇별 290프레임이다.
두 로봇과 같은 궤적의 모든 프레임을 같은 분할에 둔다. 제외 교사 사례는 0개다.
시험 사례의 영상으로 PCA·학습 범위·정규화·임계값·학습 횟수를 맞추지 않았다.

기존 커널도 같은 전체 학습 사례로 새로 학습했다. 과거 400표본/25사례 모델의
19/20 결과와 이번 결과를 합산하지 않는다. ACT는 두 RGB를 96×96, 0..1로 변환하고
전진 표적을 0.15로 나눈다. 별도 LeRobot 정규화 processor는 사용하지 않는다.
두 정책의 전처리·구조는 다르므로 데이터가 같다는 것이 모든 계산 조건이 같다는 뜻은 아니다.

ACT는 ResNet18 무작위 초기화, 64차원 Transformer, encoder 2층, chunk 4개,
매번 새 영상으로 명령 1개 실행, VAE, batch 16, 300 update, CPU 2 threads다.
로봇별 파라미터는 11,418,898개이며 카메라 위치/FOV는 유지했다.
학습과 평가 전체 wall은 418.03초, 두 ACT 학습은 합계 361.07초다.
두 커널 학습은 합계 25.11초다. 외부 LLM 호출/토큰은 0이다.
각 체크포인트를 새로 읽어 동일 입력의 추론값이 일치함을 확인했다.

## 시험 시연 프레임의 예측

| 로봇/모델 | 전진 명령 MAE | 정지 프레임의 준비 판정 누락 | 이동 중 잘못된 준비 판정 | 학습 범위 밖 거부 |
|---|---:|---:|---:|---:|
| r1 커널 | 0.003060 | 6/21 | 0/269 | 16/290 |
| r1 ACT | 0.006359 | 21/21 | 0/269 | 0/290 |
| r3 커널 | 0.005442 | 15/15 | 0/275 | 25/290 |
| r3 ACT | 0.004347 | 15/15 | 0/275 | 0/290 |

MAE 단위는 기존 forward 명령 단위이며 m/s 또는 위치 오차가 아니다.
거부 프레임은 출력 전진 0으로 MAE에 포함하고 분모에서 빼지 않았다.
ACT의 거부 0은 OOD 감지가 없다는 뜻이지 모든 영상이 학습 범위 안이라는 뜻이 아니다.
r3 ACT의 MAE가 더 낮아도 정지 판정과 물리 성공이 좋아졌다는 뜻은 아니다.
자세한 설정/환경/해시는 [학습 보고서](training-report.json)에 있다.

## 최종 실제 접근·파지 6회

미리 선언한 세 출발 거리쌍 `(20.5,20.5)`, `(25.5,22.5)`, `(29.5,27.5)`cm에서
두 정책을 각각 한 번 실행했다. 같은 장면/seed, 기존 공통 파지 스킬, 최대 접근
100회, 0.2초 명령, 정지 명령 뒤 새 영상 두 차례 확인, weld OFF를 사용했다.
순서는 사례별로 번갈아 실행했다. 시작 물리 상태(qpos/qvel 포함)와 첫 RGB 해시는
세 쌍 모두 정확히 같았다.

| 정책 | 접근·파지 성공 | 평균 접근 SIM초 | 평균 전체 wall초 | 두 로봇 접근 판단/명령 수 | 접근 중 물체 접촉 step |
|---|---:|---:|---:|---:|---:|
| 기존 커널 재학습 | 3/3 | 11.30 | 23.84 | 342 | 0 |
| 공식 ACT 작은 설정 | 0/3 | 20.25 | 28.15 | 600 | 0 |

최종 여섯 실행은 모두 런타임 오류 없이 종료했다. ACT는 모든 조건에서 정지 준비
판정을 내리지 못하고 접근 예산을 소진하여 파지를 시작하지 않았다. 이는 실제
실패이며 분모에 포함한다. 원인을 학습 부족·희소한 stop 표적 등으로 확정하지 않는다.
기존 커널의 성공은 물체 상승과 양쪽 손가락 접촉 유지에 대한 공통 평가 기준이다.
성공 판정은 실행 후 평가에서만 사용했다. 실물·다른 장면·새 물체·일반 협업 검증이 아니다.
wall은 초기화/모델 로딩/렌더링/IPC가 포함된 이 Mac의 관측값이며 다른 작업의 부하도
있었으므로 정밀한 추론 속도 벤치마크로 사용하지 않는다.

[전체 결과](physical-summary.json), [입력 감사](input-audit.json),
[시작/중간/끝 영상 표본](qa/physical-contact-sheet.jpg).
6개 영상에서 총 18프레임을 직접 확인했다. 커널의 들기와 ACT의 접근 단계 종료가
기록과 일치했다. 전체 프레임을 사람이 검토했다고 주장하지 않는다.
감사한 이미지 참조 2,076개는 모두 해시 일치했고 시작/종료 weld도 OFF였다.

## 개발 실패의 보존

앞선 `c10d24b` 물리 비교는 ACT 3회가 추론 전에 실패했다. 가상환경 Python 경로에
`resolve()`를 적용하면 실제 바이너리로 이동하여 venv의 torch를 잃는 오류였다.
[개발 실행 6회](development-physical-summary.json)를 별도로 보존했다.
이 실행은 최종 성공률과 합산하지 않으며 ACT 제어 성능의 근거로 사용하지 않는다.
수정 후 전체 6조건을 새 SHA에서 다시 실행했다. 학습 데이터/가중치/조건은 바꾸지 않았다.
