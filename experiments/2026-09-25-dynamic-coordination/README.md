# 2026-09-25 동적 협업(필요할 때만 대화) 실LLM 확인

PR #142의 `--coordination dynamic`이 실제 LLM으로 (1) 자기 선언으로 출발하고 충돌하면 대화로 넘어가는지, (2) 실행 중 접근 실패 때 두 운반 로봇이 retry/abort를 정해 재시도하는지 확인했다.

## 실행

모두 open 지도, 같은 작업 문장("서로 역할과 순서를 합의해서 beam과 box를 dock_b로 옮겨"), 동기 SIM, `--headless --record-replay`, 모델 `gemini-3.8-flash`다. 원본은 기본 체크아웃의 `outputs/dynamic-coordination-20260925/`에 로컬로만 있다. 파일 해시와 부하 평균은 `results.json`에 있다.

|---|---|---|---|---:|---|---:|---:|

- **D1**: CPU 잠금 획득 실패를 확인하지 않고 시작해 Claude가 수 초 만에 중단했다. 로봇 식별 단계였고 LLM 호출은 없다. 결과가 아니다(`D1-dynamic.interrupted.json`).
- **D2**: 자기 선언에서 r1은 빔 북쪽, r3은 빔 남쪽을 골라 `beam_route` 충돌이 났다. 호스트는 고르지 않고 동료 협상으로 넘겼고, 2턴 만에 "빔 북쪽 + 상자 남쪽, 선후 없음"으로 합의했다. 호출은 선언 3 + 협상 6 = 9번이다.
- **D3**: r3의 선언이 모델 프록시 HTTP 503으로 빠져 `missing_claim` → 3턴 협상으로 합의했다. 첫 접근은 정상 완료됐고 그 뒤 진단 실패를 주입했다(SIM 48.15초). 두 운반 로봇이 두 라운드 만에 retry로 합의했다(첫 라운드 r3 응답이 다시 503). 그러나 후진 뒤 재접근이 곧바로 `coarse RGB model convention unresolved`로 실패했고, 두 번째 retry 합의 뒤에도 같은 이유로 실패해 재시도 예산을 다 썼다.

## D3 실패 원인과 수정(v47)

- 후진(`back_off`)이 거친 픽셀 추적기를 **출발 시점 식별 위치**로 다시 만들었다. 이때 운반 로봇은 이미 빔 옆에 있어서, 바퀴 중심이 출발 위치와 약 110 px 떨어져 ±55 px 창 밖에 있었다.
- 오프라인 재현: D3의 재접근 첫 TOP 두 장에서, 출발 위치 창으로는 두 로봇 모두 바퀴 픽셀이 0개였다. RGB로 추적해 온 창으로는 두 번째 후진 뒤(합계 20구간) 두 로봇 모두 해석됐다. 첫 후진 뒤(10구간)에는 r3의 방향이 여전히 풀리지 않았다(빔에 너무 가까움).
- 수정: 후진을 20구간으로 늘린다. 추적 창은 유지하고, 정지 TOP 한 장으로 창 중심을 다시 맞춘다. 이 두 장은 `tests/fixtures/dynamic_recovery/`에 바이트 그대로 넣어 회귀 테스트로 고정했다.
- D3에서 모델은 실패 이유 문구("diagnostic injected…")와 `diagnostic_injection` 표시를 보고 "진단용 실패"라고 말하며 retry를 골랐다. 영상 판단을 시험하려고, v47부터 주입 때 로봇에게는 실제 제어기 정지 이유(`coarse RGB approach budget exhausted`)만 보이고 주입 사실은 출력에만 남긴다.
- v44는 D2/D3가 쓴 바이트 그대로 은퇴 보존했다. v47은 main의 v43(PR #143) 위에 다시 등록했다.

## 범위와 해석

- 조건마다 1회다. D2의 SIM 141초와 기준의 216초의 차이는 대부분 **계획 내용**(D2는 빔·상자 동시, 기준은 빔이 상자 뒤) 때문이다. 동적 방식 자체가 빠르다는 근거가 아니다. 호출 수(9 대 15)도 LLM 응답에 따라 달라진다.
- 확인된 것: 실LLM에서 선언 충돌 → 대화 전환, 선언 누락(503) → 대화 전환, 실패 뒤 두 로봇의 만장일치 retry 결정과 후진 실행.
- 확인 안 된 것: 수정한(v47) 재시도가 실제로 재접근·운반까지 완주하는지. 이는 D4로 확인한다(아래 갱신 예정).
- 회복 대화 메시지는 짝이 아닌 r2에게도 전달된다(기존 동료 메시지 전달 방식). 결정은 짝 두 로봇만 한다.
- 파지·운반·상자 로봇의 실패는 아직 대화 대상이 아니다.
