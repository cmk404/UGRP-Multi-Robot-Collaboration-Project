# 표식 없는 블록 전환 — 2026-09-09

사용자 요청: 블록 위 QR 모양 판을 없애고 현실처럼 표식 없는 블록으로 동작하도록 변경.

## 최종 상태

기본 장면의 QR 모양 판과 기본 집기·배치의 표식 의존을 제거했다. 실제 Gemini를 사용하는 소스 고정 M4 다섯 조건 검증은 **2/5 완료**다. seed42/43은 집기·장애물 우회·운반·방출·새 영상 완료 판정까지 통과했다. seed44/45는 방출 전 입력 예산 종료, seed46은 운반 초반 시각적 파지 확인 실패다. 표식 없는 동작은 확인했으나 안정적인 5/5 운반 또는 실제 하드웨어 성공을 뜻하지 않는다.

## 변경

- 소형 블록 01/02/03의 큰 표식 판과 대응 텍스처·재질을 기본 장면에서 제거했다. 원래 블록의 크기, 질량, 마찰, 충돌 형상은 유지했다. 과거 비교용 표식 장면은 명시적인 옵션으로만 남겨 두었다.
- 기본 집기·배치 경로는 ArUco 추적기를 사용하지 않는다. 자체 RGB의 청록색 블록 실루엣, 카메라 보정, 자체 PWM 기반 카메라 자세, 알려진 블록 치수로 바닥 위 상자 가설을 투영해 맞춘다.
- 물체를 들고 있는 동안 바닥 가설로 높이를 만들어내지 않는다. 기존 시각적 그립 확인과 능동 카메라 움직임 검증을 유지한다.
- 방출 후 한 장의 바닥 가설만으로 성공 처리하지 않는다. 집기 위치 근방에서 관측된 블록을 카메라 좌우/원위치 이동 중 반복 관측하고, 자체 PWM 방향 및 모든 관측 쌍의 위치 일치 여부를 확인한다. 최종 배치 위치는 새 RGB 관측으로 다시 판정한다.

## 관측 범위와 제약

청록색은 물체 식별 번호를 인코딩하지 않는다. 화물 ID는 작업에서 선택한 알려진 치수의 참조이며, 현재 단일 청록색 화물 장면에서 시각적 연속성을 유지한다. 여러 구분 불가능한 후보가 보이면 판정을 거부한다. 가려진 동일 외형의 다른 화물을 구별하는 일반적 재식별 기능은 구현하지 않았다.

바닥 투영 적합은 알려진 치수·수평 바닥·카메라 보정에 의존하는 조건부 추정이다. 이 변경만으로 실제 MasterPi 하드웨어 검증을 주장하지 않는다.

## 면 정렬 및 방출 관측 개선

M1 이후 블록 면 방향을 자체 영상의 상자 형상으로 추정하고, 연속 세 관측의 방향이 일치하면 기존 면 앞 대기 위치로 접근하도록 연결했다. 먼 거리의 작은 실루엣으로 면을 확정하지 않고 약 0.405m 이내에서 확인을 시작한다. 접근에 필요한 방향을 확인하지 못하면 실패로 남긴다.

파란 바닥 반사가 전체 실루엣에 붙는 문제에는 알려진 크기의 윗면 사각형을 별도로 맞춘다. 네 변의 길이, 직각, 투영 오차와 추정 높이를 모두 검사하며, 별개의 그럴듯한 블록 후보가 있으면 거부한다. 내려놓기 검사에서는 이 윗면 중심으로 카메라 이동 전후 위치를 비교한다. 단일 영상의 바닥 가설을 독립적인 접촉 증거로 취급하지 않는다.

- manip42-r2-face: 집기와 바닥 방출은 진행했지만 기존 전체 실루엣 추정의 관측 간 차이 11.899mm로 방출 확인 실패. 이후 윗면 추정을 같은 저장 영상에 적용하면 위치 차이가 약 0.389mm였다. 이 재생 결과만으로 새 물리 실행 성공을 주장하지 않는다.
- manip43-r3-combined: 먼 거리에서 면 확인이 되지 않아 4.09 SIM초에 실패했다. 가까이 접근한 뒤 면을 확인하는 변경의 근거다.
- 관련 조작, 면 정렬, 배치, 소형 블록 장면 및 기존 표식 경로 검사 44개와 하위 검사 4개 통과. 최신 검출기 검사는 별도로 기록한다.

## M3에서 드러난 완료 명령 연결 오류

M3 seed43에서는 밝기 수정 후 실제 방출과 바닥 정지 검사가 통과했고, 계획 단계 배치 증거도 inside였다. 그러나 Gemini의 finish 직전 별도 검사 호출에는 방출 확인 인자를 누락했다. 방출 후 정상적으로 held=False가 된 상태를 그대로 전달해 `RELEASE_OR_SELECTED_TARGET_CONTINUITY_UNCONFIRMED`가 되었고, 올바른 finish 요청을 반복 거부했다. seed43은 25호출/117,486입력토큰 후 예산 종료됐다.

원인을 확인해 M3를 중단했다. seed44는 초기 접근 18.076 SIM초/30관측에서 중단, seed42/45/46은 미실행이다. `m3/early-stop-record.json`이 정확한 실행 범위를 기록한다. M3를 완전한 다섯 조건 평가로 사용하지 않는다.

`inspect_actor_placement()`로 두 검사 경로를 통합했다. released 상태와 `VISUAL_RELEASE_CONFIRMED`가 함께 있어야 방출 연속성 증거를 전달한다. 새 카메라 영상과 목표 구역 내부 여유 검사는 계속 필요하다. 실제 M3 실패 당시 RGB·자체 PWM 회귀 검사로 confirmed release에서만 finish가 받아들여지고, 확인이 없는 released 상태는 거부됨을 검증했다. 관련67개/하위4개, Gemini 실행·예산·정책83개/하위26개 검사 통과.

현재 실제 운반 실행기와 새 markerless 조작 검사는 위 공통 방출 증거 경로를 사용한다. 과거 `dev-01`의 raw prefix와 표식 식별을 전제로 하는 `scripts/probe_camera_redelivery.py`는 이번 markerless 재검증 대상으로 삼지 않았다. 그 과거 체크포인트의 초기 식별 전제와 방출 후 완료 경로는 별도 이식이 필요하다. 그 스크립트의 기록과 원본은 보존했다.

## M4 최종 검증

M3 완료 경로 수정 후 145개 파일을 고정하고 seed43,44,42,45,46 순서로 실제 Gemini 운반을 실행했다. 실행 중 코드 변경과 개별 조건 재시도는 없었으며 종료 후 모든 소스 해시가 일치했다. 각 조건은 30호출/입력120,000토큰/300 SIM초, medium reasoning, 60초 요청 timeout이다.

| seed | 결과 | 호출 | 입력 토큰 | SIM초 |
|---|---|---:|---:|---:|
| 43 | 방출 및 완료 통과 | 25 | 115,835 | 195.424 |
| 44 | 방출 전 입력 예산 종료 | 25 | 116,646 | 240.694 |
| 42 | 방출 및 완료 통과 | 21 | 94,115 | 225.752 |
| 45 | 방출 전 입력 예산 종료 | 24 | 113,533 | 240.962 |
| 46 | 운반 초반 그립 확인 실패 | 4 | 18,771 | 66.760 |

seed42/43은 기존 모든 성공 기준과 자동 검증 항목을 통과했다. seed44/45는 목표 구역까지 운반했지만 방출 전에 종료했으므로 inside/stable 같은 개별 평가 값이 참이어도 성공으로 세지 않는다. seed45는 목표 근처에서 그립 재확인도 반복했다. seed46은 첫 주행 후 파지 확인에 실패하여 정지했다. 파지 검증 기준이나 예산을 완화해 성공으로 바꾸지 않았다.

모든 실행에서 자체 RGB 해시, 실제 모델 응답·사용량 정산, 소스 및 예산 일관성, 종료 후 무동작 검사는 통과했다. 실패한 세 실행의 전체 명령 흐름·방출 성공 검사는 실패로 남았다. 모델 요청 NAV 99장과 영상 표본 60개, 성공 실행의 최종 손목 영상을 직접 검토했다. 전체 7,800프레임을 디코딩했고, 연속 전체 영상의 수동 검토는 하지 않았다. 실행별 `manual-review.json`, `automated-verification.json`, `review-data.json`과 두 검토 시트를 보존했다.

관련67개/하위4개 및 Gemini 실행·예산·정책83개/하위26개 검사는 최종 코드에서 통과했다. 최종 문서·소스 정리 후 `git diff --check`를 확인했다. M4 세션 래퍼가 정상 종료했고 해당 프로세스 그룹과 실험 자식 워커가 남지 않았음을 확인했다. 결과는 로컬에 저장했다.

남은 개선점은 운반 중 그립 안정성 및 재확인 비용, 목표 경계 안쪽 진입 판단의 호출 효율이다. 알려진 색·치수, 보정된 카메라와 평탄 바닥이라는 현재 가정 밖의 검출 및 실제 MasterPi 검증은 별도 실험이 필요하다.
