# 2026-09-25 구역 협업 한국어 대화 오프라인 파일럿

**결론: 전체 한국어 프롬프트(V2)에서 로봇 메시지는 한국어로 안정적으로 나왔다. 그러나 claim 결정 10개 중 4개가 V0와 달라졌다. 다턴 창에서도 서로 묻고 답하는 협상은 거의 없었다.** 충돌 회피는 차례대로 말하는 구조에서 나왔고, 한국어 여부와는 무관했다. 이 결과는 언어·형식 지표일 뿐이며 **작업 효율의 증거가 아니다.** SIM을 돌리지 않았고, 바뀐 결정도 실행하지 않았다.

- 브랜치: `claude/zone-dialogue-ko-pilot` (기준 main `0add360`), Draft PR #172
- 범위: **오프라인**. SIM 실행 없음. 실행기(`run_zone_dispatch.py`, `zone_teacher.py`, `zone_coordination.py`, `zone_solo.py`) 변경 없음. 실행 번들 등록부 변경 없음. TensorBoard 없음.
- 모델 호출: HTTP 시도 **124회**(예산 150), 재시도 0, 전송 오류 0. 입력 837,920 / 출력 21,201 / total 886,236 토큰(모두 실제 usage 필드 값).

M1과 M3는 V3로도 돌렸다. 발언 순서는 고정 순환이고, 시작 로봇은 창마다 돌렸다. 각 로봇은 자기 원래 요청(이미지·user JSON)에 `dialogue_window.received/sent`를 추가로 받았다. 호스트는 지정한 수신자에게 전달만 한다. 중재하거나 claim을 고치지 않는다. 동시에 답하는 상황이 아니므로 C2 타이브레이크는 뺐다(추가하지 않는다는 원칙에는 어긋나지 않는다).

규칙 기반 다중 라벨(`harness/zone_dialogue_metrics.py`)과 수동 라벨을 비교했다. 표본 20개는 V1/V2 단일 턴과 V2 창에서 seed로 뽑았다. 정확히 일치한 것은 **18/20**이었다(`manual_labels.json`). 규칙이 놓친 것은 제출형 `propose`와 권유형 `request`였다. 수동 라벨은 파일럿 작성자가 붙였고, 변형을 가리지 않았다(비맹검). 영어(V0) 메시지는 `proposal` 단어 때문에 `propose`가 과다 집계되므로 행위 분포를 비교할 때 주의한다.

## 6. 실행기 통합 권고(이 수치 기준)

1. **프롬프트:** C 조건은 **V2(전체 한국어)**로 고정한다. V1보다 한국어 준수율이 높고(19/20 대 16/20), 코드 전환(1 대 4)과 ID 오류(0 대 1)가 적으며, reason도 한국어였다. 단, claim 결정 분포가 V0와 달라진다(6/10 동일). 따라서 **A·B도 같은 한국어 과제 설명을 쓰고 메시지 형식만 바꿔야** 언어 효과와 통신 효과가 섞이지 않는다. B는 V3 스키마를 한국어 과제 설명 위에 붙이는 형태를 권한다. 호스트가 만드는 user JSON의 영어 문자열(`rgb_view.source`, `executor_receipt`, 기록된 영어 peer 메시지)은 이번에는 그대로 두었다. 통합할 때 번역하거나 literal 코드로 바꿀지 정해야 한다.
2. **턴·길이 한도:** 창당 6발화, 로봇당 2발화면 충분했다. 실제로 새 정보가 담긴 발화는 로봇당 1회였고, 두 번째 라운드는 침묵이거나 반복이었다. 단일 턴 V2 메시지는 최대 114자였고, 창의 턴당 평균 출력은 121–156토큰(reason·claim JSON 포함)이었다. 따라서 **발화당 240자(검증 상한 600자 유지), 출력 256토큰**이면 여유가 있다. 한도 도달 시 호스트 합의 생성 금지는 유지한다. 비용은 이미지 재전송이 좌우하므로, 창 안의 두 번째 턴에 이미지를 다시 보낼지는 조건 공통으로 따로 정해야 한다.
3. **사건 기반 훅:** 기록에는 할 일이 남은 3로봇 동시 결정이 첫 라운드뿐이어서, 사건 트리거는 이 파일럿에서 검증하지 못했다. 설계안대로 (a) 자기 RGB 정체·파지 후 영상 불일치, (b) 집결 대기 초과, (c) **실제 수신 메시지**로 창을 열고, 동료 작업 종료가 전원을 깨우지 않게 한다. 사건 발생을 호스트 정답으로 알려서는 안 된다.
4. **지표 파이프라인:** `harness/zone_dialogue_metrics.py`(한글 비율, 코드 전환, ID 오류, 행위 라벨, 상대 언급)와 이 분석의 usage 집계를 평가 전용 출력에 연결한다. 미보고 토큰(total−prompt−completion)을 별도 열로 둔다. 직렬 발언 순서 자체가 충돌을 줄이므로 **A에도 같은 순서·창 구조를 주거나, 동시 응답을 공통으로 유지**해야 C−A가 언어 효과만 반영한다.

## 7. 검증하지 않은 것

- 작업 효율, 완료율, makespan은 측정하지 않았다(SIM 없음, 바뀐 결정을 실행하지 않음).
- 표본이 작다(단일 턴 변형당 20개, 창 6개). V0 반복은 8쌍뿐이다. plan 결정 변화는 기준 잡음과 구분할 수 없다.
- 미보고 토큰이 0이 되는 원인(숨은 추론 여부)은 확인하지 않았다.
- 사건 기반 창, 이동 중 발화, 미지 장애물, 2로봇 직접 전달 상황은 기록에 없어서 검사하지 않았다.
- 수동 라벨은 한 명이 비맹검으로 붙였다.
- 원시 wire(이미지 포함 요청 본문)는 worktree의 `outputs/zone-dialogue-ko-pilot-20260925/`(gitignore)에만 있다. 원격 백업은 없다. 커밋된 `calls.jsonl`에는 프롬프트 전문, 이미지별 SHA-256, 응답 HTTP 본문 원문, usage, wire SHA-256, 원시 파일 경로가 모두 들어 있다. 원본 이미지는 기본 체크아웃의 ZC2 요청 파일에 있으며 해시로 연결된다.

- `sample.json`: 선택한 결정 지점, 원본 파일 해시, 원래 결정·usage·설정
- `calls.jsonl`: 모든 HTTP 시도 124건(프롬프트 전문, 이미지 해시, 응답 원문, usage, 원시 경로). 커밋 시점 SHA-256은 `results.json.calls.calls_jsonl_sha256`에 있다.
- `dialogues.json`: 창별 턴, 전달 기록, 최종 claim
- `results.json`: 평가 전용 집계(변형별 표, 재생 대조, 충돌 쌍, 창 요약, 행별 지표)
- `manual_labels.json`: 수동 행위 라벨 20개

```
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py select     # 표본(결정적)
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py single     # 88회, 동시 2개
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py dialogue   # 36회, 순차
.venv-sim-worker-mac/bin/python scripts/pilot_korean_dialogue.py analyze
```

재실행하면 `calls.jsonl`에 이미 있는 호출은 건너뛴다. 예산(`--max-calls 150`)을 넘을 계획이면 호출 전에 멈춘다.
