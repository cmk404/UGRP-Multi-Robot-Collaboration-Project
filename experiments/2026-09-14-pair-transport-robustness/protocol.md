# 2026-09-14 공동 운반 잔여 실패 수정

사용자 요청: 남아 있는 방향 추정·정체·파지 상실 감지·가림 실패를 수정하고 실제 지형에서 검증한다.
baseline은 `2026-09-14-pair-terrain-trials`(완주 0/5), 직전 비교는
`2026-09-14-pair-vision-recovery`의 두 후보(각 완주 1/5, 차단 정지 1/1)다.

## 후보와 고정 조건

- `--vision-mode robust`: 네 바퀴의 노란 픽셀 군집·사각형으로 방향/중심을 추정한다.
  고정 템플릿은 최초 로봇 식별에만 사용한다. 네 군집의 크기·거리·연속성을 함께 검사한다.
- 로봇 사이 검색 구역에서 실제 주황색 빔 픽셀의 긴 변을 읽는다. 로봇 위치만으로 짐을
  관측했다고 간주하지 않으며 빔 픽셀이 사라지거나 방향이 불확실하면 공동 정지한다.
- 자기 RGB에서 가까운 빔이 가로로 넓게 보이는 실루엣이 사라지면 `grip_stop`한다.
  접촉을 인증하거나 파지를 자동 복구하는 센서가 아니며, 시각적인 운반 지속 조건이다.
- 실제 관측의 경유점 진전이 10초간 개선되지 않거나 한 구간에서 36초가 지나면
  관측된 현재 자세에서 경로를 다시 계산한다. 새 경로·버전에 두 로봇이 동의할 때까지
  공동 정지하며 최대 두 번 뒤에도 정체하면 종료한다. 기존 경유점 오차 기준은 유지한다.
- 입력은 각자의 자기 RGB, 공용 top RGB, 사전 지도·고정 카메라 보정뿐이다.
  초기 물체 길이·바퀴 외관은 기존 모델을 유지한다. 라이브 정답·접촉·관절·평가 입력은 금지한다.
- 지도·목적지·A* 비용·footprint·경유점 기준·운동 gain·grasp 모델·카메라/FOV·외관·물리 설정
  변경 없이 impratio=10, noslip_iterations=0, weld OFF, 파지 후 8초 대기,
  최대 750회(0.2 SIM초) 판단, trial당 wall 600초를 유지한다.

## 진단과 최종 비교

1. 기존 RGB만 재생해 방향·가림 처리를 확인하고 자기 RGB 파지 이상 감시를 별도 검사한다.
   재생에 변경된 행동을 실행한 의미를 부여하지 않는다. 실제 실패 이미지와 RGB에서만
   만든 직전 상태를 fixture로 보존한다.
2. 코드·프로토콜·필수 검사를 커밋한 후 S자·L자·우회 분기를 진단한다.
   필요하면 원인을 좁혀 후보를 수정하고 새 SHA에 새 출력 폴더를 연결한다.
3. 최종 SHA에서 전체 카탈로그 6조건을 각 1회 실행한다. 조건당 1회 고정 시작 결과를
   일반화 성공률로 표현하지 않는다. 성공한 좁은 문도 회귀 검사에 포함한다.
4. 운반 내내 양면 파지·높이·수평·벽/기타 접촉·지도 경계, 목표 위치/방향, 실제 내려놓기,
   weld OFF·불변 설정을 기존 평가기로 판정한다. 실패와 부분 진행도 모두 기록한다.
5. 모든 입력/명령/공동 허가를 저장된 RGB로 재계산하고 grasp 입력 감사도 수행한다.
   모든 지형의 시작·중간·종료 관찰 영상과 주요 전환 장면을 직접 검토한다.

실행 코호트마다 SHA·설정·모델 파일 해시·명령·전체 결과·시간·행동 수를 보존한다.
LLM 호출/토큰/비용은 0이다. 실행 wall 시간에는 렌더링·입출력이 포함된다.
raw는 로컬 outputs에 보존하고 선택 영상·요약·출처 해시를 Git에 저장한다.
완료 시 해당 실험 세션과 자식 프로세스를 정리한다. main 병합은 별도 승인 대상이다.
