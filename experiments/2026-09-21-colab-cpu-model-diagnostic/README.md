# Colab CPU 모델 연결 진단

사용자 승인한 다음 단계: GPU 배정과 별도로 CPU에서 규칙/Jev/Gemini의 영상·실제 응답·명령·결과 회수 경로를 확인한다. 기존 231회 비교(110회 회수/121회 미완료), 기존 Kaggle 108회 작업의 소스·조건·분모는 변경하지 않았다.

실행 소스: `8baa01f39a15321d33847a7d6c402f42b2d561b8`. CPU 세션 한 개, OSMesa/실제 Mesa llvmpipe, 기존 960×720 카메라/FOV 유지, weld OFF. `dev_open`, full, paused를 각 1회 실행했다. 제어 구간 목표 4초, 소프트 벽시계 한도 150초, 자식 프로세스 최대 180초, 모델 최대 2회/정책, HTTP 요청당 1회로 고정했다. 소프트 한도는 단계 사이에 확인하므로 마무리 촬영·정리까지 포함한 실제 시간은 이를 넘는다. 실패·시간 초과 후에도 다음 정책을 실행한다.

| 정책 | 실행 시간 | 모델 호출 | API 응답 시간 | 결과 |
|---|---:|---:|---|---|
| 규칙 | 165.89초 | 0 | 해당 없음 | 시간 한도 |
| Jev | 165.63초 | 2 | 0.43 / 0.54초 | 시간 한도 |
| Gemini | 169.91초 | 2 | 4.37 / 5.41초 | 시간 한도 |

세 실행 모두 실제 RGB 쌍 7개, 발행 명령 14개, 모델 응답 파싱(모델 정책만), 카메라 불변, weld OFF, 영상 저장을 확인했다. 자체 평가 성공은 모두 false다. 초기화/탐색 동작을 포함한 SIM 시각은 각 5.55초이며, 실제 제어 구간 4초를 모두 수행한 것이 아니다. `ready=true`는 실행 연결 검사 통과이며 과제 성공이나 충분한 처리 속도가 아니다. **현재 CPU 설정은 대량 코호트 실행 대상으로 부적합하다.** 한 번씩의 짧은 진단을 실패율·모델 순위에 넣지 않는다.

사전 연결 검사는 Jev/Gemini 각 3/3, 실제 요청 6회·최초 오류 0회다. 로봇 실행 중 실제 모델 호출은 별도 4회, 최초 오류/재시도 0회이며 응답 4개 모두 전달했다. Jev의 파일 중계 포함 대기는 4.52/2.16초, Gemini는 4.98/5.93초였다. 빠른 API 응답을 전체 시뮬레이션 속도로 표현하지 않는다.

원격 작업 본체 506.95초, 준비·회수·정리를 포함한 제어기 전체 589.48초. ZIP 및 내부 186개 파일의 해시와 실행 SHA를 Mac에서 재검증했다. 영상 3개는 각각 H.264 960×720, 34프레임/4.25초이며 영상 파일 시간과 SIM 절대 시각은 다르다. 모든 원본 성공/실패·요청/응답·사후 판정은 보존했다. 결과 회수 뒤 소유 Colab 세션과 중계/프록시를 종료했고 서버 할당 0개·8391 포트 미사용을 확인했다.

관련 로컬 검사 14개와 subtest 7개 통과. 실제 실행 소스의 GitHub CI는 6종류 모두 통과했다(push/PR 총 12개). 새 CPU 회귀 검사를 공통 CI 목록에도 등록한다. 대시보드 변환 및 실제 화면 검증 기록은 `verification.json`의 `dashboard_evidence` 경로에 저장한다. CPU 진단과 연결 검사를 별도 `0921-CPU진단` 스냅샷으로 표시하며 기존 비교 결과와 합산하지 않는다.
