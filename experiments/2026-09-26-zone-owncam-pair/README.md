# 손목 카메라만으로 두 로봇 long_beam 공동 운반: 타당성 연구 (2026-09-26)

## 요청과 범위
- 코디네이터 요청(2026-09-26): 로봇 2대가 각자 자기 `robot_cam`(손목 fisheye)만으로 long_beam(0.60 m, 0.30 kg)을 옮길 수 있는지 본다.
  1. 손잡이·스테이션 정렬
  2. 공유 카메라 없는 파지 동기화: 자기 발행 명령 타이밍과 승인된 message/wait 프로토콜(`PairCarrySync`)만 쓴다.
  3. 들보가 시야를 가리는 상태에서 대형 유지 운반
  4. 동기화된 내려놓기
- 기존 공동 운반은 모두 TOP 카메라를 썼다(robust 5/5, dispatch). 이번에는 TOP·nav_cam·GT를 제어에 쓰지 않는다.
- 조건
  - 열린 바닥(`zone_wide`, 경계벽뿐)에서 한다.
  - `cargo_noslip_v1`이 주 조건이며 **사용자 결정 대기** 표시다. weld OFF.
  - Kiro B2의 팀 화물 부분 가시 인식 브랜치(`kiro/zone-own-perception(-v2)`)는 작성 시점에 원격에 없었다. 그래서 인식은 stub(`harness/owncam_pair_beam.py`: 라임 색상 + 발행 PWM 카메라 FK + 들보 윗면 평면)으로 대신했다.
- **M1이 아니고 성공 주장이 아니다.** 타당성 판단용 소규모 코호트다.

## 입력 경계
- 각 로봇이 쓰는 것
  - 자기 `robot_cam` JPEG와 자기 발행 PWM
  - 작업 시트(역할 end_neg/end_pos, 경로 다리 axial 0.60 m → lateral 0.30 m, 속도 0.06 m/s)
  - `PairCarrySync` 장벽. 보고에는 자기 프레임 id, 준비 여부, 이유를 담고, TTL은 1 s다.
- 쓰지 않는 것: 상대 영상, TOP, GT pose, 접촉. GT는 `evaluation-only.jsonl`에만 쓴다.
- `stub_approach` 조건
  - 스테이션 0.30 m 뒤 pre-station까지만 **GT P 제어**로 접근하고, 이 구간을 표시한다.
  - 시작은 0.8 m 더 뒤에서, ±0.6 rad 돌린 상태로 한다. 그 뒤는 `own_only`와 같다.
- 정적 보정 1개: 적재 운반 주행 척도(axial 0.772, lateral 0.697)
  - dev 601 GT 이동량에서 한 번 구한 정적 상수다(카메라 보정과 같은 지위). 실행 중 GT는 쓰지 않는다.
  - 결과 파일에 출처를 기록한다(`carry_odometry_calibration`).

## 타당성 보고: 실패 모드 먼저
1. **자기 시야 정렬의 자세 사각지대(6개 중 5개 실행, 결정적 실패).**
   - 파지점 거리 0.31–0.34 m에서 다음이 반복됐다. SEARCH에서는 끝이 보인다 → 가까운 자세 p45로 전환 → p45는 끝을 잘린 것으로 본다(가까운 끝을 0.252 m로 읽음, SEARCH는 0.317 m) → 다시 SEARCH. 이동 명령 없이 24–36회 되풀이했다.
   - 추정 원인: 가파른 p45 시야에서 라임 **끝 옆면**이 윗면 평면으로 투영되며 가까이 당겨져 유효 영역 경계에 닿는다.
   - dev 601/602와 614는 이 구간을 통과했다. 그래서 시작 오프셋과 yaw에 민감하다. dev 2개로는 드러나지 않았다.
2. **장벽 프로토콜에 생존 신호가 없다.**
   - 정렬 중인 상대는 lift 장벽에 보고하지 않는다. 먼저 파지한 로봇은 20 s 뒤 `BARRIER_LIFT_TIMEOUT`으로 포기한다. 정렬 한도는 60 s다.
   - 대기 한도는 상대의 "살아 있음, 아직 준비 안 됨" 보고가 이어지는 동안 연장돼야 한다.
   - 조기 중단 자체는 안전 측이다(한쪽만 들어 올리지 않았다).
3. **운반 중 손목 시야는 사실상 눈이 먼 상태다.** 들보 아래 가장자리 띠와 바닥뿐이라 진행 거리를 볼 수 없다. 운반은 발행 명령 타이밍 기반 개루프다.
   - 무부하 이득으로는 23–30 % 이동이 부족했다(601 오차 0.164 m).
   - 정적 보정(dev 601 GT에서 1회) 뒤에는 0.026 m(602), 0.035 m(614)였다.
   - 경로·하중·바닥이 바뀌면 보정이 유효하다는 증거는 없다.
4. **들고 있음 판정의 명암 민감성**: 얇은 띠의 IoU는 미끄러짐 없이 0.46까지 떨어진다. 띠 존재 비율로 대체했다. 614에서 비율 최소 0.996, 실제 낙하 음성 시험은 아직 없다.

**되는 것** (정렬이 수렴한 3회: 601, 602, 614)
- 자기 시야 정렬 오차: x ≈ +1.1 cm(과소 추정 편향), 횡 ≤ 5 mm, yaw ≤ 1.9°.
- GT 양손 파지(손가락 5.5 N).
- 장벽 동기화: 시각 차이 ≤ 0.1 s, 상대 영상 없이 자기 프레임 id 보고만 사용.
- 대형 운반: 쌍 거리 ±1 mm, 기울기 ≤ 0.55°.
- 동기 내려놓기와 해제.

**결론**
- 조건부 타당하다. 파지 후 단계(동기화·대형·내려놓기)는 손목 시야와 장벽만으로 작동했다.
- 병목은 ① 접근 자세 설계(인식 stub의 끝면 투영)와 ② 장벽 생존 신호다.
- 운반 진행 감지는 손목 시야로는 불가하다. 정적 보정 또는 다른 자기 센서(발행 명령 적분 외)가 필요하다.

**다음 버전 후보** (새 seed로만 평가, 이번 결과는 바꾸지 않음)
- p45 대신 끝면을 제외하는 인식(윗면 색 영역만, 또는 끝면 높이 모델)을 쓴다. 또는 "끝이 보이는 자세를 유지하며 전진"하고, 잘림은 거리 감소 뒤에만 가까운 자세로 재시도한다.
- 장벽 대기: `aligning` 상태 보고를 TTL 안에서 받는 동안 한도를 연장한다(상대 정렬 한도 + 여유).
- 실제 낙하 주입으로 띠 비율 음성 시험.
- Kiro B2 부분 가시 인식이 올라오면 stub 대신 쓴다.
