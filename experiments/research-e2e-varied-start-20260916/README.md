# 다양한 출발 배치의 전체 공동 운반 E2E 검증

**19개 출발 배치 × 로컬/LLM 두 조건, 총 38회: 로컬 15/19, LLM 15/19 성공.**
거리만 바꾼 배치는 통과했지만 일부 큰 각도와 혼합 배치는 파지 전 영상 정렬에서 중단됐다.
파지 단계까지 진행한 15개 배치는 두 조건 모두 운반·내려놓기·해제까지 완료했다.

각 조건은 한 번씩 실행했다. 19개의 선택 배치에 대한 공학적 검증이며, 전체 출발 공간의
성공률이나 반복 실험 신뢰구간이 아니다. 범위 안의 모든 조합이 성공한다는 뜻도 아니다.
거리와 좌우 값은 시연 파지 위치로부터의 초기 world x 후퇴량과 world y 편차다.
각도는 로봇의 초기 yaw이며 정책 카메라의 설치 위치·FOV를 바꾸지 않았다.

## 병목과 다음 수정 후보

실패 8회는 모두 `fine RGB alignment failed`다. 실제 운반 중 낙하나 방출 실패가 아니라
파지 이전의 영상 지원 범위 검사에서 중단됐다. 실패를 없애려고 판정 기준을 완화하거나
실험 중 제어기를 변경하지 않았다. [출력 전용 사후 진단](failure-drift-diagnostics.json).

| 실패 배치 | 초기 좌우 cm | 먼 거리 전진 직후 좌우 cm | 실패 단계 |
| --- | --- | --- | --- |
| yaw-opposed10 | 0/0 | +7.25/−7.21 | 좌우 |
| mixed-far-mild | +3/−3 | +7.31/−6.38 | 좌우 |
| mixed-near-wide | +6/−6 | +7.93/−7.55 | 방향 |
| mixed-far-wide | −6/+6 | −14.58/+15.09 | 방향 |

현재 먼 거리 접근은 방향을 보정하기 전에 전진한다. 초기 yaw가 있으면 그 전진으로
옆 편차가 누적되고, 근거리 모델에 넘기는 장면이 학습 지원 범위를 벗어날 수 있다.
`yaw-opposed10`의 r1은 방향 보정 뒤에도 영상 잔차 28.00이 허용 한계 19.66을 넘었다.
반대 부호의 10° 배치는 성공하므로 단순한 각도 절댓값 하나로 성공 범위를 정할 수 없다.

**후속 수정 우선순위:** 먼 거리 RGB에서 방향을 먼저 추정·보정하는 기능을 확장하고,
전진 중 방향·좌우 편차를 계속 확인해 근거리 모델이 처리할 수 있는 장면으로 진입시킨다.
기존 근거리 방향 모델을 처음부터 호출하는 순서 변경만으로 충분하다고 단정할 수 없다.
[저장된 시작 영상으로 재계산](offline-initial-heading-check.json)했을 때 60–70 cm의
여러 시작 장면에서 기존 방향 모델 자체가 지원 범위를 벗어났다. 30 cm 큰 혼합 배치는
처음에는 방향 추정이 가능했지만 전진 후에는 불가능해졌다. 이 재계산은 오프라인 진단이며
새 제어기로 실제 성공한 결과가 아니다. 수정 뒤에는 같은 38회 비교를 다시 해야 한다.

## 입력 경계·검증

- 실행 코드는 `fd5d68ee41bc56c8b61d1f020f5891b218e36ef0`로 고정했다. 38회 중 소스·모델·설정을 바꾸지 않았다.
- 기존 제어 알고리즘, 학습 모델, 시연 팔 명령, 물리 성공 기준은 유지했다. 추가한 것은
  출발 yaw/좌우 설정과 코호트 실행·기록이다. 기존 근거리 실행기의 기본 45 cm 제한은 유지한다.
- 출발 수치는 장면 초기화와 출력 전용 기록에만 사용한다. 로봇의 입력은 기존 자기 RGB·
  공용 TOP RGB·발행 명령 이력·상대 영상 설명이며 실시간 좌표·접촉·관절 측정은 제외한다.
- 38/38 입력 재생 감사 통과: 이미지·모델 해시, RGB 판단, 발행 명령, 278개 실제 모델
  요청·응답 및 출력 전용 평가를 대조했다. 운영체제 수준 격리 검증은 아니다.
- 전 실행에서 접근 화물 충돌 0, weld 활성 0. 카메라 설치/FOV·형상·마찰·질량은
  각 실행 전후 및 38회 사이에 동일했다. 성공 실행의 목표 오차는 1.69–1.87 cm다.
- 설정한 출발 배치와 최초 평가 위치의 차이는 최대 약 3.43μm, yaw 차이는 약 1.37e−9°다.
  이는 초기화가 적용됐는지 확인한 값이며 운행 중 위치 추정 정확도가 아니다.
- [짝지은 실행 대조](setup-and-pair-verification.json): 시작 RGB는 18/19 배치에서 바이트까지
  같았다. `mixed-near-mild` TOP은 691,200픽셀 중 52픽셀이 달랐으며 발행 명령과 물리 결과는
  같았다. [영상 차이 수치](paired-rgb-difference.json). 렌더 차이의 원인은 따로 확정하지 않았다.
- 자동 회귀 730개 + 하위 검사 154개 통과([로컬 로그](local-tests.txt)). 실행 커밋의
  GitHub offline-regressions·ubuntu-simulation·individual-proxy-bootstrap도 통과했다.
- 38개 영상에서 각각 균등 추출 8프레임(총 304프레임), 실패 4배치의 초기 TOP과 마지막
  TOP·자기 카메라를 검토했다. 실패 배치의 대응 LLM 영상 입력은 동일 해시였다.
  [검토 범위와 선택 프레임](visual-review.json). 모든 영상 프레임을 검수한 것은 아니다.

## 보관과 해석 범위

전체 raw 약 1.19 GB는 `results.json`의 `raw_root`에 명시한 로컬 경로에 보관한다.
Git에는 설정·전체 결과·원본 해시·대표 성공/실패 영상·검토 자료를 저장한다.
원본 해시 목록은 raw 전체의 원격 백업이 아니다. Google Drive는 사용하지 않는다.
이 작업에서 시작한 시뮬레이션 세션은 완료 후 종료됐고 기존 공유 프록시는 유지했다.

고정 평지·물체·역할·단계 순서, RGB 바퀴/파지 보정과 시연 팔 명령의 결과다.
LLM은 제시된 스킬 실행을 허가한다. 자유로운 계획·역할 재배치, 다른 물체·지형·조명,
실물 로봇, 실시간 추론 지연 중 하중 유지, 실패 후 재파지의 검증으로 확대 해석하지 않는다.
이번 목적은 기존 후보의 범위를 측정하는 것이며, 발견된 정렬 병목은 아직 수정하지 않았다.
