# 목적지·지형 변화 E2E 검증

**기본 목적지 A만 완주했다. 목적지 B는 빔 영상 인식에서, 장애물·지형 4개 조건은 통로 폭 검사에서 정지했다.** 각 조건 1회인 탐색 검증이며, 1/6을 일반적인 성공 확률로 해석하지 않는다.

## 조건과 결과

실험 전에 `protocol.json`과 코드를 커밋했다. 6개 실행 모두 소스 `43e60e09ffa85a2334b0ef2acdb5144109b83818`, seed 11, 동일한 접근/파지 모델, `local_contact` 물리 프로필을 유지했다. 역할·경로·의존성은 세 LLM이 새로 합의했고 목적지만 `--required-dock`으로 지정했다. 계획 재생이나 원시 명령 대체는 사용하지 않았다. 통신·실행을 포함한 실제 경과 시간이다.

| 실행 | 환경 / 목적지 | 공동 계획 | 실제 E2E | 시간 | 최초 중단 지점 |
|---|---|---|---|---:|---|
| V1 | open / A | 합의 | 성공 | 299.32초 | 두 화물 운반·방출·안정 완료 |
| V2 | open / B | 합의 | 실패 | 190.92초 | 빔 운반 중 TOP 영상 인식 중단 |
| V3 | 중앙 고정 장애물 / A | 합의 | 실패 | 94.58초 | 북쪽 통로 폭 검사에서 실행 거부 |
| V4 | 지도에 없는 북쪽 장애물 / A | 남쪽 우회 합의 | 실패 | 153.01초 | 남쪽 통로 폭 검사에서 실행 거부 |
| V5 | 좁은 남쪽 통로 / A | 북쪽 경로 합의 | 실패 | 37.09초 | 북쪽 통로도 폭 부족으로 실행 거부 |
| V6 | 남쪽 요철 / A | 북쪽 경로 합의 | 실패 | 45.28초 | 북쪽 통로 폭 검사에서 실행 거부 |

V3~V6은 자기 식별용 움직임 후 운반 명령이 발행되지 않았다. 요철·협소 구간까지 도달하지 못했으므로 실제 통과 성능은 판정할 수 없다. V4 장애물은 시작부터 존재하며 지도에만 빠져 있다. **주행 도중 장애물 생성이나 실행 중 재합의는 시험하지 않았다.** V3/V4의 실제 모델용 작업 설명·지도는 완전히 같고, 시뮬레이션 배치만 다름을 확인했다.

## 물리 결과와 실패 원인

V1은 빔 1.702m, 상자 2.369m를 옮겼다. 두 화물 모두 들림이 관측됐고 선택된 슬롯 내부에서 바닥에 지지되고 로봇과 접촉하지 않은 채 약 1초간 안정했다. 프로토콜 완료와 독립 물리 평가가 함께 통과했다. 이전 F1과 같은 계획에 새로 합의해 기본 조건을 재현한 것이며, 새 시작 위치에 대한 일반화는 아니다.

V2의 목적지는 A에서 남쪽으로 1.32m 이동한 B다. 빔은 1.267m 이동했으나 지정 슬롯에 도착하지 못했고 상자는 집기 전 대기했다. 실제 마지막 입력 `rgb/pair-303-carry-top.jpg`에서 빔의 주황·노랑 색상 덩어리가 노란 바닥 표시와 연결됐다. 이전 프레임에서는 약 19×98px 빔을 분리했지만 실패 프레임에서는 251×274px 배경과 합쳐져 형상 필터를 통과하지 못했다. `canonical_pair_top → beam_feature`에서 예외가 발생했고, 마지막 물리 평가에서는 빔 높이 약 0.093m로 들린 상태였다. 별도 저장 영상에서 이를 확인했다. 두 프레임의 원본 검출 결과는 `evidence/V2/beam-recognition-diagnostic.json`이다.

V3~V6은 기존 평행 운반 대형의 보수적 폭 0.93m보다 통로가 좁다. 기본 북/남 통로는 0.685m이며 V5 남쪽은 0.39m다. 로컬 실행기가 `PAIR_ROUTE_TOO_NARROW`로 정지했다. V4의 실제 모델 응답은 지도에 없는 북쪽 장애물을 영상에서 인식하고 남쪽 우회를 제안했지만, 그 남쪽 경로도 물리 실행 스킬이 지원하지 않았다. 현재는 이 거부를 전달해 다시 합의하는 실행 루프와 회전/재파지 스킬이 연결되어 있지 않다.

모든 조건에서 weld 0, 장애물 접촉 0, 카메라/FOV 불변이다. 이는 거부된 환경의 안전한 통과를 뜻하지 않는다. 물리 프로필은 이전 F1과 같은 수치 시뮬레이션 조건이며 실물 하드웨어 성능을 뜻하지 않는다.

## 검증과 보관 범위

- 로컬 필수 검사: 816 passed + 154 subtests. 실험 소스 커밋의 GitHub push/PR 검사 6개도 통과했다.
- 전 조건의 실제 계획 요청·전송 메시지 총 75개를 원본 RGB·정적 지도·자기 명령·동료 메시지로 재구성했다. V3 1건, V4 2건의 프록시 60초 시간 초과가 있으며 이후 합의했다. 토큰 합계는 공급자가 보고한 값만 포함한다.
- V1/V2는 각각 접근 예측 242개, 파지 예측 32개를 동일 입력으로 재생했다. 상자 결정도 각각 517개/173개가 원본 RGB·자기 발행 명령·기록된 자원 대기에서 동일하게 재생됐다. 입력 감사는 물리 성공 평가를 대체하지 않는다.
- 영상 6개 전체 2,640프레임을 디코딩했다. 실제 눈으로 확인한 프레임과 최종 장면 범위는 각 `video-qa.json`에 명시했다. 모든 프레임을 눈으로 검사했다고 주장하지 않는다.
- `results.json`: 모든 조건의 계획, 실패, 시간, 로봇별 장면 명령·상자 매크로/원시 명령·판단 수, 모델 요청 수·토큰, 평가 결과. 서로 다른 단계의 명령 수는 하나의 행동 합계로 더하지 않는다. 금액은 확인할 수 없어 null이다.
- `cohort.json`: 정확한 실행 인자, 시작/종료 시각, 소스, 종료 코드. `frozen-inputs.json`: 모델 파일과 기준 영상의 해시.
- `evidence/`: 원본 결과, 합의 계획, 입력 감사, 장면/지도 해시, 선택한 검토 이미지. `full-reports.json.gz`는 6개 원본 최종 보고서다.
- `raw-manifest.jsonl.gz`: 로컬 원본 경로·크기·SHA256. 대량 RGB와 영상은 로컬 `outputs/dispatch-variation-20260917/`에만 보관한다. 원격 raw 백업은 아니다.
- `lifecycle.json`: 이 작업이 시작한 세션과 자식 프로세스의 종료 확인.

이 실험에서 운반 제어 로직은 수정하지 않았다. 추가한 `--required-dock`은 고정 작업 목적지이며 실시간 정답 정보가 아니다. 역할이나 경로를 지정하지 않고 합의된 계획이 다른 목적지를 선택하면 거부한다. 모델의 역할·경로·의존성 선택은 자유롭게 바뀌므로 모든 하위 명령이 같은 순수 궤적 비교는 아니다.

## 다음 수정 우선순위

1. 빔과 바닥 표시가 겹칠 때 이전 TOP 영상·자기 카메라로 빔을 계속 추적하도록 보완하고, 같은 A/B 조건을 모두 재검증한다.
2. 실행 스킬의 대형·통로 제약을 계획 단계에 연결하고, 실제 장애물을 피할 수 있는 회전/대형 전환 또는 재파지 동작을 검증한다.
3. 실행 중 시각적 장애물 발견 → 정지 → 계획 폐기/재합의 → 재개를 별도로 시험한다.

원본 재현 명령은 `cohort.json`을 따른다. 새 실행에서는 출력 폴더와 세션 이름을 바꿔 기존 증거를 보존한다. 모델은 이전 [스킬 통합 기록](../dispatch-skill-integration-20260917/README.md)의 번들을 사용할 수 있다.
