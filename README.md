## 2. 연구의 핵심 가설

기존 다중로봇 시스템은 중앙 제어기, 좌표·속도 같은 수치 메시지, 고정된 역할 규칙에 의존한다. 이 구조는 정형 환경에서는 효율적이지만, 물체의 무게·크기 변화, 장애물, 미끄러짐, 목표 변경처럼 맥락 판단이 필요한 상황에서 유연성이 제한된다.

이 연구는 각 로봇이 동일하거나 동등한 조건의 LLM 에이전트로 동작하고, 다음 정보를 자연어로 주고받는 분산 구조를 검증한다.

1. 현재 관측 및 로봇 상태
2. 단독 처리 또는 협력 처리 판단
3. 역할 제안과 상대 로봇의 동의
4. 실행 중 발생한 이상 상황
5. 예외 이후의 재계획 및 역할 재할당

자연어의 장점은 단순한 값 교환이 아니라 작업 의도와 상황 맥락을 전달할 수 있다는 점이다. 반대로 환각, 교착 상태, 불필요한 통신, 지연과 토큰 비용이 주요 위험이다.

## 3. 원래 제출 연구계획

### 3.1 시스템

원래 계획은 **로봇팔 3대**가 블록을 분류·운반·배치하는 축소 물류 시나리오다.

- 중앙 제어기 없이 3대의 독립 에이전트가 비동기 통신
- 카메라로 물체의 색상·크기·위치 등을 인식
- 물체를 단독으로 처리할지 여러 로봇이 협력할지 에이전트가 판단
- 운반 중 이상 상황을 다른 에이전트에 전파하고 계획을 수정
- 자연어 통신 시스템을 수치 기반 규칙 시스템 및 중앙 제어 시스템과 비교

### 3.2 난이도

| 단계 | 태스크 | 검증 포인트 |
| --- | --- | --- |
| L1 | 작은 블록 단독 분류·이송 | 기본 인식과 단독 작업 계획 |
| L2 | 큰 블록 공동 파지·이송 | 파트너 요청, 역할 합의, 출발 동기화 |
| L3 | 크기가 섞인 블록과 예외 상황 | 단독/협력 선택, 경로 충돌, 재협상과 복구 |

### 3.3 계획된 평가 지표

- 작업 성공률
- 역할 분담 및 파트너 선택 성공률
- 작업 완료 시간 또는 완료 step 수
- 예외 상황 복구율
- 교착 상태 발생률
- 환각·실행 불가능한 행동 발생률
- 통신 turn 수와 LLM 토큰 비용
- 자원 효율 및 동시 추론에 따른 지연

### 3.4 원래 계획의 단계

| 기간 | 계획 단계 | 주요 산출물 |
| --- | --- | --- |
| 2026.05–06 | 로봇·시뮬레이션 환경 구축, 사전 실험 | 환경과 사전 측정 결과 |
| 2026.07–08 | 비동기 통신 프로토콜, 프롬프트, 규칙 기반 baseline | 프로토타입 v1.0 |
| 2026.09–10 | L1–L3 본실험과 데이터 수집 | 실험 데이터셋, 통계 자료 |
| 2026.11 | 통계 분석과 실물 검증 | 분석 보고서, 검증 영상 |
| 2026.12–2027.01 | 보고서·발표·공개 정리 | 최종보고서, 발표 자료 |

위 일정은 연구계획서에 적힌 계획이며, 실제 완료 여부는 별도 실험 로그로 확인해야 한다.

## 4. 연구 방향의 수정안

별도 문서인 `UGRP_수정_연구계획_컴팩트.pdf`에서는 실물 중심 설계를 다음과 같이 전환했다.

- **기존**: 실물 로봇팔 3대 기반 블록 분류·협력 이송
- **수정안**: Isaac Lab 기반 가상 물류 환경에서 휴머노이드 2–3대의 협력 이송
- **유지**: 중앙 계획자 없음, 보조 계획자 없음, 동등한 LLM 에이전트 간 자연어 협상
- **초점 변경**: 보행·관절 제어보다 파트너 선택, 역할 분담, 출발 동기화, 예외 재계획

### 4.1 수정안 시스템 경계

- **환경**: 가상 창고, 상자, 목표 구역, 장애물·로봇 고장 이벤트
- **에이전트**: 각 로봇은 자기 상태와 수신 메시지만 보고 자기 행동을 제안
- **행동 스킬**: `navigate_to`, `approach_object`, `request_partner`, `wait_for_partner`, `start_transport`, `reroute`, `deliver`
- **환경 심판**: 행동 유효성, 충돌, 동기화 실패, 성공 여부만 판정. 계획 자체는 세우지 않음
- **실험**: L1 단독 이송, L2 협력 이송, L3 장애물·고장·목표 변경 후 재협상

수정안은 연구 문제를 더 통제된 시뮬레이션으로 옮기는 장점이 있다. 다만 현재 확인된 자료만으로는 이 수정안이 공식 변경 승인까지 완료됐는지 확인되지 않으므로, **공식 확정안과 구분해 관리해야 한다**.

## 5. 현재 확인된 구현 자산

UGRP 관련 구현 자산은 이 저장소 밖의 기존 프로젝트에 있다.

### 5.1 `decentral-cobot`

위치: `~/Documents/기타/Projects/Antigravity/decentral-cobot/`

현재 확인된 성격은 **연구 시연용 브라우저 sandbox**다.

- 단일 HTML 기반 2.5D 다중 CoBot 시뮬레이터
- 블록 분류, 무거운 물체 공동 운반, 미끄러짐 이상 상황, 토크 경고 시각화
- UGRP 예산·하드웨어 구성 패널
- 처리량, 협력도, payload 동기화, Pareto 차트 등 시각화
- 브라우저 내부 결정론적 상태 머신과 키워드 명령 라우터
- 실제 로봇, 외부 LLM 추론 서버, backend API와 연결되지 않음

중요한 구현 사실:

- 실제 실행 소스는 `index.html` 내부의 임베디드 JavaScript/CSS다.
- 별도 `app.js`와 `style.css`는 존재하지만, 현재 `index.html`이 직접 불러오지 않는 구형 변형이다.
- 따라서 이 자산은 연구 아이디어를 시각화하는 데는 유용하지만, 자연어 LLM 통신 실험이나 Isaac Lab 실험을 이미 구현한 것으로 간주하면 안 된다.

### 5.2 연구계획 생성 초안

`~/Documents/AI/연구/generate_final_proposal.py`에는 또 다른 설계 초안이 있다.

- 이동형 MasterPi 2대
- 판단 에이전트와 실행 에이전트의 비대칭 모델 구성
- 비동기 이벤트 버스와 JSON 메시지
- MuJoCo 시뮬레이션, 클라우드 GPU, 실물 검증
- 모델 조합·성공률·판단 정확도·시간·메모리 비용의 Pareto 비교

이 초안은 평가 변수와 통신 메시지 설계에 참고할 수 있지만, Isaac Lab 휴머노이드 수정안 및 원래 제출계획과 구성이 다르다. 따라서 **현재 연구의 권위 있는 사양으로 자동 병합하지 않는다**.

## 6. 통신 프로토콜 후보

원래 초안에서 확인된 메시지 흐름은 다음과 같다.

| 메시지 | 방향 | 의미 |
| --- | --- | --- |
| `SOLO_ASSIGN` | 에이전트 A → 에이전트 B | 단독 처리 지시와 물체·목표 정보 |
| `COLLAB_START` | A → B | 협력 시작, 파지 위치, 이동 순서 |
| `STATUS_REPORT` | B → A | 진행·완료·저항 감지 등 현재 상태 |
| `ALERT` | B → A | 미끄러짐·장애물·중량 초과 등 이상 상황 |
| `REPLAN` | A → B | 이상 상황을 반영한 수정 지시 |

수정안의 완전 분산 구조에서는 A/B처럼 고정된 판단자·실행자 역할을 두면 안 된다. 이 경우 메시지는 특정 역할이 아니라 `sender_id`, `object_id`, `observation`, `intent`, `proposed_action`, `required_partner`, `ack`, `failure_reason`, `timestamp` 같은 상태·의도 중심 필드로 재설계해야 한다.

## 7. 비교군 설계

수정안 문서가 제안한 비교군은 다음과 같다.

1. 규칙 기반 분산 시스템
2. 통신 없는 LLM 시스템
3. 자연어 통신을 사용하는 LLM 분산 시스템
4. 선택적 비교군: 중앙 계획자 시스템

비교 시 환경 시드, 물체 배치, 장애물 이벤트, 모델 호출 예산, 최대 step 수를 고정해야 한다. 그렇지 않으면 통신 방식의 차이와 환경 난이도의 차이를 분리할 수 없다.

## 8. 이 저장소에서 유지할 기준

현재 자료에는 세 가지 설계가 함께 존재한다.

| 구분 | 기준 | 이 저장소에서의 취급 |
| --- | --- | --- |
| 공식 제출계획 | 3대 로봇팔, 블록 분류·협력 이송 | 기본 연구 배경 및 최초 가설 |
| 수정 연구 방향 | Isaac Lab, 휴머노이드 2–3대, 완전 분산 협상 | 최신 작업 가설. 승인 상태 확인 필요 |
| 기존 구현·생성 초안 | 브라우저 sandbox, MasterPi/MuJoCo 변형 | 구현 참고 자료. 연구 사실과 분리 |

향후 코드를 추가할 때는 위 세 층을 섞지 않는다. 특히 브라우저 시뮬레이터의 결정론적 keyword router를 실제 LLM 자연어 통신으로 표현하거나, 생성된 제안서의 예상 수치를 실험 결과처럼 기록하지 않는다.

## 9. 다음 구현 순서

1. **연구 사양 고정**: 공식안과 Isaac Lab 수정안 중 이번 실험의 환경·로봇 수·에이전트 구조를 결정
2. **공통 태스크 명세**: L1/L2/L3의 초기 상태, 성공 조건, 실패 조건, 최대 step, 이벤트 주입 규칙 정의
3. **환경 심판 분리**: 에이전트가 계획을 대신 얻지 못하도록 충돌·접촉·동기화·성공 판정만 담당
4. **메시지 스키마 확정**: 자연어 원문과 실행 가능한 구조화 행동을 함께 저장하고 파싱 실패를 측정
5. **baseline 구현**: 규칙 기반, 통신 없는 LLM, 자연어 통신 LLM을 동일한 환경에서 실행
6. **실험 로거 구축**: seed, episode, step, 메시지, 행동, 비용, 실패 원인을 재현 가능하게 저장
7. **기존 sandbox 정리 또는 이관**: 시각 데모와 실제 실험 코드를 별도 패키지로 분리
