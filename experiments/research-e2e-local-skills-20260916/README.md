# 영상 기반 공동 운반 E2E 연결

**최종 고정 코드에서 로컬 3/3, 실제 두 LLM 조건 3/3으로 전체 운반에 성공했다.**

| 조건 | 시작 거리 r1/r3 | 이동 | 목표 오차 | 실제 경과 | 바퀴/팔 명령 묶음 | LLM 요청 / 입력 토큰 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| local | 60/60 cm | 48.19 cm | 1.81 cm | 46.20초 | 125/31 | 0 / 0 |
| local | 55/63 cm | 48.29 cm | 1.71 cm | 43.86초 | 130/31 | 0 / 0 |
| local | 65/57 cm | 48.23 cm | 1.77 cm | 43.63초 | 129/31 | 0 / 0 |
| llm | 60/60 cm | 48.19 cm | 1.81 cm | 95.12초 | 125/31 | 18 / 94,105 |
| llm | 55/63 cm | 48.29 cm | 1.71 cm | 98.48초 | 130/31 | 18 / 93,996 |
| llm | 65/57 cm | 48.23 cm | 1.77 cm | 83.05초 | 129/31 | 18 / 93,934 |

명령 수는 정지·대기까지 포함한 양쪽 로봇 명령 묶음이다. LLM 조건은 총 54회 호출했고
추론 중 SIM이 멈춘다. 물리 과정의 SIM 시간은 약 48–49초이며, 경과 시간·영상 길이와 구분한다.

접근 → 파지 준비 → 닫기 → 들기 → 목표 구역 이동 → 내려놓기 → 놓기 → 팔 회수까지
한 실행에서 수행했다. [사전 계획](protocol.md), [전체 시도·환경·원본 해시](results.json),
[대표 실제 실행 영상](transport.mp4), [영상 검토 시트](review-sheet.jpg).

## 실행 방식과 입력 경계

두 로봇은 팔을 접은 채 파지 위치에서 각각 55–65 cm 떨어져 출발한다.
영상 기반 먼 거리 접근, 기존 학습 모델의 근거리 정렬, 영상 정밀 정렬을 거친 뒤
기존 시연 팔 동작과 RGB 파지 보정으로 잡는다. 이동 중에는 TOP에서 물체와 목표를
추적하고 기존 두 로봇 동기화 정책으로 주행한다. 초기 영상에서 본 고정 목표 위치를
기억하므로 로봇에 가려져 초록 영역이 쪼개져도 목적지가 이동하지 않는다.

`--planner llm`은 로봇마다 별도 Gemini 3.8 Flash 요청을 보내 아홉 단계의 실행 허가를
받는다. 현재/이전 자기 RGB·공용 TOP, 자기 발행 명령, 상대의 영상 설명만 받는다.
양쪽 모두 해당 스킬을 confidence ≥0.8로 선택해야 진행하며 HOLD는 최대 세 번
새 영상으로 재확인한다. 요청 오류는 최대 세 번 재시도한다. 실제 전송 본문과 응답을
저장했고 이를 다시 구성해 대조했다. 단계 순서와 r1/r3 역할은 고정이다.

**팔 전개·닫기·들기·내려놓기는 시연 명령이고, 바퀴와 파지 보정은 RGB 피드백이다.**
원시 관절 명령을 LLM이 직접 만들어 성공했다거나 자유로운 계획·역할 협상을 검증한
결과로 해석하지 않는다. 같은 모델의 두 추론이므로 오류가 독립적이라고 가정하지 않는다.
이 실행은 기존 원시 행동 LLM 파일럿과 별도 조건이며, 예전 실패 기록을 대체하지 않는다.

카메라 위치/FOV·외관·형상·마찰·질량을 유지하고 weld를 끈다. 영상은 기존 학습 스킬과
같은 960×720이며 이전 원시 LLM 파일럿의 640×480과 구분한다. 실제 로봇 좌표,
측정 관절, 접촉, 평가 결과를 행동 생성이나 단계 전환에 사용하지 않는다. 로봇 위치는
시작 장면을 구성할 때만 설정하며 접근 도중 순간 이동시키지 않는다.
독립 평가 좌표는 결과 로그와 검토용 영상의 표시만을 위한 것이며 모델 카메라에 없다.

## 발견하고 수정한 병목

1. **분리되어 있던 로컬 스킬:** 먼 거리 접근부터 운반·방출까지 하나로 연결했다.
   9월 10일 학습 모델은 기존 저장소의 `models.zip`에서 새로 풀어 사용했다.
2. **목표 가림:** 첫 후보는 약 42 cm 이동 후 초록 영역 분할 때문에 멈췄다.
   출발 시 허용된 TOP 영상에서 확인한 목표를 기억하도록 수정했다.
3. **하중을 든 채 느린 전진:** 두 번째 후보는 마지막 구간에서 오래 지체하면서 미끄러졌다.
   기존에 시연된 0.04–0.10 주행 명령 범위로 이동하고, 새 영상으로 멈춘다.
   목표를 지나치면 추가 전진하지 않는다. 장시간 파지 유지 문제를 해결했다는 뜻은 아니다.
4. **접근 완료 허용 범위와 팔 보정 범위의 불일치:** 첫 비교 코호트의 (65,57) cm 배치는
   기존 접근 완료 판정에 들어왔지만 r1 팔 보정 영상이 학습 범위를 벗어났다.
   LLM도 이를 허가했고 두 조건 모두 약 8 cm 이동 후 한쪽 파지를 잃었다.
   파지 전에 기존 영상 위치 오차 추정기로 더 정밀하게 정렬하고 두 번 새 영상으로 확인한다.
   ±1 mm는 **영상 추정치의 정지 범위**이며 실제 위치 정확도를 보장하는 수치가 아니다.
   파지 보정 모델이 관측 불가 또는 confidence <0.8이면 CLOSE를 차단한다.
   실패한 같은 배치의 진단 재실행에서 전체 운반 성공을 확인한 뒤 여섯 조건을 재검증했다.

개발 시도 5회와 두 비교 코호트 12회를 모두 보존했다. 개발 중 실패 2회,
첫 비교 코호트 실패 2회도 결과에 포함한다. 서로 다른 코드 버전의 시도를 합쳐
일반화 성공률을 계산하지 않는다.

## 검증 범위

- 최종 실행 코드: `11da61320dbce0dd7894a1e8705e8c756c54069d`.
- 목표 이동 50±3 cm, 2초 양쪽 파지 유지, 운반 중 연속 하중 유지,
  내려놓은 뒤 바닥 지지·로봇과 분리·1초 이상 안정, 목표 구역 안착을 확인한다.
  물리 평가는 약 10 Hz 표본이며 모든 물리 프레임을 검수했다는 뜻은 아니다.
- 접근 중 화물 충돌 0, weld 활성 0, 카메라·형상 불변도 별도 확인한다.
- RGB 판단, 명령 이력, 모델 파일·이미지 해시, 실제 LLM 요청/응답, 바퀴 명령과
  동기화 결정을 재계산한다. 감사는 보관 입력의 재생이며 운영체제 수준 격리는 아니다.
- 새 clone에서 자동 회귀 729개와 하위 검사 154개 통과. 목표 가림·정지 영상,
  목표 초과, 오래된 LLM 답·HOLD·편측 허가, 정밀 정렬, 지원 범위 밖 파지 차단을 포함한다.
- 두 비교 코호트의 각 영상에서 균등하게 뽑은 12프레임과 주요 원본 카메라를 검토했다.
  전체 영상을 프레임마다 사람이 검수했다고 주장하지 않는다.

## 재현

Mac의 기존 시뮬레이션 환경에서 저장소 루트를 기준으로 실행한다. 새 출력 폴더 이름을
사용하고, 실행 전에 변경을 커밋해 작업 트리를 깨끗하게 한다. 모델 프록시는
[프록시 안내](../../docs/gemini_subscription_proxy.md)를 따르며 인증정보는 기록하지 않는다.

```sh
python3 -m zipfile -e experiments/2026-09-10-rgb-varied-start/models.zip outputs/goal-models
.venv-sim-worker-mac/bin/python scripts/ugrp_session.py run goal-transport -- \
  .venv-sim-worker-mac/bin/mjpython scripts/run_camera_goal_transport.py \
  --planner llm --distance .60 .60 \
  --grasp-model-dir outputs/goal-models/models/grasp \
  --stage-model-dir outputs/goal-models/models/varied \
  --reference-top tests/fixtures/camera_goal_transport/reference-top.jpg \
  --out-dir outputs/goal-transport-NEW-ID
.venv-sim-worker-mac/bin/python scripts/audit_camera_goal_transport.py outputs/goal-transport-NEW-ID
```

`--planner local`은 LLM 호출 없는 같은 로컬 제어 비교 조건이다. Ubuntu에서는 안내의
가상환경과 Python을 사용하되 이번 실제 모델 운반 결과는 Mac에서 검증한 것으로 구분한다.

## 남은 범위와 보관

고정 평지 장면의 작은 배치 비교다. 지형 통과, 다른 물체·조명·카메라, 실물 로봇,
자율 역할 선택, 통신 유무의 성능 효과는 검증하지 않았다. 추론 중 SIM이 멈추므로
실시간 추론 지연 중 하중 유지도 아직 검증하지 않았다. 긴 운반·정지 시의 미끄러짐과
실패 후 재파지는 후속 과제다. 물리 파지의 성공 여부를 LLM의 자신감으로 대체하지 않는다.

raw 전체는 이 작업 worktree의 `outputs/`에 로컬 보관한다. `results.json`에 정확한
경로·해시·코드 SHA·환경·시간·명령 수·모델 토큰을 기록했다. 공급자가 청구액을 주지 않아
달러 비용은 미상이다. 선택한 MP4/JPEG와 작은 회귀 fixture만 Git에 포함하며,
해시 목록을 raw 전체의 원격 백업이라고 부르지 않는다. Google Drive는 사용하지 않는다.
